### Strategy Rationale

The spurious files all come from one path: `promote_pending_candidates` loads at most the 5 most recent `action_records`
for a context fingerprint (`_fetch_recent_context_records`), and `_promote_failure_candidate` writes
`KB-failure-<fp8>.json` whenever the failure ladder is `repeated` or `proven-fail`. Stage 4 review rows share a
fingerprint derived from the flow's unique branch target, so two findings in one flow reach `repeated` within minutes
(for example, `KB-failure-9f57ffa8.json` cites two `ACT-FIND-*` refs with the same `I-1794464833-scrubcreds/...`
target).

The fix is to add a pure predicate, `is_single_flow_review_chatter(records)`, in `promotion_rules.py` (63 lines, budget
400), and to short-circuit `_promote_failure_candidate` with it. The predicate returns true only when the record list is
non-empty, every `record_id` starts with `ACT-REV-` or `ACT-FIND-`, and all records map to one flow key. The flow key is
the intent-id segment (`I-<digits>` plus slug) found in the target. When the target has no intent segment (legacy
targets such as PR number `85`), the whole stripped target is the key. Any non-review row, or two distinct flow keys,
returns false, so promotion stays byte-identical to today. An empty list also returns false, which keeps the existing
`unknown action` fallback.

`wisdom.py` (353 lines) must not grow. Two lines are added: the import, and the predicate folded into the existing
ladder-state guard condition, which stays within the 120-column limit. Two lines are removed by inlining the single-use
`source_ids` local into `ledger_refs`. Net delta is zero or negative.

Aggregation: overall `entropy_pred` is the sum of step entropies (`1.0 + 1.2 + 1.0 + 0.8 = 4.0`) and `cost_pred` is the
sum of step costs (`2.5 + 2.5 + 3.0 + 2.0 = 10.0`). `p_success_pred` is a qualitative bottleneck judgement: Step 2 (the
line-neutral wiring) and Step 4 (lint and full suite) each sit near 0.92, and the steps are correlated, so the overall
value is 0.88 rather than the product 0.72. Impact (70) is the intent-level value: it stops 3 to 21 spurious committed
files per multi-reviewer PR, removes add/add conflicts and restores signal to the failure KB. Overall EV:
`EV = 0.88 * 70.0 + 0.5 * 4.0 - 0.3 * 4.0 - 10.0 = 61.6 + 2.0 - 1.2 - 10.0 = 52.4`.

Strong assumptions:

- (a) Evidence is judged from the same 5 most recent records the payload already cites. A fingerprint whose older trials
  came from other flows, but whose last 5 are one flow's review rows, is suppressed. Review fingerprints embed the flow
  branch, so cross-flow sharing of a review fingerprint is in practice limited to legacy PR-number targets.
- (b) Existing KB-failure files are not pruned, per the intent.

   - otherwise return `len({_flow_key(r["target"]) for r in records}) == 1`.

   Use only subscript access, so both `sqlite3.Row` and `dict` work. Add a one-line docstring in the domain language
   ("Stage 4 review rows of one flow are not independent failure evidence").

   (it is expected to land at about 85).
