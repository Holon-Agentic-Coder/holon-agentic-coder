  then the `flow-<slug>` sibling the default-branch redirect would use (`flow_worktree_layout` with

  before the existing `--checkpoint` branch, so loading, runner/model resolution, worktree checks and later saves all
  follow the existing `--checkpoint` path; `--from-stage` still wins over the checkpoint's `current_stage`.
- `--from-stage` and `--checkpoint` help texts name the new behaviour.
- Checked: `test_cli.py`, `test_flow_target_worktree.py`, `test_flow_default_branch_worktree.py`: 380 passed.
