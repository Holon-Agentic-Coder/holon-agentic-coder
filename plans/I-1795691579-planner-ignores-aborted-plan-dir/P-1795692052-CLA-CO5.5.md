### Strategy Rationale

The bug is a one-function defect in `apps/sandbox-executor/src/sandbox_executor/entrypoint/execution_workspace.py` (154
lines, default budget 400, so there is plenty of headroom). Two designs were considered:

1. Pathspec exclusion (`:(exclude,glob)plans/I-*/**`) appended to `_ENGINE_OWNED_EXCLUDES`. Rejected: a pathspec exclude
   hides tracked edits under `plans/` too (violating acceptance criterion 2), changes the existing exclusions (criterion
   3), changes the resume check's `git diff --name-only` semantics in `partial_resume.py`, and changes the pinned git
   trace.
2. A second git probe (`ls-files --others`), as the previous attempt did. Rejected: it adds a git spawn and changes the
   pinned trace in `test_executor_characterisation.py`, which is exactly why the previous execution was refused.
3. Chosen: keep the one existing `git status --porcelain -- . <excludes>` call byte-for-byte, and drop only porcelain
   lines whose status code is `??` (untracked) and whose path starts with the engine-owned plan directory prefix
   `plans/I-`. Tracked modifications (` M`, `M `, `A `, `D `, `R `, ...) under `plans/` keep their non-`??` code and are
   still refused. No new git process, no change to the trace, no change to the existing exclusion tuple.

The new constant (`ENGINE_OWNED_PLAN_DIR_PREFIX = "plans/I-"`) sits directly below `ENGINE_OWNED_NOTES_GLOB` next to the
other engine-owned names. The resume check in `resolve_partial_head` keeps consuming `_ENGINE_OWNED_EXCLUDES` unchanged;
it compares committed trees (`git diff --name-only base tip`), where untracked files never appear, so the plan-dir
exclusion has no bearing on it and the acceptance criterion "existing exclusions unchanged" takes precedence.

Aggregation: overall `p_success` is the product-ish bottleneck of Step 1 and Step 2 (`0.95 * 0.96 * 0.98 ≈ 0.90`),
entropy is the sum of step entropies (`1.5 + 1.5 + 1.0 = 4.0`), cost is the sum (`2.0 + 2.5 + 1.5 = 6.0`), impact is the
intent-level value of unblocking retries (60), learning value is small (3).
`EV = 0.90 * 60.0 + 0.5 * 3.0 - 0.3 * 4.0 - 6.0 = 54.0 + 1.5 - 1.2 - 6.0 = 48.3`.
