## Plan Description & Strategy

Implement a fast, read-only git-history measurement script `scripts/measure_deleted_why_comments.py` that scans
first-parent commits on `main` (or a caller-specified `--ref`), identifies merged self-doc slice commits, inspects each
slice's unified diff across code files, extracts removed comment lines carrying reason indicators that lack an added
`# why:` counterpart in the same hunk or file, and reports every unmatched removed reason with `(file, line, text)` in
human-readable text or JSON format. Pair it with comprehensive hermetic tests in
`apps/sandbox-executor/tests/test_measure_deleted_why_comments.py`, smoke-test it against the live `main` history to
validate real-world precision and speed, and finish with foreground execution of targeted pytest, full
`uv run task test`, and `uv run task lint`.

3. Define module-level constants for `REASON_INDICATORS` (`because`, `so that`, `otherwise`, `must`, `avoid`, `never`,

5. Implement `extract_hash_comment(line: str) -> str | None` using a quote-aware character scan (tracking single/double

6. Implement `is_why_comment(comment: str) -> bool` checking whether the stripped comment body starts with `why:`
   (case-insensitive), and `has_reason_indicator(comment: str) -> bool` checking `REASON_INDICATOR_PATTERN` against the
   stripped comment body.
7. Implement `find_unmatched_reasons_in_diff(diff_text: str) -> list[UnmatchedReason]` to parse unified diff output per
   file and per hunk (`@@ -old_start(,old_count)? +new_start(,new_count)? @@`):
   - Track exact 1-based `old_line` numbers for removed lines (`-`, excluding `--- `) and context lines (` `).
   - For each code file hunk, collect removed comments with reason indicators and count added `# why:` comments in that
     hunk.
   - If a hunk has at least one added `# why:` comment, treat that hunk's removed reason comments as matched; otherwise
     carry them to file-level matching against any remaining added `# why:` comments from other hunks in the same file
     (1-to-1 consumption so extra unmatched reasons are still reported).
   - Return every remaining unmatched reason as `UnmatchedReason(file_path, line, text)` in deterministic file and line
     order.
8. Implement `list_merged_self_doc_slices(repo_root: Path, ref: str = "main") -> list[SelfDocSlice]` using a single
   `git log <ref> --first-parent --format=%H%x1f%s%x1f%b%x1e` call (no environment overlay; inherits default process
   environment). Match commits whose `* intent: created <intent_id>` line contains `self-doc` (case-insensitive),
   or—when no intent creation line exists—whose subject contains `self-doc` (case-insensitive). Extract PR number
   `(#NNN)` from the subject when present.
9. Implement `scan_slice_diff(repo_root: Path, slice_info: SelfDocSlice) -> SliceReport` using
   `git -c core.quotePath=false show --format= --patch -U3 --no-color --no-ext-diff <sha>` and passing the decoded diff
   text to `find_unmatched_reasons_in_diff`.
10. Implement `scan_self_doc_history(repo_root: Path, ref: str = "main") -> list[SliceReport]` and CLI
    `main(argv: list[str] | None = None) -> int` supporting `--repo`, `--ref` (default `"main"`), and `--format`
    (`"text"` | `"json"`, default `"text"`). In text mode, print each merged self-doc slice header and every unmatched
    reason as `  <file>:<line>: <text>` plus a summary footer; in JSON mode, emit structured JSON with `ref`,
    `slices_scanned`, `unmatched_count`, and per-slice `unmatched` lists (`file`, `line`, `text`).
