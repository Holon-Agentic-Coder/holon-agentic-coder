## Plan Description & Strategy

Today the check behaves like this (`scripts/check_self_explaining.py`):

- `changed_files_to_check` returns `None` when `merge_base(root)` (in `scripts/self_explaining_diff.py`) finds nothing.
- `main` then prints `NO_MERGE_BASE_NOTICE` and returns 0, so the change is never checked.
- When there are violations, it prints them followed by one total line.

The plan has three parts:

1. **Obtain a merge base or fail (`self_explaining_diff.py`).** `merge_base(root)` first tries
   `git merge-base HEAD origin/main`. If that finds nothing and an `origin` remote exists, it deepens the history:
   - fetch `+refs/heads/main:refs/remotes/origin/main` from origin;
   - if the repository is shallow, run `git fetch --unshallow origin` with the same refspec;
   - try `git merge-base` again.

   It returns `None` only when every attempt fails.

2. **Fail closed and report counts (`check_self_explaining.py`).**
   - Remove the skip notice and its exit-0 path.
   - When no merge base is found, write an error naming `origin/main` to stderr and exit non-zero.
   - Group violations by file. After the existing violation lines, print one count line per file and then the total.
   - On success, keep the "passed (N changed file(s))" line.
   - `--staged` keeps comparing the index with HEAD and never looks up a merge base.

3. **Tests.**
   - Replace `test_missing_merge_base_skips_with_notice` with failure tests: no remote, and a remote with unrelated
     history.
   - Add a test with a local bare remote and a depth-1 single-branch `file://` clone, proving the lookup deepens the
     clone and the check passes.
   - Add tests for the per-file and total counts, and for `--staged` passing without a merge base.

Then run the affected tests, then lint, then the full suite once. Each run happens in the foreground.

### Implementation Details (No code blocks, only logic/steps)

1. Add module constants to `scripts/self_explaining_diff.py`:
   - `TARGET_REF = "origin/main"`;
   - `MAIN_FETCH_REFSPEC = "+refs/heads/main:refs/remotes/origin/main"`;
   - `FETCH_TIMEOUT_SECONDS` (for example 300).
2. Rename the current lookup to `existing_merge_base(root)`. It keeps the body:
   `run_git(root, "merge-base", "HEAD", TARGET_REF)`, returning the stripped sha or `None`.
3. Add `has_origin_remote(root)`. It is true when `git remote get-url origin` exits 0. This keeps a repository with no
   remote from attempting any fetch.
4. Add `is_shallow_repository(root)`. It is true when `git rev-parse --is-shallow-repository` prints `true`.
5. Add `fetch_from_origin(root, *args)`, which:
   - runs `git fetch --quiet origin <args...>` through `subprocess.run`;
   - uses `capture_output`, `text=True` and `check=False`;
   - sets `timeout=FETCH_TIMEOUT_SECONDS` and an environment that copies `os.environ` with `GIT_TERMINAL_PROMPT=0`;
   - returns true on exit code 0 and false on `OSError`, `subprocess.TimeoutExpired` or a non-zero exit.

   Add a single `# why:` comment on the environment setting, for example
   `# why: a credential prompt would hang CI and the containers`. That is the only comment allowed.

6. Add `deepen_towards_origin_main(root)`, which:
   - calls `fetch_from_origin(root, MAIN_FETCH_REFSPEC)`;
   - then, if `is_shallow_repository(root)`, calls `fetch_from_origin(root, "--unshallow", MAIN_FETCH_REFSPEC)`.

   Each call's failure is tolerated, because the final merge-base retry decides the outcome.

7. Make the new `merge_base(root)`:
   - return `existing_merge_base(root)` when it is found;
   - otherwise return `None` when there is no origin remote;
   - otherwise call `deepen_towards_origin_main(root)` and return `existing_merge_base(root)`.

   Keep each function at C901 complexity of 3 or less.

8. Add `import os`. Add no docstrings and no other comments. Keep the module below 400 lines (expected about 170).

### Strategy Rationale

The intent is precise, small and high-value: a gate that passes blind measures nothing. So it is accepted as is, with no
reframing or decomposition. The design keeps the fast path unchanged: a checkout that already has a merge base never
fetches. CI uses `fetch-depth: 0`, so it pays nothing. Network access happens only when the merge base is missing, and
it is bounded by a timeout and `GIT_TERMINAL_PROMPT=0`. The merge-base logic stays in `self_explaining_diff.py` (the
module that owns git diff data), and the reporting stays in `check_self_explaining.py`. Each module grows by fewer than
60 lines.

How the overall metrics were derived:

- **p_success:** bounded by the bottleneck chain. Steps 1 and 3 are 0.88 and 0.85, and their risks are correlated: both
  depend on the shallow-clone semantics, so if Step 1's sequence works, Step 3's fixture almost certainly does. Lint and
  suite noise reduce it further, giving a qualitative 0.82 rather than the raw product of about 0.59.
- **entropy:** the sum of the steps, `1.5 + 1.0 + 1.2 + 0.3 = 4.0`.
- **impact:** 70, below the sum of the steps (90), because the steps overlap in delivering one gate behaviour.
- **cost:** the sum, `2.5 + 1.5 + 2.5 + 2.0 = 8.5`.
- **learning value:** 3.0, near the maximum of the steps.
- **EV:** `EV = 0.82 * 70.0 + 0.5 * 3.0 - 0.3 * 4.0 - 8.5 = 57.40 + 1.50 - 1.20 - 8.5 = 49.20`.

The strong assumption is that the executor, review-loop and conflict-resolver workspaces that run `uv run task lint`
already have an `origin/main` ref with shared history. This planner workspace does. Where one does not, lint will now
fail, which is the intended fail-closed outcome. It may surface as a one-off lint failure that needs a fetch, not a code
change.
