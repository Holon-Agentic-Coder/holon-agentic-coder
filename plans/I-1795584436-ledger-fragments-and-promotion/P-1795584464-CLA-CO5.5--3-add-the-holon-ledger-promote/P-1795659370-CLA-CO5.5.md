### Intent & Git Integration

- **Step Intent:** Provide a pure promotion planner and a lock-guarded, additions-only apply that moves pending fragment
  rows into the canonical ledgers and then deletes the promoted fragments.
- **Git branch:** the execution branch of this plan (no separate branch)
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Confirm that `git diff 3c30608e HEAD -- apps/sandbox-executor/src/sandbox_executor/ledger/` is empty on the execution
   branch. If the parent changed the ledger package, re-derive from the current code instead of porting.
2. Write `ledger/promote_threshold.py`: `PROMOTE_EVERY_ENV = "HOLON_LEDGER_PROMOTE_EVERY"`,
   `DEFAULT_PROMOTE_EVERY = 10`, `promote_every_from_env` (unset or empty gives the default; a stripped positive integer
   is accepted; anything else raises `ValueError` with the variable name), `canonical_ledger_paths` (the three canonical
   files from `fragments.LEDGER_NAMES`), and `pending_root_intents` (distinct `<root>` stems that have at least one
   fragment, as a union across the three `pending/<stem>/` directories, excluding `fragments.UNSCOPED_ROOT`).
3. Write `ledger/promote.py` with frozen dataclasses `FragmentSnapshot` (path, bytes), `LedgerPromotion` (ledger name,
   lines to append, snapshots to delete, held paths), `PromotionPlan` and `PromotionResult` (promoted row counts per
   ledger, repo-relative `deleted` and `held` lists, threshold met, root count), plus `PromotionRaceError`.
4. `plan_ledger` (pure): parse canonical rows with `merged.parse_jsonl_rows`, seed a seen set with
   `merged.row_identity`, then walk the fragments from `fragments.iter_fragment_files`. A fragment that is not UTF-8, or
   has a non-blank line that is not a JSON object, is held. Otherwise each new-identity line is collected **verbatim**
   (original text, not re-serialised). Collected lines are ordered by
   `(order.parse_created_at instant, discovery index)`, with untimed rows last.
5. `plan_promotion`: count roots with `pending_root_intents`. Below `every` and without `force`, return a plan with no
   work; otherwise build a `LedgerPromotion` for each ledger.
6. `apply_promotion`: for each ledger, re-read every snapshot and raise `PromotionRaceError` before writing anything for
   that ledger if any bytes changed. Under `LedgerLock` with `assert_ledger_prefix`, write a separating newline when the
   canonical file is non-empty and does not end in one, then append the lines. Only after the append, delete the
   promoted fragments and remove empty `pending/<stem>/` and `pending/` directories.
7. `promote(repo_root, *, every=None, force=False)`: resolve `every` (explicit value, else the environment), plan,
   apply, and return a `PromotionResult`. It runs no git commands.
8. Export `promote`, `plan_promotion`, `apply_promotion`, `PromotionResult` and `PromotionRaceError` from
   `ledger/__init__.py`.
9. Follow the ledger package convention enforced by `test_ledger_self_doc.py`: no docstrings and no non-pragma comments
   (`PromotionRaceError` has a `pass` body). Full type annotations on every public signature. Each module stays at 200
   lines or fewer, and each function within the ruff limits.
