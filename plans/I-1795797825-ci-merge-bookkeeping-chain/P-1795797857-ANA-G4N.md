## Plan Description & Strategy

When a Stage 4->5 push sequence stacks bookkeeping commits before and/or after a clean two-parent `sync: merge target`
commit and GitHub Actions concurrency cancels the intermediate bookkeeping or merge runs, the current gates fail to skip
in three places: `ci_bookkeeping_gate.py` stops when `find_real_success` hits a cancelled run or when `diff_rule` from
an older real success spans a `GATE_SKIPPED` merge commit, and `ci_merge_push_gate.py` declines any head commit that
does not directly have two parents.

The strategy extends the three gate modules cleanly along their existing boundaries:

1. Extend `scripts/ci_bookkeeping_chain.py` with opt-in cancelled-run traversal (`allow_cancelled=True`, recording
   `crossed_cancelled` on `ChainResult`) and bounded single-parent commit-chain verification helpers
   (`find_merge_ancestor` and `verify_single_parent_chain`).
2. Wire those helpers into `scripts/ci_merge_push_gate.py` (staying under 350 lines) and
   `scripts/ci_bookkeeping_gate.py` so `synchronize` pushes whose head is a bookkeeping chain stacked on a clean
   two-parent base-branch merge evaluate the full chain from the last real green PR head through the merge to
   `head_sha`, while never skipping `hygiene`.
3. Add comprehensive hermetic tests in `apps/sandbox-executor/tests/` covering cancelled merge+bookkeeping chains,
   combined single-push merge+bookkeeping, mixed non-bookkeeping changes before or after the merge, and hygiene
   enforcement.
4. Validate with targeted `uv run pytest`, full `uv run task test`, and `uv run task check`.
