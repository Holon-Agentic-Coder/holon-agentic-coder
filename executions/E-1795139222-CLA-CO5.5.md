### Step 3: Accept partial work forked from an earlier ledger-only plan tip and merge the current plan tip (done)

- New `entrypoint/partial_resume.py`: `plan_lineage_refusal(repo, plan_tip, head, intent_tip)` accepts a head that
  descends from the plan tip, or whose fork point lies on `rev-list --first-parent <plan_tip> ^<intent_tip>` and after
  which the plan branch changed only `holon-knowledge/ledger/*.jsonl`; without a resolvable intent tip that sub-check is
  skipped with a stderr note. Refusals keep the prefix `not a descendant of the plan tip`, so the existing executor test
  of a plan revision still matches. `intent_branch_tip` resolves `<intent>/_` from the plan prefix.
- `resolve_partial_head` uses the rule instead of the strict ancestor check and returns a typed `ResumeStart`.
- `executor._resume_start` creates the execution branch at the chosen start and, through `_merge_plan_tip`, merges the
  current plan tip (`merge --no-edit`; ledger-only conflicts go through `_reconcile_conflicted_merge` with the plan side
  as prefix). On any other conflict or failure the merge is aborted, the branch is re-created at the plan tip and the
  reason is printed. `plan_tip` stays the empty-diff and attribution base.

### Step 4: Resume from the execution branch tip (done)

- `partial_resume.resume_from_branch_tip` keeps the recorded head when the tip equals it or adds only engine-owned
  files (the failure commit), returns the tip when it strictly descends from the head and passes the lineage rule
  (reason `resumed from the branch tip <tip12>, <n> commit(s) after the recorded partial head <head12>`), and otherwise
  keeps the head with the reason (`the branch tip <tip12> does not descend from the recorded partial head <head12>;
  resuming from the recorded head`), which the executor prints to stderr, redacted. The continuation note names the
  actual start commit.
