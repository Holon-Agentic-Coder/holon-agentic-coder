## Step 1: Add calibration_outcome.py with flow-order and superseded-conflict rules, used by calibration_ev.py

### Intent & Git Integration

- **Step Intent:** Make the latest summary row in flow order the final outcome, and stop counting a resolved
  `sync_conflict` as a failure in the observed EV.
- **Git branch:** the execution branch for this plan (no separate branch)
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Create `apps/sandbox-executor/src/sandbox_executor/calibration_outcome.py` with a module docstring that describes the
   ordering rule.
2. Move `is_converged_record` and `_record_exit_code` (made public as `record_exit_code`) into it. Re-export
   `is_converged_record` from `calibration_ev.py` so that `calibration.py` and the existing tests still import it.
3. Add `SYNC_CONFLICT_STATUS = "sync_conflict"` as a literal. Do not import it from the flow package or an entrypoint.
4. Add `_created_at_instant`. It strips the value, rewrites a trailing `Z` to `+00:00`, parses with
   `datetime.fromisoformat`, treats naive values as UTC, and returns an aware `datetime.min` for missing or unparseable
   values.
5. Add `summary_row_order_key`, which returns `(instant, revision)`. The revision defaults to 1 when it is missing or
   not an integer. Add `latest_summary_row`, which takes the last element of a stable sort and returns None for an empty
   input.
6. Add `has_unresolved_failure(ordered_records)`. It returns True if the last row is a `sync_conflict`. Otherwise it
   returns True if any row is failed (status `failed` or a non-zero exit code), except a `sync_conflict` row that a
   later converged, zero-exit row supersedes.
7. In `evaluate_dual_ev_outcomes`, replace the local `sort_key` with `summary_row_order_key`, and replace the
   `has_failure` expression with `has_unresolved_failure(sorted_records)`.
8. Keep `calibration_ev.py` under 200 lines, and keep every function within the ruff C901 and PLR limits.
