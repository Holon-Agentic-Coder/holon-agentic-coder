### Strategy Rationale

The intent is accepted as is. It targets fundamental architectural decoupling: eliminating container entrypoint
dependencies on the host orchestration flow engine (`flow.pipeline`, `flow.stages`, or `cli`), encapsulating checkpoint
persistence and schema migration behind a clean `CheckpointStore` protocol port, splitting the monolithic `ledger.py`
(1035 lines) into a focused `ledger/` package (`rows`, `lock`, `query`, `reconcile`), and reducing cyclomatic complexity
across stage-conflict and question-validation routines without inline `# noqa` suppressions.

A major constraint is the frozen module budget policy in `holon-config/hygiene/module_budgets.json`:

- `flow/checkpoint.py` is frozen at 228 lines. Introducing the `CheckpointStore` protocol and its `FileCheckpointStore`
  adapter directly in `flow/checkpoint.py` would breach this limit. Therefore, the protocol and file adapter are placed
  in a new focused module `flow/checkpoint_store.py` (subject to the default 200-line budget), while
  `flow/checkpoint.py` delegates to it, keeping `flow/checkpoint.py` comfortably under 228 lines.
- `flow/ledger_reconcile.py` is frozen at 224 lines. Moving pure ledger reconciliation logic into `ledger/reconcile.py`
  allows `flow/ledger_reconcile.py` to become a thin backward-compatible adapter delegating to
  `sandbox_executor.ledger.reconcile`, easily remaining well within its 224-line budget.
- Container entrypoints (`entrypoint/execution_workspace.py`, `entrypoint/executor.py`, `entrypoint/planner.py`,
  `entrypoint/intent_creator.py`, `entrypoint/review_loop.py`) currently import `sandbox_executor.flow` for utilities
  (`check_and_resolve_stage_conflicts`, `reconcile_ledger_file`, `failed_partial_head`, `validate_intent_questions`).
  Importing `sandbox_executor.flow` at runtime imports `flow/__init__.py`, which pulls in host-only modules
  `flow.pipeline` and `flow.stages`. By moving `failed_partial_head` out of `flow/stages/execute.py` into a focused
  module `flow/partial_head.py`, and redirecting entrypoint imports directly to focused domain modules
  (`ledger.reconcile`, `flow.stage_conflicts`, `flow.intent_questions`, `flow.partial_head`, `flow.review.*`),
  entrypoints are completely decoupled from host orchestration. A hermetic AST import test enforces this boundary.
