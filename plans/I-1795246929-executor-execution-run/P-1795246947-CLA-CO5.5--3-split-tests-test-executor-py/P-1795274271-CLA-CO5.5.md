## Plan Description & Strategy

`apps/sandbox-executor/tests/test_executor.py` is 4,234 lines. It holds four `unittest.TestCase` classes (`TestExecutor`
with about 70 tests, `TestExecutorPrePushSync`, `TestExecutorIncrementalNotes` and `TestExecutorPartialWorkSalvage`),
about 25 parametrized module-level tests for decomposition and sub-intent parsing, two autouse fixtures
(`_agent_turns_use_run_cmd` and `_workspace_is_mounted`), and about 15 shared helpers. Three other test modules import
its internals:

- `test_executor_plan_decision.py:10` imports `_cuts_branch`, `_run_executor_main` and `_validate_stub`.
- `test_executor_error_context.py:5-12` imports the module object, the `_workspace_is_mounted` autouse fixture,
  `TestExecutorIncrementalNotes.run_executor` / `write_notes` and `VALID_NOTES`.
- `test_ledger_append_only.py:499` lazily imports `_cuts_branch`, `_turn_via_run_cmd` and `_validate_stub`.

The strategy is a pure relocation:

1. Record the collected test IDs before the move.
2. Create `tests/executor_fixtures.py`, which holds no tests, as the single home for the autouse fixtures, the shared
   helpers and the shared harness methods.
3. Move each test, byte-for-byte, into a flat `tests/test_executor_<module>.py` file named after the executor package
   module it exercises.
4. Repoint the three importers to `tests.executor_fixtures`.
5. Delete `tests/test_executor.py`.
6. Prove that nothing was lost or duplicated by diffing the normalised IDs and the whole-suite collected count.

Three design choices keep the proof trivial and the risk low:

- **Class names are preserved.** A test moved out of `TestExecutor` stays in a class named `TestExecutor` in its new
  module. pytest allows the same class name in different modules, so each node ID changes only in its file path. The
  `Class::method[param]` suffix stays identical, and the diff can strip only the file prefix.
- **No `TestCase` subclass and no `test_*` function in `executor_fixtures.py`.** pytest collects every
  `unittest.TestCase` subclass it finds in a test module's namespace, whatever its name. Importing a `TestCase` into a
  second module would collect its tests twice. So shared harness methods (`run_executor`, `write_notes`, `summary`,
  `_run_main_with_agent_diff`, `_run_over_budget_main`, `_agent_capture_side_effect`, `_create_bare_remote_with_plan`,
  `_clone_workspace`) move into plain mixin classes that do not subclass `TestCase`. A mixin is created only when a
  helper is used by more than one new module. Otherwise the helper stays on its class.
- **The modules stay flat in `tests/`.** `test_no_placeholder_sub_intent_text_in_source` finds `src/` through
  `dirname(dirname(__file__))`, so it must stay one level under the app root. That rules out a `tests/executor/`
  subpackage.

The target modules are below. File names avoid the existing `test_executor_package.py`, `test_executor_test_run.py`,
`test_executor_characterisation.py`, `test_executor_empty_diff.py`, `test_executor_plan_decision.py` and
`test_executor_error_context.py`. The executor confirms each test's owning module with

- `tests/test_executor_commands.py`: `redact_args`/`redact_text`, the witness patterns, diagnostic retention, delimiter
