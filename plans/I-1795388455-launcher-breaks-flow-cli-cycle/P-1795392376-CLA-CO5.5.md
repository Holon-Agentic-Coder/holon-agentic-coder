### Strategy Rationale

The cycle exists because container plumbing (env files, mounts, proxy sidecar, role dispatch) lives in the presentation
package. The plan extracts that plumbing into a new `sandbox_executor.launcher` package that imports neither `cli` nor
`flow`. `cli/__init__.py` then re-exports the names and the four flow call sites import from `launcher`. The dependency
direction becomes `cli -> flow -> launcher` and `cli -> launcher`, with no back edges.

Key facts found while planning (all verified in the tree at `3a8f042c`):

- `tests/test_complexity_gate.py` keys its frozen `BASELINE_SNAPSHOT` of complexity `noqa` annotations by **file path**.
  Any `noqa` carried into `launcher/*.py` would fail the ratchet, whatever the intent says. The moved functions
  (`run_docker_container` with C901/PLR0911/PLR0912/PLR0913/PLR0915, `setup_token_reduction_proxy` with
  C901/PLR0912/PLR0915, `detect_holon_coherence` with C901/PLR0911/PLR0912, `dispatch_role_agent` with PLR0913)
  therefore **must** be decomposed. Dropping snapshot entries for `cli/__init__.py` is allowed (the ratchet only goes
  down), so `test_complexity_gate.py` does not need editing.
- PLR0913 counts named parameters, keyword-only ones included. To keep every call site byte-identical (cli commands,
  `flow/dispatch.py`, injected test dispatchers), `dispatch_role_agent` and `run_docker_container` keep their leading
  positional parameters (4 or fewer). The optional keywords move into `**options: Unpack[<TypedDict>]`, which ruff does
  not count and type checkers still verify.
- `holon-config/hygiene/module_budgets.json` only budgets `sandbox_executor/flow`. The new launcher modules are not
  line-checked by `check_module_budgets.py`. The plan still keeps each launcher module at or below about 250 lines, by
  splitting, to follow the placement rule. The touched flow modules (`context.py` 280/280, `pipeline.py` 426/431,
  `review/loop.py` 936/952, `dispatch.py` 81/200) only swap one import line each, so their line counts stay level or
  fall.
- `tests/conftest.py` monkeypatches `cli.find_github_token` and `cli.env_file_dir` for hermeticity. After the move these
  must target the launcher modules, or the suite would write env files under the real `~/.holon/tmp`.

## Step 1: Freeze a golden characterisation of the container launch and sidecar output

- **Sub‑intent recommendation:** NO
- **Reasoning:** A small, test-only step that makes "byte-for-byte identical" measurable. It is cheap, low-risk and must
  land on the same branch as the refactor it guards.
- **Step Type:** TEST
- **Exploration level:** BALANCED

- **Hypothesis being tested:** Running `run_docker_container` against a recording fake `subprocess.run`, a fixed
  environment and a temporary env-file directory gives deterministic output. That output is the argv, the redacted
  `Executing:` stdout line, the env-file contents, error messages and exit codes. It can be pinned as inline literals
  and replayed unchanged after the move.
- **Learning target:** Which parts of the launch are non-deterministic (pid/uuid suffixes in sidecar names, temporary
  paths, the `HOLON_STAGE_BUDGET_SECONDS` clock) and need normalising in the snapshot.
- **Maximum acceptable cost for this learning:** about 3 cost units. If more than three sources of nondeterminism need
  bespoke patching, fall back to asserting on structural invariants (token positions, `--env-file` placement, absence of
  secret values from argv) rather than full literals.

### Intent & Git Integration

- **Step Intent:** Add `tests/test_container_launch_characterisation.py`, which pins today's launch behaviour before any
  code moves.
- **Git branch:** `I-1795388455-launcher-breaks-flow-cli-cycle/P-1795392376-CLA-CO5.5/_` (plan execution branch; commit
  per step)
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Write the test against the **public** entry points only (`sandbox_executor.cli.run_docker_container`,
   `cli.dispatch_role_agent`, `cli.get_host_proxy_envs`, `cli.detect_holon_coherence`, `cli.redact_cli_error`). The same
   test then runs unchanged after the move, because the names stay re-exported.
2. Patch only stdlib module attributes (`subprocess.run`, `shutil.which`, `socket.create_connection`, `os.environ` via
   `monkeypatch.setenv`/`delenv`). Never patch `cli.<function>` names here, so the test survives the relocation without
   edits. Use the existing hermetic fixtures (`tmp_path` env-file dir via the conftest fixture, `credential_env.py`
   helpers).
3. Cover at least these scenarios, each asserting the full recorded docker argv, the stdout `Executing:` line, the
   env-file key=value lines (sorted), and the return code:
   - planner role, `claude-agent`, a host worktree, `GITHUB_TOKEN` plus a `HOLON_*` var holding a URL with a password;
   - executor role with `result_file`;
   - intent-creator with `intent_file` present, and with it missing (exit 1 and the exact error text);
   - `docker` missing from PATH (exit 1 and the exact message);
   - `pi` runner with a local-LLM provider set (generated agent dir mount);
   - an env-file write failure (`OSError`), giving the exact "could not write the credential env-file" message and no
     secret on argv;
   - `token_reduce=True` with an external `HOLON_PROXY_URL` (attach path, so no sidecar is spawned) and the resulting
     proxy env names.
4. Normalise only the run-specific values (tmp paths, pid/uuid suffixes, stage-budget seconds) through one helper that
   swaps them for stable placeholders before comparison.
5. Run
   `uv run pytest apps/sandbox-executor/tests/test_container_launch_characterisation.py apps/sandbox-executor/tests/test_url_message_fuzz.py apps/sandbox-executor/tests/test_redaction.py`
