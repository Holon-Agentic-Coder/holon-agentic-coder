### Step 2: Flow repositories from layered read-only templates and a fast history builder

- New `apps/sandbox-executor/tests/flow_repo_templates.py` (about 170 lines):
  - `build_flow_history(root, base_files, commits)` gives the state of `build_flow_repos` followed by one `commit_on`
    per `FlowCommit`, using five git processes (`init`, `clone`, one `fast-import` for every commit, `push --all`,
    `checkout`). The loop it replaces costs about 8 plus 7 per commit.
  - `flow_history_copy` serves that history, plus an optional git command such as a stopping merge, from a
    `shared_template` named by a hash of its content, and copies it with `copy_template`.
  - `derived_template` and `replace_with_copy` layer a fixture's fixed state over another template, here the flow
    conftest's `flow-template`.
- Deviation from the plan: it planned an explicit hermetic environment on every template git call. Every template here
  is instead requested from a function-scoped fixture or test body, so it is built under the session-autouse
  `hermetic_git_config` (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`) and the autouse guards. That keeps the rule four
  of `repo_templates.py` without a second environment recipe. No template build runs production code.
- New `apps/sandbox-executor/tests/test_flow_repo_templates.py` (6 cases) proves the following:
  - The fast history equals `build_flow_repos` plus `commit_on` in refs, trees, upstreams, local config, `HEAD`,
    status and commit graph.
  - Bytes content round-trips, and a branch that origin lacks is refused.
  - A copy's origin names the copy, a push from the copy leaves another copy untouched, and the template is
    read-only.
  - A merge stopped in the template is copied with `MERGE_HEAD` and the conflicted index.
  - A derived template replaces an earlier copy.
- Converted:
  - `flow/test_conflict_resolver_attempt.py`: the `merging` factory fixture serves the whole conflicting
    `--no-commit` merge state from a template, one per distinct `ours`/`theirs` pair.
  - `flow/test_target_sync.py`: the `repos_with(*commits)` factory, used for the target move, code conflict,
    ledger-only conflict, marker file and sync-conflict row scenarios.
  - `flow/test_conflict_classes.py`: `_conflicted` and the non-UTF-8 case use `build_flow_history`. Each case is a
    distinct one-off repository, so a template would only add a repack.
  - `flow/test_conflict_resolver_role.py`: the `work_with(*commits)` factory, and `build_flow_history` for the one
    case with its own base.
  - `flow/test_target_sync_resume.py`: the `repos_with(*commits)` factory. The merge stays in each body, because the
    test interrupts it there.
  - `flow/test_admission.py`: the `own_plan_with(touch_set, before, after)` factory derives one template per plan
    shape from `flow-template`. The local flow's linked worktree stays per test.
  - `flow/test_ledger_worktree_cleanup.py`: the execution branch with its ledger row is a derived template.
  - `test_pre_push_sync_conflict.py` and `test_partial_salvage.py`: the fixture bodies became `shared_template`
