### Strategy Rationale

The intent has three parts and three acceptance tests. Each part maps to one module-level change.

1. **Supervisor guard (goal 2).** `run_turn` already samples the runner's descendants for tool CPU through
   `descendant_cpu_seconds`. A quiet foreground test (blocked on I/O, sleeping between retries, or waiting on an xdist
   worker) burns under `TOOL_CPU_PROGRESS_SECONDS`, so the 90 s stall window fires. The guard asks a second, simpler
   question: does the runner have any live non-agent descendant? While it does, the stall check uses
   `silence_window(budgets, streaming=False)`. That function already exists and returns
   `max(stall_seconds, turn_seconds)`, or `max(stall_seconds, DEFAULT_TURN_SECONDS)` when the turn is `unlimited`. So
   the turn timeout bounds the guarded turn even when no artefact is watched, which is the resolver's case: it calls
   `run_turn(cmd, cwd=repo_dir, turn_budgets=...)` with no `watch_path`. The `turn` breach and the stage ceiling are not
   changed.
2. **Background warning (goal 3).** After the runner exits with no breach, the same lister is called once more. Any
   process still in the runner's process group (a `cmd &` keeps the group, and the runner was started with
   `start_new_session=True`) is logged as a warning that names its command line, and is recorded on the `TurnResult`.
   When a breach does fire, the warning lists any live descendant commands, so the operator no longer sees only a bare
   `stall`.
3. **Prompt rule (goal 1).** Each of the three shipped templates gets one short rule: run tests and lint in the
   foreground, wait for the result in the same turn, and never background a command and end the turn. A parametrised
   test asserts the rule.

**Known gap, not fixed here (follow-up intent recommended).** The Stage 4 resolver turn prompt is a hard-coded string in
`entrypoint/review_loop.py::_build_resolver_prompt`, not `review_loop.template.md`. The template governs reviewers and
documents resolver discipline (Invariant 11), but the text the resolver agent actually reads changes only if
`_build_resolver_prompt` changes. That file is outside the intent scope ("Keep the change minimal and within the listed
files"). Touch-set admission would refuse it, and adding it would breach the user's explicit constraint. The supervisor
guard still protects a resolver foreground test. A resolver that backgrounds a test is still stopped once the test
finishes and the runner sits idle, but the warning now names the command. The plan records a recommended follow-up
intent: "Add the foreground test and lint rule to the resolver turn prompt in `_build_resolver_prompt`". The scaffold
twins in `sandbox_executor/scaffold.py` (`PLANNER_TEMPLATE`, `EXECUTOR_TEMPLATE`, `REVIEW_LOOP_TEMPLATE`) are also out
of scope and get the same follow-up note. Only the posted-shape block is parity-tested, so they may diverge without

## Step 1: Confirm how a backgrounded command appears after the runner exits

- **Sub‑intent recommendation:** NO
- **Reasoning:** A read-only check of a few minutes. It decides whether the post-exit lister can rely on process-group
  membership alone.
- **Step Type:** EXPLORATION
- **Exploration level:** BALANCED

- **Hypothesis being tested:** A command started with `&` by a runner launched with `start_new_session=True` stays in
  the runner's process group after the runner is reaped. The existing walk in `descendant_cpu_seconds` (`pgid == root`
  membership plus a parent walk) therefore still finds it, and `/proc/<pid>/cmdline` (or `ps -o args=` on macOS) gives
  its command line.
- **Learning target:** Whether `pgid` membership is enough, or whether a backgrounded `setsid`/`nohup` command escapes
  the group. If it escapes, the plan documents the limit and does not chase it.
- **Maximum acceptable cost for this learning:** 1.0 cost unit (about 10 minutes). Stop as soon as the answer is clear.

- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. In a scratch shell (no repository change), start `python -c` with `subprocess.Popen(..., start_new_session=True)`
   running `sh -c "sleep 20 >/dev/null 2>&1 & exit 0"`, wait for it, then read `/proc/*/stat` for processes whose pgid

3. Record the result in the execution notes. If the host has no `/proc`, confirm that `ps -A -o pid=,ppid=,pgid=,args=`

## Step 2: Add a descendant command lister to turns.py

- **Sub‑intent recommendation:** NO
- **Reasoning:** A small, additive helper next to the existing process sampler, with low risk. It reuses the descendant
  walk by extracting it, without changing behaviour.
- **Step Type:** IMPLEMENTATION
- **Exploration level:** EXPLOIT

### Intent & Git Integration

- **Step Intent:** Give supervision a way to ask "which non-agent descendants of the runner are alive, and what are
  their commands?"
- **Git branch:** same execution branch as Step 1
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Extract the member walk from `descendant_cpu_seconds` into a private helper `_descendant_members(table, root_pid)`.
   It returns the set of pids descended from `root_pid` or in its process group. Make `descendant_cpu_seconds` call it.
   Its behaviour is unchanged, and the existing `TestProcessSampler` tests must pass untouched.
2. Add `process_command(pid, proc_root="/proc") -> str | None`. It reads `/proc/<pid>/cmdline`, splits on NUL, joins
   with single spaces and strips. When `/proc` is absent it falls back to `ps -o args= -p <pid>` with
   `PS_TIMEOUT_SECONDS`, mirroring `process_name`. It returns None if the process is gone. It truncates to a bounded
   length (a new constant, for example `COMMAND_DISPLAY_CHARS = 200`) so a huge argv cannot flood the log.
3. Add a type alias `ChildLister = Callable[[int], dict[int, str] | None]` and a public function
   `descendant_commands(root_pid, table_source=process_table, name_of=process_name, command_of=process_command, agent_names=WRAPPED_AGENT_PROCESS_NAMES)`.
   That is five parameters, within `PLR0913`. It returns `{pid: command}` for members minus the agent's own pids (root
   plus wrapped-agent direct children, the same rule as `descendant_cpu_seconds`), skipping pids whose command can no
   longer be read. It returns None when no process table is available.
4. Add a small formatter `describe_commands(commands: Mapping[int, str]) -> str` that renders
   `"<command> (pid N); <command> (pid M)"`, sorted by pid, so log lines are deterministic for tests.
5. Give every new public function a docstring (ruleset §2) and keep each well under the complexity limits.

- **Is Bottleneck:** NO

- **Relevant rules:** ruleset §2 (types, docstrings); repository ruff limits (no new `# noqa`).
- **Potential failure modes for this step:** The refactor changes `descendant_cpu_seconds` results; command lines
