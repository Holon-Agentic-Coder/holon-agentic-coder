### Strategy Rationale

The cost is quadratic in tests per worker because every `tmp_path_factory.mktemp(...)` and every built-in `tmp_path`
call `_pytest.pathlib.make_numbered_dir`, which runs `os.scandir` over the worker base temp to find the highest used
number. Three autouse fixtures add three entries per test, plus `tmp_path` for most tests, so a worker ends with 10,000+
entries and the last test scans all of them several times. Two independent fixes compound:

1. The three autouse fixtures that only need a private empty directory (`isolated_claude_home`, `isolated_env_file_dir`,
   `isolated_layered_config`) take their directories from one per-test parent created by a process-local counter under a
   dedicated sub-directory of the worker base temp. This removes three entries per test from the base temp and makes
   those three directories O(1).
2. The suite's numbered-directory creation, which `tmp_path`, `tmp_path_factory.mktemp` (including
   `feature_worktree_cwd` and `hermetic_git_config`) all use, is replaced at configure time by a counter-backed
   allocator that scans a `(root, prefix)` pair once, then increments, and on `FileExistsError` rescans and retries, so
   it never reuses a name.

Fix 2 alone already removes the quadratic term; fix 1 is the intent's preferred shape and keeps the base temp small,
which also keeps pytest's end-of-session retention cleanup cheap. Both are kept in a new module `tests/fast_tmp_dirs.py`
so `tests/conftest.py` (422 lines, not under a budgeted package, but the rule says new helper code goes into new
modules) only gains a few wiring lines and loses the three `mktemp` calls.

Aggregation: overall `p_success_pred` is bounded by the implementation step (Step 2, 0.88) and the measurement step
(Step 6, 0.85, the 3x median-test threshold depends on the host) and slightly discounted for Step 7 depending on CI

## Plan Description & Strategy

Add a new test-support module `apps/sandbox-executor/tests/fast_tmp_dirs.py` that holds two constant-time helpers:

- `NumberedDirAllocator` (or an equivalently named class): a drop-in for `make_numbered_dir(root, prefix, mode)` that
  keeps a per-`(root, prefix)` next-number counter, seeded by a single directory scan the first time that pair is seen,
  claims names with `os.mkdir(path, mode)` and on `FileExistsError` rescans and retries, so it never reuses a name. It
  is installed for the session by an `install`/`uninstall` pair (or a context manager) that replaces
  `_pytest.tmpdir.make_numbered_dir` and restores it on cleanup.
- `PrivateTestDirs` (or `per_test_private_root`): a process-local counter that creates one new directory per test under
  a dedicated `isolated` sub-directory of the worker base temp, mode `0o700`; the three autouse fixtures create their
  own child (`claude-home`, `env-files`, `layered-config`) in it.

Then wire `tests/conftest.py`: a `pytest_configure` hook (with `config.add_cleanup`) installs the allocator, a
function-scoped fixture provides the per-test parent, and the three autouse fixtures take their directories from it.
`feature_worktree_cwd` and the session `hermetic_git_config` keep `tmp_path_factory.mktemp`, which is now constant-time.
A new test module `tests/test_fast_tmp_dirs.py` proves constant time, uniqueness and the isolation guarantees. Before
and after numbers are measured on the same machine with three alternating runs, and the CI per-test floor is re-measured
from the pull request's own CI run.

Execution is one plan on one execution branch: the change is small (three test-harness files), low risk and fits the
entropy budget with a wide margin.

### Intent & Git Integration

- **Step Intent:** Provide a numbered-directory allocator and a per-test private-directory helper whose cost does not
  depend on how many directories already exist.
- **Git branch:** the plan's execution branch
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Create `apps/sandbox-executor/tests/fast_tmp_dirs.py` with a module docstring explaining the quadratic cost of
   pytest's numbered directories, what the module replaces and the never-reuse guarantee.
2. `NumberedDirAllocator` (class): holds a `dict` from `(resolved root, prefix)` to the next number and a
   `threading.Lock`. Its `__call__(root, prefix, mode=0o700)` matches the keyword signature recorded in Step 1 and:
   - on the first call for a key, seeds the counter with one scan of `root` (max existing numeric suffix of entries
     starting with `prefix`, plus one; zero when none), reusing pytest's own suffix parsing rule so `prefix` values with
     digits behave the same;
   - tries `os.mkdir(root / f"{prefix}{n}", mode)` and increments the counter;
   - on `FileExistsError` rescans and retries, at most a fixed number of attempts (10, like pytest), then raises
     `OSError` naming root and prefix, so a name is never reused and a pathological collision fails loudly;
   - returns the created `Path`. It does not maintain pytest's `<prefix>current` symlink (it is only a convenience for
     humans browsing a base temp, and costs two extra syscalls per call); if Step 1 found a test relying on it, keep it
     instead with a single `os.symlink` replace, which is still constant time.
   - Keep each method well under the ruff complexity limits by splitting the seeding scan into a small helper.
3. `install_fast_numbered_dirs()` / `uninstall` (or a context-manager function): replaces
   `_pytest.tmpdir.make_numbered_dir` with a fresh allocator and returns a callable that restores the original. Only the
   reference in `_pytest.tmpdir` is replaced, so `make_numbered_dir_with_cleanup` and the base temp's own creation and
   retention stay pytest's.
4. `PrivateTestDirs` (class) or `new_private_test_dir(base_temp)` function: under `base_temp / "isolated"` (created once
   per process with `exist_ok`) creates `t{n}` with an in-process counter and `os.mkdir(..., 0o700)`, with the same
   `FileExistsError` rescan-and-retry rule (a stale directory left by an earlier run under a reused `--basetemp` is
   skipped, never reused). Returns the new parent `Path`.
5. Full type annotations and docstrings on every public name (`holon-config/world/ruleset.md` section 2); no imports
   from `sandbox_executor` (the module is pure test support).

## Step 4: Prove constant time, uniqueness and isolation in a new test module

- **Sub‑intent recommendation:** NO
- **Reasoning:** The tests are the acceptance evidence for criteria 2 and 3 and belong with the change; they are small.
- **Step Type:** TEST
- **Exploration level:** EXPLOIT

### Intent & Git Integration

- **Step Intent:** Add `apps/sandbox-executor/tests/test_fast_tmp_dirs.py` so a regression to a scanning allocator, a
  reused name or a shared private directory fails the unit suite.
- **Git branch:** the plan's execution branch
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Constant time, allocator: in a fresh `tmp_path` root, time the first 100 `NumberedDirAllocator` calls for one prefix,
   create 5,000 more, then time the next 100. Assert the later batch takes no more than a generous multiple (for example
   3x, plus an absolute slack of a few milliseconds) of the first. Use `time.perf_counter` and take the minimum of three
   repeats of each batch to make it robust on a loaded CI runner. As a deterministic companion that does not depend on
   wall time, wrap `os.scandir` (via `monkeypatch`) in a counter and assert that after the first call for a
   `(root, prefix)` pair no further scans happen while names are free.
2. Constant time, private directories: the same pattern for `new_private_test_dir` (5,000 then 100 against the first
   100), plus the scan counter.
3. Never reuse: pre-create `prefix0` to `prefix4` and a foreign `prefix7` after seeding; assert the allocator skips to

   env-file, layered-config or `tmp_path` directory. Under xdist the worker base temp is per worker (`popen-gwN`), so

## Rejected Alternatives

- **Only fix the three autouse fixtures (no allocator):** removes three entries per test but leaves `tmp_path`, which
  most tests use, scanning a base temp that still grows one entry per test; still quadratic, so it would not meet the
  "first and last test cost the same" goal.
- **Use `--basetemp` per test or `tmp_path_retention_policy=none`:** retention only deletes at session end or for
  passing tests' directories after the fact and does not stop the scan per call; per-test base temps are not something
  pytest supports.
- **Plain `tempfile.mkdtemp` for `tmp_path`:** constant time but drops pytest's readable `test_name0` naming that
  developers use when inspecting failures; the counter allocator keeps the names and is equally cheap.
- **Changing `module_budgets.json` or anything under `src/`:** forbidden by the intent and the frozen-budget rule, and
  unnecessary.
