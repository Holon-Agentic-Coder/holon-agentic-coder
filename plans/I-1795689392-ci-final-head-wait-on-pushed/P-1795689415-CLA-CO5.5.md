## Plan Description & Strategy

Current behaviour (`apps/sandbox-executor/src/sandbox_executor/flow/github/ci_final_head.py`, 286 lines, budget 400 =
`default_max_lines`):

1. `_settled_status` calls `_wait_for_pr_head`. That function reads the pushed head (`git rev-parse HEAD`) and polls
   `GitHubAdapter.pr_head_sha(branch)` every `CI_REGISTRATION_POLL_SECONDS` (15 s) for up to
   `resolve_ci_registration_timeout()` (180 s). If the PR head never matches, it raises a `RuntimeError`, which
   `check_final_head_ci` turns into `unknown` after three minutes of idle time.
2. Only after that does it probe `gh pr checks <branch>` (the PR's head checks), wait for registration if needed, and
   settle pending checks through `wait_for_pending_ci`.

New behaviour:

- Read the pushed head and the PR head **once**, with no polling loop.
- **Head matches, or either head is unknown:** take the existing branch-probe path (`probe`, then
  `_wait_for_ci_registration`, then `wait_for_pending_ci`). This leaves the CI wait policy unchanged. If checks are
  still not registered after the registration wait, do one fresh probe. If that still finds nothing, the result is
  `unknown` with the reason "no checks registered for the pushed head".
- **PR head lags the pushed head:** do not wait. Probe the **pushed commit's own check runs** through
  `check.github.gh(["api", "--paginate", "repos/{owner}/{repo}/commits/<sha>/check-runs", "--jq", CHECK_RUNS_JQ])`,
  parsed with `ci_head_checks.parse_check_runs` and `latest_checks_for_head`. Convert them to the `gh pr checks`-shaped
  dicts that `summarise_ci_checks` already understands, so the result has `source = github_cli`. That commit probe then
  drives the unchanged `wait_for_pending_ci` and `classify_final_head` logic, so the real CI outcome of the pushed
  commit comes back. If the commit has no check runs, do exactly one retry after one poll interval: a fresh PR-head read
  and a fresh commit probe. If the PR head now matches, fall back to the branch path. If checks are still absent, return
  `unknown` at once with the reason "pull request head lagged the pushed head (<pr8> vs <pushed8>) and no checks
  registered for the pushed head".
- `unknown` never becomes `success`. Only `classify_final_head`'s existing `all_passed is True` branch yields success.
  An unknown result returns straight from `check_final_head_ci`; the timing-rerun path only runs for `failed`.

The work fits in a single plan (`entropy_pred` 4.0 against a budget of 15.0), so there is no sub-intent list.

1. Imports: add `CHECK_RUNS_JQ`, `PASSING_CONCLUSIONS`, `CANCELLED_CONCLUSIONS`, `parse_check_runs` and
   `latest_checks_for_head` from `sandbox_executor.flow.github.ci_head_checks`, and `summarise_ci_checks` from
   `ci_policy`. Read-only reuse; neither module is edited. `ci.py` is not touched.
2. Add the reason constants `PR_HEAD_LAGGED_REASON = "pull request head lagged the pushed head"` and
   `NO_CHECKS_REASON = "no checks registered for the pushed head"`. These are new private-style names; every existing
   public name (`BOOKKEEPING_PATH_PREFIXES`, `FinalHeadSeams`, `check_final_head_ci`, `classify_final_head`,
   `format_final_head_ci`, `not_pushed_record`, `MAX_REASON_CHARS`, plus `_bookkeeping_only` and `_git_changed_paths`
   imported by `review_restart.py`) keeps its signature.
3. Add `_as_pr_check(head_check)`. It maps a `HeadCheck` to the `gh pr checks` shape `{name, bucket, state, link}`:
   - status not `completed`: bucket `pending`
   - conclusion `skipped`: bucket `skipping`
   - other passing conclusions: bucket `pass`
   - cancelled or stale: bucket `cancel`, which matches what `gh pr checks` reports
   - anything else: bucket `fail`, state `FAILURE`

   The link is `https://github.com/actions/runs/<run_id>` when `run_id` is known, so `parse_run_id` and the existing
   detail lookup and timing-rerun logic keep working.

4. Add `_commit_probe(check, sha)`, which returns a zero-argument probe. It calls
   `check.github.gh([...api check-runs for sha..., "--jq", CHECK_RUNS_JQ])` inside try/except. On a non-zero exit, an
   exception or an empty list it returns `{"source": "unregistered", "total": 0, "pending": 0, "checks": []}`. Otherwise
   it returns `summarise_ci_checks([_as_pr_check(c) for c in latest_checks_for_head(parse_check_runs(stdout), sha)])`.
   Routing through `check.github` keeps the existing `FinalHeadSeams.github` seam authoritative, so tests stay hermetic
   with `FakeGitHub(cli=...)`.
5. Replace `_wait_for_pr_head` with `_select_probe(check, policy)`, which returns `(probe, lagged_reason_or_None)`:
   - Read `pushed` and `pr_head` once, through the seams or the `_git_gh_head` defaults.
   - If either is None or they are equal, return the branch probe (`seams.probe or check.default_probe()`) and None.
   - Otherwise return the commit probe and the lagged reason, which embeds the first 8 characters of both shas.
   - There is no deadline loop and no `RuntimeError`.
6. Rewrite `_settled_status` around `_select_probe`. To stay within ruff limits (`C901 <= 10`, `PLR0912 <= 12`), move
   the registration handling into `_registered_status(check, probe, lagged, policy)`:

     `github_cli`, take one fresh probe. If it is still unregistered, attach `unknown_reason = NO_CHECKS_REASON` to the
     status.
   - **Lagged path:** probe the commit. If unregistered, call `policy.sleep(CI_REGISTRATION_POLL_SECONDS)` once, then
     re-run `_select_probe`. If the PR head caught up, continue with the branch path. Otherwise probe the commit again.
     If it is still unregistered, attach `unknown_reason = lagged reason + "; " + NO_CHECKS_REASON`.

   Pending checks still settle through `wait_for_pending_ci(context, probe, ci_status, policy, stop_on_failure=True)`
   with whichever probe was selected.

7. In `classify_final_head`, keep the signature. The first branch (`source != github_cli`) uses
   `ci_status.get("unknown_reason") or "CI checks were not measured on GitHub."`, so the reason is specific and the
   state stays `unknown`. No other branch changes, and success still requires `all_passed is True`.
8. In `_rerun_timing_once`, use `_select_probe(check, policy)[0]` instead of the fixed branch probe for
   `_wait_for_rerun_start`, so a lagged head watches the pushed commit's reruns. In `_resolve_final_head`, prefer the
   pushed head and fall back to the PR head, since the measured checks now belong to the pushed commit. Existing tests
   pass `pushed_head=lambda: None`, or a tmp_path outside git, so they resolve as before.
9. Keep the module at or below 380 lines (budget 400). Check with `uv run python scripts/check_module_budgets.py` (or

### Strategy Rationale

The stall is entirely in `_wait_for_pr_head`. The pushed commit's check runs are authoritative and can be read directly
through `gh api repos/{owner}/{repo}/commits/<sha>/check-runs`. The repository already parses that API in
`ci_head_checks.py`, so the fix removes the wait rather than tuning it. Several choices keep the blast radius to one
module:

- The commit probe goes through the existing `FinalHeadSeams.github` adapter seam (`GitHubAdapter.gh`).
- Its output is converted into the `gh pr checks` shape, so `summarise_ci_checks`, `wait_for_pending_ci`,
  `classify_final_head`, the detail lookup and the timing-rerun path work unchanged.

The CI wait policy in `ci.py` and the review loop is untouched: the branch path still uses `_wait_for_ci_registration`
when heads match.

Scope note: `tests/test_calibrate_final_head_ci.py` has two tests that assert the removed behaviour.
`test_pr_head_never_matching_pushed_head_is_unknown` encodes the very three-minute unknown this intent fixes. Leaving
them would make acceptance criterion 7 ("existing final-head tests pass") unsatisfiable alongside criterion 1. Amending
those two tests to the new contract, while keeping their safety property, is the minimal, higher-EV resolution. No
source file outside scope changes.

Aggregation:

- `p_success` is roughly the product of the bottleneck Step 1 (0.86) and the near-certain later steps, adjusted upward
  for correlation, giving 0.82.
- Entropy is the step sum: `2.5 + 1.0 + 0.5 = 4.0`.
- Cost is the step sum: `6 + 3 + 2 = 11`.
- Impact is 65. This is a recurring three-minute stall and a spurious unverified head at the end of every flow where
  GitHub lags.
- Learning value is 3.0. It confirms whether commit-level probing removes the observed unknowns.

Overall: `EV = 0.82 * 65.0 + 0.5 * 3.0 - 0.3 * 4.0 - 11.0 = 53.3 + 1.5 - 1.2 - 11.0 = 42.6`.
