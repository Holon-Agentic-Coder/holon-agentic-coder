## Plan Description & Strategy

The design is the same as plan `P-1795685415-CLA-CO5.5`, whose execution branch
`I-1795685390-single-runner-per-checkpoint/P-1795685415-CLA-CO5.5/E-1795703416-CLA-CO5.5/_` holds a complete, passing
implementation:

- `flow/run_lock.py` and `flow/run_lock_record.py`: a per-slug exclusive `fcntl.flock` lock at
  `<git common dir>/holon/flow-run-locks/<slug>.lock`. It records pid, host, start time, slug and worktree as JSON in
  the lock file. A held lock refuses with a message that names the holder pid and the lock path. A lock left by a dead
  pid, or whose flock nobody holds, is taken over and the takeover is logged. The kernel releases the lock when the
  process dies, and it is also released explicitly at exit. `flow/admission_lock.py` is unchanged.
- `flow/process_reaper.py`: the run registry, the SIGINT/SIGTERM handlers and the exit hook. At the end of a run it
  terminates the process groups of children the run spawned, the docker run clients, and each container launched with
  the run's `--name` / `holon.flow.run=<run id>` label (stopped with `docker stop`).
- `launcher/run_tracking.py`: the launch-side seam. It adds container identity args (name and label) and runs the docker
  client in its own process group, tracked by the run. With no active flow run it does nothing, so `holon review` and
  other direct launches are unchanged.
- `flow/lazy_exports.py`: registers the new flow modules' public names, which the `flow` package export contract
  requires (`tests/flow/test_package_exports.py`). The previous run needed this, but its touch set did not list the
  file.
- Edits to `cli/commands/_flow_worktree.py` and `launcher/containers.py` are net-zero or smaller: one hook call each,
  balanced by small simplifications. `turns.py` stays at or below 892 lines (its frozen override) and should not need
  any change.

Strategy: start from the previous execution's code, re-validate it against the current `main` merge (`1567b6b6`), and
