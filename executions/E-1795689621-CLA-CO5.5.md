## Steps Executed

### Step 1: one-shot head read and pushed-commit check-runs probe

- Replaced `_wait_for_pr_head` in `ci_final_head.py` with `_select_probe`. It reads the pushed head once and, only
  when that is known, the pull request head once. There is no deadline loop and no `RuntimeError`.
- Added `_commit_probe`. It reads `gh api --paginate repos/{owner}/{repo}/commits/<sha>/check-runs` through the
  `FinalHeadSeams.github` adapter and parses the output with `parse_check_runs` and `latest_checks_for_head`.
  `_as_pr_check` and `_pr_bucket` convert the result into the `gh pr checks` shape for `summarise_ci_checks`.
- Split the registration handling into `_branch_status` and `_lagged_status`:
  - The branch path keeps `_wait_for_ci_registration`, then takes one fresh probe.
  - The lagged path does one retry: one `CI_REGISTRATION_POLL_SECONDS` sleep, a fresh head read and a fresh commit
    probe.
- Added the `unknown_reason` values `PR_HEAD_LAGGED_REASON` and `NO_CHECKS_REASON`; `classify_final_head` reports
  them. Success still requires `all_passed is True`.
- `_rerun_timing_once` now watches the selected probe. `_resolve_final_head` now prefers the pushed head.
- The module is 355 lines (budget 400), and `ruff check` passes with no `# noqa`. `ci.py` is unchanged.

### Step 2: registration tests and the two head-wait tests on the new contract

- Added `apps/sandbox-executor/tests/flow/github/test_ci_final_head_registration.py` with six hermetic tests. They use
  a fake clock and `FakeGitHub(cli=...)`, so no real time passes and no real `gh` runs. The tests cover:
  - a lagging head with registered passing checks returns `success` with no sleep and one `gh api` call
  - a lagging head returns the pushed commit's own failure, not the stale branch green
  - pending commit checks settle through the wait policy
  - a lagging head with no commit checks makes one retry (two probes and one `CI_REGISTRATION_POLL_SECONDS` sleep),
    then returns `unknown` with the lagged reason and never `success`
  - a head that caught up on the fresh read takes the branch path
  - matching heads that never register checks return `unknown` with "no checks registered for the pushed head"
- Confirmed against the old module (restored from `HEAD~1` temporarily): all 6 new tests fail.
- `tests/test_calibrate_final_head_ci.py`: both named tests now inject commit check runs through `FakeGitHub(cli=...)`.
  The stale branch probe is never consulted (`fakes.probes == 0`), which keeps the original safety property. No other
  test changed.
