# Execution Record: E-1795399083-CLA-CO5.5

## Summary

Implements plan `P-1795398882-CLA-CO5.5` for intent `I-1795398860-holon-env-all-via-env-file-v2`. Every forwarded
`HOLON_*` item now travels in the 0600 `--env-file` in the main run (`run_docker_container`) and the pre-flight probe
(`build_probe_docker_cmd`). Both builders use one shared predicate, `cli.is_env_file_item`, so the two paths cannot
drift apart again. `is_secret_env_item` is unchanged, so non-`HOLON_*` routing (proxy variables, `GITHUB_TOKEN`, claude
credential names) is the same as before. The `Executing:` echo still goes through `redact_command`, and it now holds no
`HOLON_*` item.

Deviations from the plan, each needed to avoid a behaviour change:

- **Non-UTF-8 values:** the plan's line-break exception was widened to values that cannot be encoded as UTF-8
  (`surrogateescape` bytes from `os.environ`). `write_env_file` cannot write them (it raises `UnicodeEncodeError`), and
  docker rejects env-files that are not valid UTF-8. Before this widening, `test_config_fuzz.py` failed: a non-UTF-8
  budget value made the run exit 1. Such a value now falls back to the unchanged credential rule, as a multi-line value
  does. The rule lives in the private helper `_fits_env_file`.
- **Probe runner binary:** the probe's `_reference_secret_args` now always keeps the runner binary (`runner_cmd[0]`)
  literal. Without this, `HOLON_AGENT_ID=claude` in the env-file turned the `claude` binary into
  `exec "${HOLON_AGENT_ID}"`, and every claude, codex and pi probe switched to `sh -c`. Runner arguments are still
  referenced exactly as before.

## Steps Executed

1. **Step 1: route `HOLON_*` items through the env-file.** In `cli/__init__.py`, added `is_env_file_item(key, value)`
   (exported in `__all__`) and the private helper `_fits_env_file`. `run_docker_container.add_env` now calls the
   predicate, and the comment above it was updated. `preflight.build_probe_docker_cmd` imports and uses the same
   predicate, and its docstring was updated. The `--env-file` insertion, sweep, error handling, removal and echo are
   unchanged.
2. **Step 2: fuzz test** (`tests/test_url_message_fuzz.py`). Added
   `test_every_forwarded_holon_value_stays_off_argv_and_echo`. It runs every name in `INVALID_VALUE_ENV` (including
   `HOLON_TURN_TIMEOUT_SECONDS` and `HOLON_STAGE_BUDGET_SECONDS`) and `HOLON_AGENT_SETTINGS`, `HOLON_AGENT_EFFORT`,
   `HOLON_MODEL`, `HOLON_PROXY_URL` and `HOLON_EXAMPLE_SETTING`, each with every bare shape from `_credential_shapes()`.
   For each case it checks the main-run argv, the probe argv and the echo, and that both env-file mappings hold the
   value. In `test_invalid_envelope_value_never_echoed_by_doctor_or_run_path`, the `TIMEOUT`/`BUDGET` names no longer
   skip the run. Their argv must hold no fragment and the env-file must hold every forwarded value. The env-file path is
   masked before the fragment check. Against the pre-change source, the new test fails for all 10 names (124 cases each)
   and the updated test fails too. After the change, both pass.
3. **Step 3: argv-pinning tests moved to env-file reads.** Changed `test_cli.py`, `test_preflight.py`,
   `test_cli_unlimited_budgets.py`, `test_local_llm.py`, `test_host_worktree_sandbox.py` and
   `flow/test_worktree_all_stages.py`. Each argv assertion on a `HOLON_*` item became an env-file assertion plus a check
   that no `HOLON_` item is on the argv. Credential-free URL tests now assert the value is in the env-file unchanged.
   `test_probe_keeps_a_credential_free_multiline_settings_json_on_the_argv` documents the one exception. New probe tests
   cover a single-line settings JSON, a bare credential under `HOLON_EXAMPLE_SETTING`, and the literal runner binary.
   `test_host_worktree_sandbox.py` gained `_docker_runs`, which returns env-files and masks the random path, and now
   compares argvs and env-files separately. No module outside the touch set needed changes. A final grep found no
   remaining `HOLON_*` argv pins except the documented multi-line exception.
