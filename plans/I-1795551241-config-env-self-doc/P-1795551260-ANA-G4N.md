  - A constant tuple listing the five target module paths resolved relative to the repository's
    `apps/sandbox-executor/src/sandbox_executor/` directory: `config_env.py`, `config_env_keys.py`,

    (reporting module path, node name, and line number).
  - A tokenizer helper using `tokenize.generate_tokens(io.StringIO(source).readline)` that inspects every
    `tokenize.COMMENT` token and checks an allowlist predicate:
    - Shebang on line 1 starting with `#!`.
    - PEP 263 encoding declaration on line 1 or line 2 matching the standard `coding[:=]\s*[-\w.]+` pattern.
    - Tool pragmas whose stripped comment body starts with `noqa` (followed by end-of-string, `:`, or whitespace),
      `type: ignore` (followed by end-of-string, `[`, or whitespace), or `pragma: no cover` (followed by end-of-string
      or whitespace).
  - Parametrized tests over all five scoped modules asserting:
    - Each module file exists and has zero AST docstrings.
    - Each module has zero non-allowlisted comments.
  - Focused unit tests on the AST and comment-allowlist helpers using in-memory source snippets to prove that
    explanatory comments and module/class/function docstrings are caught, while shebangs, encoding lines,
    `# noqa: E501`, `# type: ignore[assignment]`, and `# pragma: no cover` are permitted.
  - Keep the test completely hermetic (no network, no subprocesses, no external state, no reliance on working
    directory).
