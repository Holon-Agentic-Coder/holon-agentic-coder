## Plan Description & Strategy

Add `apps/sandbox-executor/src/sandbox_executor/flow/calibrate_fetch_retry.py`, a small module (well under 60 lines)
that owns the bounded fetch retry for Stage 5: three attempts, backoff delays of 4 s then 8 s (12 s total, within the 10
to 15 s target and the 15 s ceiling), one `context.log` line per retry, and re-raise of the final `HostRemoteError`.
Permanent failures (remote branch missing, unsafe name) are raised at once. `_fetch_execution_branch` in
`calibrate_sync.py` calls this helper instead of `fetch_base` directly; its `except HostRemoteError` block (raise
`CalibrationSyncError` when a local origin ref exists and pushing is enabled, warning otherwise) is unchanged. A new
test file proves the success-after-retry path, the exhausted path in both outcomes, the attempt count and backoff bound,
the no-retry path for a missing remote branch, and that no real time is slept. Then the affected tests, lint (module
budgets and complexity) and the full suite are run once each in the foreground.

### Intent & Git Integration

- **Step Intent:** Provide `fetch_execution_branch_with_retry(context, branch, *, fetch=None, sleep=None)` that retries
  the origin fetch on transient `HostRemoteError` with a short, bounded backoff.
- **Git branch:** I-1795693496-fetch-execution-branch-retry/P-1795693524-CLA-CO5.5/E-{timestamp}-CLA-CO5.5/\_
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Create `apps/sandbox-executor/src/sandbox_executor/flow/calibrate_fetch_retry.py` with a module docstring naming its
   purpose (Stage 5 bounded retry of the origin fetch of the execution branch) and `from __future__ import annotations`.
2. Imports: `time`, `Callable` from `collections.abc`, `FlowContext` from `sandbox_executor.flow.context`, and
   `DEFAULT_REMOTE`, `HostRemoteError`, `fetch_base` from `sandbox_executor.flow.host_remote`. No import from
   `calibrate_sync` (no cycle) and none from entrypoints.
3. Module constants: `FETCH_BACKOFF_SECONDS: tuple[float, ...] = (4.0, 8.0)` (delay before attempts 2 and 3) and
   `FETCH_ATTEMPTS = len(FETCH_BACKOFF_SECONDS) + 1` (equals 3). Total backoff 12 s.
4. Private predicate `_is_permanent(exc: HostRemoteError) -> bool`: true when `exc.detail` (lower-cased) contains
   `couldn't find remote ref` (git's message when the branch is absent on origin) or starts with the unsafe-name prefix
   produced by `host_remote._name_error` (inspect that function during execution and match its stable wording, or
   compare against the set of unsafe-argument messages; keep the check to a small tuple of substrings).
5. Public function `fetch_execution_branch_with_retry(context, branch, *, fetch=None, sleep=None) -> None` (keyword-only
   injectables keep `PLR0913` at 4 arguments). Resolve `fetch or fetch_base` and `sleep or time.sleep` inside the call,
   so `patch("sandbox_executor.flow.calibrate_fetch_retry.fetch_base")` and
   `patch("sandbox_executor.flow.calibrate_fetch_retry.time.sleep")` both take effect when the helper is reached through
   `sync_execution_ref`:
   - Loop `attempt` from 1 to `FETCH_ATTEMPTS`; call `fetch(context.target_worktree, branch, DEFAULT_REMOTE)`; return on
     success.
   - On `HostRemoteError` as `exc`: if `_is_permanent(exc)` or `attempt == FETCH_ATTEMPTS`, re-raise `exc` unchanged.
   - Otherwise pick `delay = FETCH_BACKOFF_SECONDS[attempt - 1]`, log exactly one line through `context.log`, for
     example
     `Stage 5 sync: fetch of origin/<branch> failed on attempt <n>/<FETCH_ATTEMPTS> (<exc.detail>); retrying in <delay>s.`,
     then `sleep(delay)`.
   - Catch only `HostRemoteError`; every other exception propagates.
6. Keep cyclomatic complexity well under 10; no `# noqa`.
