### Strategy Rationale

The intent is the first, lowest-risk child of the parent's three-way split, and it is accepted as is: it fits the 15.0
entropy budget as one plan, so no sub-intent list is used. The ordering (baseline, then one extraction per decision
area, then guards and validation) keeps each move independently testable against unchanged existing tests, which are the
behavioural oracle. Steps 2 to 5 are independent of each other and only share Step 1 and Step 6.

Aggregation: entropy, impact and cost are sums over steps (`entropy = 0.3 + 1.0 + 2.0 + 2.0 + 1.5 + 1.2 = 8.0`,
`impact = 3 + 8 + 12 + 12 + 10 + 8 = 53.0`, `cost = 0.5 + 1.5 + 2.5 + 2.5 + 2.0 + 2.0 = 11.0`). Probability is a
judgement rather than a product: the raw product `0.97 * 0.93 * 0.85 * 0.82 * 0.88 * 0.85 = 0.47` treats every step
failure as terminal, but each step is retried locally against fast tests, so the realistic failure modes are the two
bottlenecks (Step 4 noqa narrowing being rejected and Step 3 decomposition drift), giving 0.78. Learning value 4.0
(whether the identity-snapshot ratchet accepts a same-function narrowing, and how much each source module shrinks ahead
of the adapter child). `EV = 0.78 * 53.0 + 0.5 * 4.0 - 0.3 * 8.0 - 11.0 = 41.34 + 2.0 - 2.4 - 11.0 = 29.94`.

Strong assumptions: (1) `RUF100` is active because `RUF` is selected, so stale `noqa` codes fail lint, which forces the
narrowing decision in Step 4; (2) re-imports with the explicit `as` form are not "definitions" for
`tests/flow/test_package_exports.py` (it inspects only top-level `def`/`class` nodes), so moved names are not double
defined; (3) no test outside `tests/flow/github/` patches a name that moves (Step 1 verifies this by grep before any
