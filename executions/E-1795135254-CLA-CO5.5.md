## Steps Executed

### Step 1: fail-closed dispositions

- `resolver_evidence.default_disposition` now returns `open` at every severity; `settle_rejection` refuses an empty or
  `unspecified` reason at every severity (audit text `refused rejection (no reason)`); new `has_stated_reason`,
  `require_rejection_reason` and the documenting constant `ENGINE_REASONS` (`no-convergence`).
- `DispositionRecorder.record` refuses a hand-built `rejected` disposition without a stated reason (no row, signature
  not recorded, so it stays open).
- Test changes: `tests/test_resolver_evidence.py` replaced
  `test_an_unknown_reason_is_unspecified_never_out_of_scope` and the parametrised nit-default test (both encoded the
  defect) with refusal tests; new tests in `tests/test_review_report.py` and `tests/test_review_resolver_failure.py`.
  No other existing test asserted the old nit default.

### Step 2: a failed container resolver turn decides nothing

- `entrypoint/review_loop._run_resolver_agent` checks the exit code before reading the dispositions file (a file left by
  a failed turn is ignored), raises `ResolverTurnError("Resolver agent produced no usable output")` after a clean exit
  without a usable file, and `_turn_failure_label` names a usage, session or rate limit
  (`exited with code 1: usage limit reached`).
- Test changes: `tests/test_review_loop.py` `test_run_resolver_agent_with_autospec_agent_runner` and
  `test_run_resolver_agent_fallback_to_compose_cmd` expected `[]` for a clean exit without a file; they now expect the
  "no usable output" failure. Four new tests in `tests/test_review_resolver_failure.py`.

### Step 3: no adjudication rows after a failed resolver pass

- `flow/review/resolver.py`: `_dispatch_review_resolver` and `_invoke_resolver_pass` return `dispositions=()` on every
  error path (dispatch exception, container failure, seam exception, a mapping or `ResolverOutcome` carrying an error).
  The rejected-attempt fields are kept, so `_record_rejected_attempt` still writes its tests-failed row.
- `flow/review/loop.py`: the end-of-loop fallback records nothing when `resolver_error` is set; the loop result carries
  `open_findings` (the merged current and carried rows without a disposition) on every exit. Non-failure halts still
  record `open` rows (now open, not false rejections, because of step 1).
- Tests (new, `tests/test_review_resolver_failure.py`): the PR #203 incident replay with a usage-limited resolver
  mapping, the same with a raising resolver, and the host-dispatcher path with a container exiting 1.

### Step 4: carried findings, resolved first on resume, blocking approval

- New `flow/review/carried_findings.py` (141 lines): `serialize_open`, `deserialize_carried` (fail-closed),
  `merge_findings`, `undisposed`, `carried_blocker`, `CarriedPass` and `resolve_carried_first`. `undisposed` takes the
  recorded dispositions rather than `recorded_keys`, because the recorder also keys `open` rows.
- `FlowContext.carried_review_findings` (default `[]`, round-tripped in `to_dict`/`from_dict`, so older checkpoints load
  without a schema bump; `checkpoint.py` needed no change). A child intent starts with none.
- `run_review_loop`: carried rows go to the resolver before the first ensemble call (labelled with the halted pass,
  `first_label - 1`, so the pre-pass never shares the next ensemble iteration's label); a failed pre-pass starts no
  iteration; each later resolver input is `merge_findings(iter_findings, carried_rows)`; an ensemble approval while a
  carried row has no disposition becomes `CHANGES_REQUESTED` with a blocker naming the rows, a halt reason and no post.
  `_run_engine_review_loop` stores `open_findings` on the context, which the engine checkpoints after Stage 4.
- The flow package re-exports the new public names (`__init__.py`), as the package export test requires.
- Tests: new `tests/test_review_carried_findings.py` (helper tests plus the three resume variants through a saved and
  reloaded checkpoint, with one shared call log proving the resolver runs before the ensemble). The resume tests live
  in this new file rather than `tests/test_review_loop.py` to keep that file's fixtures separate. Changed
  `tests/flow/stages/test_decomposition.py::test_child_context_inherits_or_resets_every_field` to classify the new
  field (reset for a child). A mutation check (gate disabled) failed the variant (b) test as expected.
