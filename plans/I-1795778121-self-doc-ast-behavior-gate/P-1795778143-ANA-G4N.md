### Implementation Details (No code blocks, only logic/steps)

1. Define pure AST normalisation helpers in `scripts/check_self_doc_behavior.py`:
   - `is_docstring_statement(statement)`: returns true only when `statement` is `ast.Expr` whose `value` is
     `ast.Constant` with `isinstance(value.value, str)`.
   - `strip_docstrings(tree)`: an `ast.NodeTransformer` (or recursive walk over `ast.Module`, `ast.ClassDef`,
     `ast.FunctionDef`, `ast.AsyncFunctionDef`) that inspects only `node.body[0]`; if it is a docstring statement,
     removes it; if the node is a `ClassDef`, `FunctionDef`, or `AsyncFunctionDef` and `node.body` is now empty,
     replaces `node.body` with `[ast.Pass()]` (while leaving an empty `ast.Module.body` as `[]`). Non-leading string
     expressions anywhere in a body or nested block are never stripped.
   - `normalised_ast_dump(source)`: parses `source` with `ast.parse`, applies `strip_docstrings`, and returns
     `ast.dump(tree, include_attributes=False)`. Because `ast.parse` discards comments and whitespace and
     `include_attributes=False` drops line/column offsets, any comment or docstring removal produces an identical dump
     while any non-docstring AST change produces a different dump.
   - `compare_python_sources(before, after)`: returns a typed result indicating equivalence or mismatch (distinguishing
     `SyntaxError` in before/after from structural AST divergence).
2. Define pure trigger-detection helpers:
   - `has_self_doc_label(labels)`: case-insensitive check matching labels containing `self-doc`, `self_doc`, or
     `self-explaining`.
   - `has_self_doc_title(title)`: case-insensitive regex matching `self[-_ ]doc` or `self[-_ ]explaining`.
   - `is_self_doc_test_path(path)`: matches self-doc test files (filename matching `test_self_doc_*.py` or
     `self_doc_scanner.py`).
   - `is_diff_only_self_doc(changed_entries, read_blob)`: returns true when there is at least one changed file, at least
     one modified Python file or self-doc test file, and every changed file is either a self-doc test path or a
     modified/renamed `.py` file whose before and after sources are AST-equivalent under `compare_python_sources`. Any
     changed non-Python file (outside self-doc tests), added/deleted non-test `.py` file, or modified `.py` file with a
     runtime AST change returns false.
   - `detect_trigger_reason(labels, title, changed_entries, read_blob)`: returns `"label"`, `"title"`, `"diff-only"`, or
     `None` in that precedence order.
3. Define git revision-range inspection helpers:
   - `ChangedEntry` frozen dataclass holding `status`, `old_path`, `new_path`.
   - `git_changed_entries(base, head, repo)`: runs `git diff --name-status -z <base>...<head>` (falling back or raising
     `DiffUnreadable` with exit code 2 when base/head is empty or git fails) and parses `M`, `A`, `D`, `R*`, `C*`
     entries cleanly.
   - `git_read_blob(rev, path, repo)`: runs `git show <rev>:<path>` (UTF-8 with replacement on decode errors) and raises
     `DiffUnreadable` on failure.
   - `check_revision_range(base, head, repo)`: iterates over every modified or renamed `.py` file (`status == "M"` or
     `status.startswith("R")`) in `git_changed_entries`, compares `git_read_blob(base, old_path, repo)` against
     `git_read_blob(head, new_path, repo)` via `compare_python_sources`, and returns a list of failure descriptions
     (file path plus concise reason).
4. Implement CLI `main(argv=None) -> int`:
   - Accepts `--base`, `--head`, `--repo` (default `.`), `--pr-title` / `--pr-title-env`, `--pr-labels-json` /
     `--pr-labels-env`, and `--only-when-triggered` flag.
   - When `--only-when-triggered` is set, evaluates `detect_trigger_reason`; if `None`, prints a clear skip message and
     exits `0`; otherwise prints the trigger reason and runs `check_revision_range`.
   - When `--only-when-triggered` is not set, always runs `check_revision_range`.
   - Exits `0` on pass, `1` on AST mismatch or parse failure, and `2` on unreadable git diff or invalid revision.
5. Keep all functions small (`C901 <= 10`, `PLR0912 <= 12`, `PLR0913 <= 5`, `PLR0915 <= 50`), module length well under
   350 lines, and strictly self-explaining (no docstrings; no comments except `# why:` where needed).
