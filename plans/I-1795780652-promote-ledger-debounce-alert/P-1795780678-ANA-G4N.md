### Strategy Rationale

Removing the unguarded `on.push` trigger from `.github/workflows/promote-ledger.yml` and relying on the existing daily
`schedule` (`41 3 * * *`) plus `workflow_dispatch` (with `force` boolean input) is strictly better than adding a
`paths: ['holon-knowledge/ledger/pending/**']` filter on `push`: almost every merged intent pull request writes pending
ledger fragments under `holon-knowledge/ledger/pending/`, so a path-filtered `push` trigger would still fire on every
merge burst and reproduce the concurrency-queue cancellations (`cancel-in-progress: false` queues at most one pending
run and cancels intermediate runs). Removing `on.push` eliminates per-merge cancelled run storms completely while
keeping automated daily promotion and on-demand manual dispatch intact.

When `HOLON_LEDGER_BOT_TOKEN` is unset, adding a read-only sparse checkout of `holon-knowledge/ledger/pending` (using
the default read-only `GITHUB_TOKEN`, keeping `permissions: contents: read`) allows the missing-token step to count
pending `.jsonl` fragment files and emit an explicit `::warning::` annotation (plus step summary) naming the exact
backlog count, `HOLON_LEDGER_BOT_TOKEN`, and the required maintainer secret action, replacing the silent `::notice::`
no-op without breaking CI with a hard failure.
