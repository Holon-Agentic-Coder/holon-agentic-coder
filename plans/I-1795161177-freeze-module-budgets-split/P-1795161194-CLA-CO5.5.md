## Plan Description & Strategy

The work moves the per-module line budget from `apps/sandbox-executor/flow_module_budgets.json` to a frozen, generic
config at `holon-config/hygiene/module_budgets.json`. That config holds `default_max_lines: 200`, `packages` (currently
only `apps/sandbox-executor/src/sandbox_executor/flow`) and `overrides`: the 22 modules whose current budget is over
200, with repository-relative paths, sorted, one per line, plain integers. The 49 modules at 200 lines or less are
covered by the default.

A new `scripts/check_module_budgets.py` replaces the old checker. It has no hardcoded package, path or count beyond the
default config location; it fails over-limit modules with a "split the module; the budget may not be changed" message,
and turns stale or redundant overrides into `::warning::`. It also compares the config byte for byte with the merge-base
copy, failing any difference unless `HOLON_ALLOW_MODULE_BUDGET_CHANGE=1`.

Flow enforcement uses one shared module, `sandbox_executor/module_budget_guard.py`, which owns:

- the config path constant;
- the authorisation predicate, true only when the intent has a non-empty `module_budget_change` field;
- the environment flag name;
- path-matching helpers.

That module is used by:

- the planner entrypoint, to drop the config from the recorded touch set;
- Stage 3, through `touch_set_guard.py`, to refuse an execution diff that changes the config;
- the Stage 4 resolver: the in-container commit drops config changes and records a refusal, and the host-side push
  refuses a head whose diff changes the config;
- the role environment, to export the flag only when authorised.

CI passes the flag only when the PR has the `module-budget-change` label. The prompt templates and
`docs/architecture.md` state the rule: over the limit means split, and the budget is frozen except on the maintainer's
explicit instruction. Affected tests run first, then the full suite once, then `uv run task lint` and
`uv run task lint-docs`.

### Implementation Details (No code blocks, only logic/steps)

1. Constants are limited to `REPO_ROOT`, the default config path (`holon-config/hygiene/module_budgets.json` relative to
   `REPO_ROOT`) and the environment flag name `HOLON_ALLOW_MODULE_BUDGET_CHANGE`. The script hardcodes no package,
   module path or line count.
2. Arguments: `--config PATH` (default: the config path) and `--base PATH`. The base is a file holding the base copy for
   tests; the literal `none` means no base. When `--base` is omitted, the base is derived from git (point 5).
3. Load and validate the config. Exactly the keys `default_max_lines` (positive int), `packages` (non-empty list of
   strings) and `overrides` (mapping of path to positive int, not bool). Unknown keys or wrong types are errors.
4. Counting: for each package, list every `*.py` under `REPO_ROOT / package` and key it by its repository-relative POSIX
   path; read the line count the same way the old script did. The limit is the override if present, otherwise the
   default. Over-limit message:
   `::error::module budget: <path>: <n> lines exceeds its limit of <limit>; split the module into smaller modules - the budget is frozen and may not be changed`.
5. Warnings, never failures, and the exit code is unaffected:
   - an override whose path does not exist or is outside every package;
   - an override at or below `default_max_lines`;
   - unsorted override keys (a formatting nit, reported as a warning; the freeze check below catches any change anyway).
6. Freeze check (keeps `main` simple):
   - Obtain the base copy: with `--base`, read that file. Otherwise run `git merge-base HEAD origin/main`. If that fails
     (no remote, shallow clone or no common ancestor), print nothing and skip the check ("skipped quietly"). Otherwise
     run `git show <sha>:<repository-relative config path>`; if the path is missing at the base, print a `::notice::`
     (no base copy: this is the bootstrap) and skip.
   - Compare raw bytes. Any difference, including reformatting, is a change. If the environment flag equals `1`, print a
     `::notice::` saying the change was authorised. Otherwise print a `::error::` that names the change (raised,
     lowered, added or removed override, or changed default or packages, computed from the parsed JSON when both parse;
     otherwise "reformatted") and says: the budget configuration is frozen; split the module instead; it changes only on
     the maintainer's explicit instruction (the `module-budget-change` PR label in CI, or the intent's
     `module_budget_change` field in the flow).
7. Keep each function within the C901 and PLR limits by splitting load, count, violation, warning, base-lookup and
   diff-description helpers. Use `subprocess.run` with an argument list, `check=False` and `capture_output`, and run in
   `REPO_ROOT`.
8. Success message: `Module budgets passed: <n> modules in <k> packages (default <d>, <o> overrides)`. Exit 1 on any
   error, otherwise exit 0.
