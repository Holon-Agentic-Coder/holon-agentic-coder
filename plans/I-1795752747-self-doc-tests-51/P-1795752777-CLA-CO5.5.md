4. Define `MACHINE_DIRECTIVE` as a compiled regex matching a comment body that starts with one of:
   - `noqa`
   - `type:`
   - `pragma`
   - `fmt:`
5. Define `REASON_PREFIX = "why:"`.

**Helper functions**

Each function has an intention-revealing name and stays well under the complexity limits.

- `comment_body(comment)`: strip the leading hashes and whitespace.
- `is_allowed_comment(comment, line_number)`: true when any of these holds:
  - it is a shebang on line 1;
  - it is an encoding declaration on line 1 or 2;
  - the body starts with `why:` (case-insensitive, matching the lint rule);
  - the body matches `MACHINE_DIRECTIVE`.
- `disallowed_comments(source)`: run `tokenize.generate_tokens` over `io.StringIO(source)`. Return `line: text` for
  every COMMENT token that is not allowed.
- `docstrings(source)`: run `ast.walk` over `ast.parse(source)`. For every Module, ClassDef, FunctionDef and
  AsyncFunctionDef whose first body statement is an `Expr` holding a `str` `Constant`, return the line and node kind.

**Tests**

1. A test parametrised over `SCOPED_TEST_FILES` with readable ids (the file stem). It reads the file and asserts that
   `docstrings(source) + disallowed_comments(source)` is empty. The assertion message lists the offending lines.
2. Two small sanity tests that keep the guard honest without touching other files:
   - One feeds an in-memory source string with a docstring, a plain comment, a `# why:` comment, a `# noqa` directive
     and a shebang. It asserts exactly the docstring and the plain comment are reported.
   - One asserts that every path in `SCOPED_TEST_FILES` exists, so a renamed file cannot pass vacuously.

**Checks**

1. In the foreground, run `uv run pytest apps/sandbox-executor/tests/test_self_doc_tests_51.py`. Confirm:
   - the 12 parametrised cases fail, matching the baseline counts;
   - the sanity tests pass.
2. Run `uv run ruff check` and `uv run ruff format --check` on the new file.
3. The red state may be committed as an intermediate commit only if the branch flow tolerates it. Otherwise commit the
   new test together with step 3 and step 4.
