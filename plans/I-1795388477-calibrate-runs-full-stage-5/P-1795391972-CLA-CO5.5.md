## Plan Description & Strategy

Extract the shared Stage 5 core, "calibrate, then reconcile and commit, then promote and commit", into
`sandbox_executor/flow/stage5.py` as `run_stage5(context, steps, verdict, report_only=False) -> Stage5Outcome`.
`run_calibrate_stage` keeps the flow-only concerns: the conflict gate, execution-branch checkout and sync, preparing the
`/calibrated` branch, stage-conflict resolution, the fallback report on calibration exceptions, publishing, final-head
CI and the CI re-verify. It calls `run_stage5` for the three steps. `holon calibrate` builds a minimal standalone
`FlowContext` (target worktree, execution branch, `dry_run` equal to `--no-commit`), resolves the verdict from the
executions ledger, and calls the same `run_stage5` with the same `Stage5Steps` built by `stages/calibrate.py`.
`--report-only` passes `report_only=True`, which stops after `run_calibrate` and prints a clear "report only" notice.
`--json` prints the calibration report dict extended with a `stage5` object containing `mode`, `reconciliation` (status,
verdict, rows appended) and `newly_promoted_count`.

Idempotency: before reconcile, the core checks `executions.jsonl` for an existing `reconciliation` event whose
`parent_action_id` is the execution branch. If one exists, it skips the call (`status: already_recorded`). Promotion is
already idempotent (it returns only newly promoted candidates), and the commit helpers are no-ops when nothing changed.

Execution branch: one plan branch, no sub-intents. Work order: verify assumptions, add the core, rewire the stage,
rewire the CLI, add tests, then run the affected tests, the full suite and lint.

### Implementation Details (No code blocks, only logic/steps)

1. Create `apps/sandbox-executor/src/sandbox_executor/flow/stage5.py` with a module docstring explaining that it is the
   single Stage 5 core shared by the flow stage and `holon calibrate`.
2. `Stage5Steps` is a frozen dataclass of callables: `calibrate`, `reconcile`, `promote`, `commit_reconciliation`,
   `commit_promoted`, `warn_ledger_failure`, plus an optional `on_calibrate_error`. The callables keep the exact
   signatures of `run_calibrate`, `reconcile_records`, `promote_pending_candidates`,
   `_commit_stage5_reconciliation(context, repo_dir)`, `_commit_stage5_promoted_artifacts(context, repo_dir, count)` and
   `_warn_ledger_failure`.
3. `Stage5Outcome` is a dataclass with `report_dict`, `calibration_succeeded`, `report_only`, `reconciliation` and
   `promoted_candidates`. `reconciliation` is a dict with `status` (one of `recorded`, `already_recorded`,
   `skipped_report_only`, `skipped_no_commit`, `skipped_no_ledger`, `skipped_no_verdict`, `left_uncommitted`, `failed`),
   `verdict` and `rows_appended`. It also has `newly_promoted_count` and `to_json_dict()`, which returns the `stage5`
   object for the CLI's `--json` output.
4. `run_stage5(context, steps, verdict, report_only=False)`:
   - Calls
     `steps.calibrate(execution_branch=..., target_worktree=context.target_worktree, json_output=False, skip_commit=context.dry_run, log_fn=context.log)`.
     On success it sets `context.calibrated_branch` and records the report dict.
   - On an exception other than `LedgerRewriteError` and `CalibrationFormatError`: if `steps.on_calibrate_error` is set
     (the flow sets it), call it and use the fallback report dict with `calibration_succeeded=False`; otherwise re-raise
     (the CLI keeps its fail-loud exit 1). `LedgerRewriteError` and `CalibrationFormatError` always propagate, so the
     flow's existing fail-closed handling stays in `stages/calibrate.py`.
   - If `report_only`, return straight away with reconciliation `skipped_report_only` and no promotion.
   - Otherwise call the private helpers `_reconcile_execution` and `_promote_candidates`. Each helper stays under the
     ruff complexity limits, and the bodies mirror the current block in `_calibrate_execution_branch` exactly: same
     paths, `max_age_days=14`, the same reason string, commit only when calibration succeeded, the same log lines, and
     `LedgerRewriteError` re-raised while any other exception goes to `steps.warn_ledger_failure`.
5. The idempotency guard `_already_reconciled(ledger_path, execution_branch)` streams `executions.jsonl` and returns
   True when any row has `event_type == "reconciliation"` and `parent_action_id == execution_branch`. When True, skip
   the reconcile call and its commit, set status `already_recorded`, and log one line saying so.
6. `resolve_execution_verdict(repo_dir, execution_branch) -> str | None` is a thin wrapper over the summary-row lookup
   confirmed in Step 1 and `calibration_outcome.is_converged_record`. It returns `success`, `failure` or None. Only the
   CLI uses it; the flow keeps deriving the verdict from `stage_results`.
7. `standalone_context(execution_branch, target_worktree, no_commit)` builds the minimal `FlowContext` the CLI passes
   in.
8. Type-annotate every function and give each public symbol a docstring. Keep the module under 200 lines. Import nothing
   from `entrypoint`.
