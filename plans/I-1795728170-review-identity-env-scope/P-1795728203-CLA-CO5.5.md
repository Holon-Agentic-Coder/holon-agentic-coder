The intent is correct and small: the identity overlay on `os.environ` for the whole run is the leak; scoping it to a
per-call `env=` copy for the single resolver commit is the minimal fix and matches the pattern already used by
`flow/review/ledger_commit.py` and `flow/review/conflict_merge.py` (`{**os.environ, **REVIEW_GIT_ENV}`). One plan, three
steps, no decomposition.

bottleneck is Step 2 (rewriting tests so they assert the new contract through the real seams, in particular the child
Python process and the hermetic commit via `_commit_resolution`). Entropy is the sum `0.8 + 1.8 + 0.6 = 3.2`. Cost is
the sum `3.0 + 4.5 + 1.5 = 9.0`. Impact is the plan-level impact (the resolver no longer halts before push on identity
assertions in pre-push tests), learning value is the max of the steps plus a little. Derivation:
`EV = 0.88 * 70.0 + 0.5 * 2.5 - 0.3 * 3.2 - 9.0 = 61.60 + 1.25 - 0.96 - 9.0 = 52.89`.

### Implementation Details (No code blocks, only logic/steps)

- In `flow/review/git_identity.py`:
  - Keep `REVIEW_GIT_ENV` unchanged (tests/flow/test_stage_conflicts.py and `flow/lazy_exports_review.py` depend on it).
  - Add public `review_git_env(environ: Mapping[str, str]) -> dict[str, str]` returning a new dict of `environ` overlaid
    with `REVIEW_GIT_ENV`; it never mutates its argument. Docstring states inputs, output, and that it has no side
    effects.
  - Remove `_apply_review_git_identity` and `_review_git_identity` and the now-unused `contextlib`, `Iterator` and
    `MutableMapping` imports.
  - Rewrite the module docstring: the identity reaches the review loop's own commits (ledger commits, conflict merges,
    resolver commit) only through a per-call environment copy, never through the process environment (which every child
    process, tests and tools included, would inherit) and never through git config.
- In `entrypoint/review_loop.py`:
  - Change the import at line ~54 to `review_git_env`.
  - Make `main()` call `_run_main()` directly (drop the `with` block) and rewrite its docstring to say the identity is
    applied only to the resolver commit. Keeping `_run_main` avoids touching its `noqa` header and keeps the diff small;
    folding it into `main()` is acceptable only if the `noqa` line stays identical.
  - In `_commit_resolution`, change the commit call to
    `run_cmd(commit_cmd, cwd=repo_dir, env=review_git_env(os.environ), check=False)`. Do not pass the identity to
    `git add`, `git reset --soft`, `git status`, verification, lint or test commands.
  - Update the module docstring bullet (lines 6-7) to: identity applied only to the resolver commit via a per-call
    environment copy of REVIEW_GIT_ENV; never in the process environment, never in git config.
- Run `grep -rn "_review_git_identity\|_apply_review_git_identity" apps/` and confirm the only remaining hits are in the
  test file that Step 2 rewrites.
