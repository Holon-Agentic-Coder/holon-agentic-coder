## Summary

Routes post-approval CI failures by class in Stage 4 and Stage 5. The new `flow/review/ci_failure_routing.py` classifies
a red pipeline fail-safe as `noise_timing`, `noise_infra`, `noise_cancelled` or `defect`. It keeps a rerun budget of one
per run id and head in `context.review_state["ci_routing"]` (checkpointed) and appends one `ci-failure-routing` ACT row
per decision.

- **Stage 4** (`flow/review/ci_noise_rerun.py`, a few lines in `loop.py`): noise after a clean review is rerun once
  inside the same iteration and CI is inspected again. No extra reviewer ensemble runs, and the diff approval stands. A
  defect, or noise still red, goes to the resolver with the CI finding as before; a repeated timing failure keeps
  `timing_gate_finding`.
- **Stage 5** (`flow/review/merged_head_routing.py`, `review_restart._decide`): noise is rerun once and the merged head
  polled again; only a fresh `passed` calibrates. A defect, or noise still red, restarts Stage 4 with `FIND-CI-000`
  carried, the diff approval kept and the delta-review anchor moved to the merged head, so the fix is reviewed scoped.
  The consensus is withdrawn only for a changed reviewable diff (or a diff gate that does not hold) or when the scoped
  review of the fix does not approve. Unsettled CI still fails closed, and the 3-restart cap is unchanged.
- The stop message names a noise class still red after its rerun, and `docs/review_consensus.md` documents the routing.

Two deviations from the plan, both caused by guards on files outside the touch set, are recorded under Steps 3 and 4:

- The new cross-module helpers use `_`-prefixed names, because `test_package_exports.py` would otherwise require edits
  to `flow/__init__.py`.
- `HOLON_CI_NOISE_RERUNS` was dropped for the constant `CI_NOISE_RERUNS = 1`, because the environment drift guard would
  otherwise require edits to `env_registry.py` and `config_env_keys.py`.

The changed paths, excluding `executions/`, are 20 files, all in the touch set. `module_budgets.json` and `uv.lock` are
unchanged, and no `# noqa` was added.

### Step 1: CI failure classifier and per-head rerun budget

- New `flow/review/ci_failure_routing.py` (197 lines): the four classes (`noise_timing`, `noise_infra`,
  `noise_cancelled`, `defect`), `FailedRun` with `failed_runs_from_status` (Stage 4 `gh pr checks` shape) and
  `failed_runs_from_record` (Stage 5 merged-head record), the fail-safe `classify_failure`, `resolve_ci_noise_reruns`
  (`HOLON_CI_NOISE_RERUNS`, default `1`, `0` disables, invalid keeps `1` with a warning), the budget in
  `context.review_state["ci_routing"]` (`reruns_spent`, `note_rerun`, `route_failure`), and `record_routing` (last
  decision, `PipelineGate.classification` on the same head, one `ACT-CIROUTE` ledger row through `record_review_action`,
  imported lazily). `apply_last_classification` re-applies the class after the gates are re-recorded.
- A mix of classes (including cancelled plus failed) is `defect`, as the plan's fail-safe rule says.
- New `tests/flow/review/test_ci_failure_routing.py`: classification table (12 cases), both normalisers, env parsing,
  budget per head and run id with a checkpoint round trip, and the ledger row.
- Later steps changed this module: the helpers became `_`-prefixed (Step 3), and the environment variable was replaced

### Step 2: Stage 4 in-iteration noise rerun

- `ci_inspection.CiInspectionInputs` gained two optional seams, `detail_lookup` and `rerun_failed`; `inspect_ci` is
  unchanged.
- New `flow/review/ci_noise_rerun.py`: `rerun_noise_once` returns the inspection unchanged unless the post-review gate
  is red with clean reviewers, settled checks, no local test failure, a head and no dry run. It classifies, routes,
  dispatches `rerun_failed` per run id (whole-run `rerun_run` for a cancelled run), counts the budget, waits until the
  rerun checks leave the failed set (bounded by the registration timeout, credited to the iteration timer) and inspects
  CI again. A defect or a failed dispatch records `resolve` and returns the red inspection.
- `loop.py` (936 to 938 lines, limit 952, no new `noqa`): binds `ci_inputs`, calls `rerun_noise_once` after
  `inspect_ci`, and re-applies the routing class after `record_iteration_gates` (`apply_last_classification`, red gate
  on the same head only).
- `ci_timing_finding.py` docstring: one noise rerun first, then the slowest-tests finding.
- Tests: new `tests/flow/review/test_ci_noise_rerun.py` (6 cases); three loop-level cases in `tests/test_review_loop.py`
  (green after one rerun with one ensemble dispatch and approval; still red goes to the resolver with the timing
  finding; a test-step failure is never rerun); the default seams in `tests/flow/review/test_ci_inspection.py`.
  `FakeGitHub` already records `rerun_failed`, so `tests/review_fakes.py` needed no change. The "next pass is scoped"

### Step 3: Stage 5 routing by class

- New `flow/review/merged_head_routing.py`: `_route_merged_head_failure` withdraws (unchanged comment, marker and row)
  only for a `withdrawal_reason` record (`CHANGED` coverage) or a diff gate that does not hold on the merged head.
  Otherwise noise under budget is rerun once (whole-run dispatcher), the head is polled again after the failed checks
  clear, and only a fresh `passed` returns None (with `PipelineGate(head, GREEN, source="merged_head")`); still red
  becomes a defect; unsettled fails closed (`_refuse_calibration`). A defect marks the pipeline red with its class,
  carries `FIND-CI-000` (`timing_gate_finding` for a repeated timing failure, else `ci_failure_finding`), resets the
  iteration counter, marks the consensus `approved: False` with `pipeline_defect` (not `withdrawn`), calls
  `delta_review._adopt_reviewed_head` and returns a SKIPPED Stage 5 with `review_restart` and `scoped_restart`.
  `_pending_scoped_restart` and `_resumed_restart` handle resume; `_withdraw_after_rejected_restart` withdraws when the
  scoped restart's Stage 4 does not approve.
- `merged_head_gate.py`: gained `_stage4_ci_record` (moved from `review_restart.py`), `_wait_for_rerun_start`, and the
  optional `detail_lookup` and `slowest_lookup` seams; docstring updated.
- `delta_review.py`: `_adopt_reviewed_head` moves `last_reviewed_head` and `anchor_head` to the merged head and resets
  the chain, keeping `last_critical`.
- `review_restart.py` (197 to 191 lines): `_decide` returns `(result, record)` and delegates `FAILED` to the router; the
  resume check and fail-closed refusal moved to the router; `approval_stands` also requires no pending scoped restart;
  the restart log names a scoped restart ("CI defect (<class>) on merged head ...; the diff approval stands") or a
  withdrawal; a rejected scoped restart withdraws. `review_restart.withdraw_consensus` stays bound and is passed to the
  router, because `tests/flow/review/test_sync_points.py` (not in the touch set) monkeypatches it.
- **Deviation (naming):** `tests/flow/test_package_exports.py` requires every public top-level function in `flow/` to be
  re-exported from `flow/__init__.py` (and `lazy_exports.py`). Both are outside this plan's touch set, so the new
  cross-module helpers use the repository's existing private-helper idiom (`_stage_failure`, `_ci_green`): for example
  `_classify_failure`, `_route_failure`, `_rerun_noise_once`, `_route_merged_head_failure`.
- Tests: new `tests/flow/review/test_merged_head_routing.py` (8 cases: green after one rerun without a withdrawal, still
  red restarts scoped with the timing finding, defect restarts scoped keeping the diff gate, changed diff withdraws,
  gate not holding withdraws, budget survives a checkpoint, unsettled re-poll fails closed, resumed pending restart);
  `tests/test_review_restart.py` (the red-CI carried-approval test now restarts scoped without a withdrawal; new resumed
