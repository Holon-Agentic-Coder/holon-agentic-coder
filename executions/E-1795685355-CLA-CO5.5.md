### Step 4: Stage-start templates for tests that do not assert on the stages they pass through (exploratory)

New module `tests/flow/stage_templates.py`:

- `AgentsSpec` is the frozen description of the fake containers and context that the skipped stages can see (dispatch or
  budget containers, the budget plans, `planner_records_decision`, intent extras). Options that only Stage 3 reads
  (`executor_mode`, `executor_decision`, `_execute` patches) are set by the test on its own fresh containers, so tests
  that differ only there share one template.
- `StageTemplates.start(tmp_path, monkeypatch, through, spec)` builds, once per test run and across xdist workers, the
  template named by `template_name("stage-start", through, spec)`: a copy of the flow template, then the real
  `run_intent_stage`, `run_plan_stage` and `run_execute_stage` up to `through`, inside a `pytest.MonkeyPatch.context()`
  that points `HOME` and `consult.DEFAULT_LEDGERS` at the template root. The build returns `ctx.to_dict()` (the
  context's own serialiser, as the checkpoint uses) and the budget planner's `planner_calls` and `clock_offset`.
- Per test: `copy_template`, the checkpoint files under `host/.holon` and the saved context re-pointed from the template
  root to the copy (the context's log lines named the template path, which a later checkpoint would have carried),
  `HOME` and the consult ledgers pointed at the copy, `target_worktree` at the copy's host, and fresh fake containers
  attached as the dispatcher.
- The flow conftest's function-scoped fixture `stage_start(through, spec, target=None)` is the only way to ask for one,
  so every build runs under the asking test's autouse guards (rule four of `tests/repo_templates.py`).

Equivalence check, `tests/flow/test_stage_templates.py` (stays in the suite as the helper's guard):

- `test_each_template_copy_equals_the_fresh_run_at_its_stage_and_runs_the_next_stage_alike` runs the real Stages 1 to 3
  once, snapshots after each, and compares each with a copy of the template that stops there: origin branches, host
  refs, host checkout and status, every file under `holon-knowledge/ledger` on every origin branch, and the context
  fields (all normalised for ids, times, shas and paths). From each copy it runs the next stage (Stage 2, Stage 3, or
  Stage 4 with its loop stubbed) and compares status, error, payload keys and dispatched roles with the fresh run's.
- `test_a_budget_plan_template_carries_the_decision_stage_3_reads` does the same for the budget containers' decomposed
  plan through Stage 2 and compares Stage 3's read of the plan row's decision.
- It is not vacuous: a template whose build added one intent field, and one whose checkpoint was not re-pointed, each
  made it fail (mutations tried by hand, not committed).
