## Steps Executed

### Step 1: Confirm the head-keyed couplings a ledger commit affects

- Head-keyed loop state: `resolved_target.head_sha` (reviewer dispatch, resolver `ResolverInput` handoff,
  `_push_resolver_head`'s "head did not move" check, `budget_push_refusal` base, `target_commit` approval stamp),
  `current_sha` and `prev_head_sha` (no-convergence streak) and `ci_wait` (reset only on `head_changed`).
- The resolver container takes `pre_resolver_head` from the worktree's own `HEAD`, so it already includes a ledger
  commit made before the pass. On the host, `_push_resolver_head` treats `head_sha == target.head_sha` as "no move";
  a stale `target.head_sha` would make an unchanged resolver report `pushed=True` after a ledger commit and reset the
  no-convergence streak. Advancing `resolved_target.head_sha` to the ledger commit (and carrying `prev_head_sha` forward
  when it equalled the old head) is therefore required.
- `probe_ci_checks` is keyed on the branch name. The CI wait (`settle_pending_ci`) runs only on the clean-review path,
  which ends the loop, so a ledger-only head costs at most one wait, at the final iteration, which the resolver's push
  would have cost anyway.
- Tests patch `loop.check_pr_mergeability`, `loop.probe_ci_checks`, `loop._resolve_review_commit`,
  `loop._resolve_reviewed_target`, `loop._wait_for_ci_registration`, `loop._warn_ledger_failure` and
  `loop._record_rejected_attempt`; `flow/__init__.py` re-exports `loop._loop_status`. None of these move.
- Decision: option (a), commit and push at every iteration boundary.

### Step 2: Add `flow/review/ledger_commit.py`

- New module owning "commit and push pending ledger rows": `LEDGER_RELS` (the three ledgers, executions path reused
  from `calibration.LEDGER_EXECUTIONS_REL`), `pending_ledger_paths`, `commit_ledger_rows` (pathspec commit with
  `REVIEW_GIT_ENV`, lazily imported), `ledger_commit_message` (built locally: `Action-Origin` and `Review-Iteration`
  trailers only, no `Co-authored-by`), `commit_pending_ledger_rows` (single never-raising entry point),
  `_push_ledger_commit` (fast-forward via `host_remote.push_commit`), `advance_past_ledger_commit` and
  `close_review_stage`.
- Additional guards beyond the plan: the commit only runs when the worktree path is the root of its git worktree (so a
  directory nested in another repository is never committed into it), and it is skipped inside a role container
  (`workspace_mounted()`), where the host owns commits and pushes. The result is a `LedgerCommit(sha, parent, pushed)`
  so callers can tell a local-only commit from a pushed one; the loop advances the reviewed head only when the commit's
  parent is that head.

### Step 5: Conflict gates commit pending rows first; the local branch follows a pushed merge

- `_gate_conflicting_head` commits and pushes pending rows (reason `before conflict merge`) before `_merge_and_push`,
  covering both `_approved_post_gate` and `_stage5_conflict_gate`. A commit that did not reach `origin` (push rejected,
  or `skip_push`) blocks the gate with `pending ledger rows could not be pushed` and merges nothing.
