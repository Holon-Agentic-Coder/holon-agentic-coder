### Implementation Details (No code blocks, only logic/steps)

1. Create `apps/sandbox-executor/tests/test_review_loop_git_identity.py` with a module docstring. Reuse
   `FakeGitCommands` and `_run_entrypoint` from `tests/test_review_loop.py` if importing them is clean (that module
   already re-exports helpers for other tests). Otherwise write a minimal recording fake with the same rule table.
2. Test A, no identity config write (criterion 1): run `main()` through `_run_entrypoint` (or an equivalent patch set)
   with a recording `run_cmd`. Fail if any recorded argv has `config` among its first verbs and contains `user.name`,
   `user.email` or a `user.` key in any scope (`--global`, `--local`, `--system`, `--worktree`, `--file` or none). Also
   add a static check, like `tests/test_entrypoint_git_identity.py`: the `review_loop.py` source has no string literal
   `"user.name"` or `"user.email"`.
3. Test B, environment holds the identity and is restored (criterion 2): use `monkeypatch.delenv(..., raising=False)`
   for the four keys first. Inside `with review_git_identity(os.environ):` assert that each of the four keys equals
   `REVIEW_GIT_ENV[key]`. After the block, assert that the keys are absent again. Add a variant that sets a pre-existing
   value through monkeypatch and checks it is restored. Add another that drives `main()` with a patched
   `run_review_loop` side effect that captures `{k: os.environ.get(k) for k in REVIEW_GIT_ENV}` during the loop. Assert
   the capture equals `REVIEW_GIT_ENV` and that `os.environ` no longer holds the keys after `SystemExit`. This shows
   that in-process callers do not leak.
4. Test C, hermetic commit authorship (criterion 3): in `tmp_path`, create an empty file `empty-gitconfig`.
   - Use monkeypatch to set `GIT_CONFIG_GLOBAL` to it, `GIT_CONFIG_NOSYSTEM=1` and `HOME=tmp_path/home`, and delete any
     `GIT_AUTHOR_*`, `GIT_COMMITTER_*`, `EMAIL` and `GIT_CONFIG_PARAMETERS`/`COUNT` vars. This overrides the conftest
     session config, which contains a `[user]` section.
   - Run `git init -q -b main` on `tmp_path/repo` and write a file.
   - Inside `review_git_identity(os.environ)`, commit through the entrypoint's own helpers,
     `review_loop.run_cmd(["git", "add", ...], cwd=repo)` and
     `review_loop.run_cmd(["git", "commit", "-q", "-m", ...], cwd=repo, check=True)`. These run with `env=None`, so they
     inherit the overlay just as the resolver commit does in production.
   - Read `git log -1 --format=%an%n%ae%n%cn%n%ce` and assert it equals the four `REVIEW_GIT_ENV` values in that order.
   - Add a negative control in the same test: outside the context, a commit attempt fails ("Please tell me who you are"
     or a non-zero exit). This proves the test environment really has no identity, so the overlay is what supplies it.
     Set `user.useConfigOnly=true` in the repo's local config for the control only if it is needed to stop git falling
     back to the hostname. Prefer that `user.useConfigOnly` comes from a `GIT_CONFIG_COUNT` env var scoped to the
     control call. If the control turns out to be flaky across git versions, drop it rather than weaken the main
     assertion.
5. Test D, local config unchanged (criterion 3, second test): after the same commit flow, run
   `git config --local --get-regexp ^user\.` in the tmp repo and assert exit code 1 with empty output. Also assert that
   the empty global file is still empty, so nothing was written to "global" either.
6. In `tests/test_review_loop.py`, search for any assertion on the old `config --global user.*` argv and update it to
   the new contract. Expect few or none, because the fake answers `config` with success and nothing asserts on it. Make
   no other changes to that file.
7. Use only `monkeypatch`, `tmp_path` and `patch` context managers, so nothing persists after a test.
