## Plan Description & Strategy

Findings from reading the code (base `ea3936e8`):

- `agent_attribution.attribution_off_settings` merges `ATTRIBUTION_OFF` and the code-mode default env into the given
  settings, then returns `json.dumps(merged)` inline unless the input was a file path, in which case it returns
  `_private_temp_file(text)` (mkstemp, so mode 600, atexit removal, cached per text in `_TEMP_FILES`).
- `ClaudeAgentRunner.build_cmd` (agent_runner.py ~L682-697) calls it and writes the value after `--settings`, so inline
  JSON carrying a token ends up on argv. Since code mode is on by default, the merged settings almost always carry an
  env block.
- Second leak path, the one the resolver actually uses: `entrypoint/conflict_resolver.run_agent_turn` and
  `entrypoint/review_loop._run_resolver_agent` call `runner.build_command(prompt, model)`, which in `AgentRunner`
  delegates to `compose_cmd`, and `StandardAgentRunner._append_env_mappings` appends
  `--settings <raw HOLON_AGENT_SETTINGS>` straight from the environment via
  `EnvMapping("HOLON_AGENT_SETTINGS", "--settings")`. Fixing only `build_cmd` would leave the observed resolver leak in
  place.
- `compose_cmd` must keep emitting the raw value: `preflight._probe_command` (host side, out of scope) passes
  `compose_cmd` output to `_reference_secret_args`, which rewrites the raw value to `"${HOLON_AGENT_SETTINGS}"` inside a
  `sh -c` for the probe container; a host temp-file path would not exist in the container. `tests/test_preflight.py`
  L176-277 pins this.
- `test_real_registered_runners_build_command_contract` asserts `build_command == compose_cmd` for every runner with no
  settings set, so the claude `build_command` override must be a no-op when `HOLON_AGENT_SETTINGS` is unset.
- Module budgets: `agent_runner.py` is 782 lines with a frozen override of 782 (zero headroom); `agent_attribution.py`
  is 82 lines under the 400 default. Test modules are not budgeted. Therefore the argv placement logic moves into
  `agent_attribution.py` and `agent_runner.py` must end at 782 lines or fewer.
- No "echo padding" entry exists in the Python sources; the settings content is serialised from the merged dict without
  any rewriting, so whatever padding entry the input carries is preserved as is. The plan does not add, strip or reorder
  keys.

Strategy: (1) make `attribution_off_settings` write a private file whenever the merged settings carry a non-empty `env`
dict (inline or file input), keeping inline output only for env-free settings; add a small placement helper there. (2)
Rewire `ClaudeAgentRunner` so both `build_cmd` and a new `build_command` override route through that helper, the latter
only when `HOLON_AGENT_SETTINGS` is set, without growing `agent_runner.py`. (3) Update the inline-form assertions and
add the token-off-argv tests. (4) Run touched tests, the full suite once, lint and lint-docs in the foreground.

### Strategy Rationale

The intent is accepted with one narrow reframe. Reading the call sites showed the resolver (and review-loop resolver)
builds its argv through `build_command -> compose_cmd`, which appends the raw `HOLON_AGENT_SETTINGS` and never calls
`attribution_off_settings`. Fixing only `build_cmd` would leave the observed leak. The reframe stays within the four
scoped files, and it deliberately leaves `compose_cmd` raw because the host pre-flight probe depends on that form.

Overall metrics: entropy is the sum of step entropies, `1.2 + 1.5 + 1.0 + 0.3 = 4.0`. Cost is the sum,
`2.5 + 3.0 + 3.0 + 1.5 = 10.0`. p_success is set by the bottleneck Step 2 (0.88), because the steps are strongly
correlated (the same small change) rather than independent; a plain product (about 0.69) would understate it. Impact 80
is a qualitative judgement for removing a long-lived credential from every in-container claude argv. Learning value 3.0
is about the sum of step learning values.
`EV = 0.88 * 80.0 + 0.5 * 3.0 - 0.3 * 4.0 - 10.0 = 70.40 + 1.50 - 1.20 - 10.0 = 60.70`.

Assumptions: mkstemp yields mode 600 on Linux containers (POSIX guarantee); `/tmp` inside the agent container is private
to the container user; claude accepts a file path for `--settings` (already relied on for file input).
