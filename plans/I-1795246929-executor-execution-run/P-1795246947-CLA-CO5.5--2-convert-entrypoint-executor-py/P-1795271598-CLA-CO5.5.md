**Patch seam.** Tests patch collaborators by name on `sandbox_executor.entrypoint.executor`, for example
`patch("sandbox_executor.entrypoint.executor.run_cmd")` and `monkeypatch.setattr(executor, "get_runner", ...)`. Once the
code lives in a submodule, a `from x import y` binding would ignore those patches. Every submodule therefore imports the
package itself (`import sandbox_executor.entrypoint.executor as executor_facade`) and looks these names up at call time
(`executor_facade.run_cmd(...)`). The seam set, measured on `main` at planning time, is: `run_cmd`, `get_runner`,
`validate_mounted_workspace`, `get_workspace_dir`, `workspace_mounted`, `sync_and_reconcile_pre_push`, `run_turn`,
`prepare_agent_output_block`, `measure_executor_tests`, `converge_prettier`, `_get_local_safe_directories`,
`record_budget_failure`, `atomic_ledger_append`, `append_action_record`, `supervise_authoring_turn` and
`SANDBOX_WORKSPACE_MOUNT` (if it is referenced). Step 2 re-derives this set from the tests rather than trusting it.

The package `__init__` imports `run.py` and the other submodules _after_ it defines the constants and imports the
collaborators. A submodule's `import ... as executor_facade` during that partial initialisation resolves from
`sys.modules` (supported since Python 3.7), and attributes are only read at call time, so there is no circular-import
failure.
