### Strategy Rationale

The intent is four independent fixes (A to D) on the review and execution reporting path, scoped well enough to execute
as one plan. The steps sum to `entropy = 1.4 + 1.3 + 2.2 + 2.4 + 1.8 + 3.0 + 0.8 + 0.6 = 13.5`, which is under the 15.0
budget, so there is no sub-intent list. Splitting it would add four pipeline rounds (plan, execute, review, calibrate)
for changes that are each smaller than one round's overhead.

One clause of B is reframed. "Ledger-only conflicts interleaved by created_at" is read as ordering only the appended
head-only rows by `created_at`, while the target branch's rows stay a byte prefix. A full interleave would move
historical rows on the target branch, which the append-only ledger constraint (constraints.md section 3) and the
existing `assert_ledger_prefix` check forbid. The reframe keeps the intent's purpose (a fast, test-free, chronologically
readable ledger merge) and drops only the unsafe part.

Ordering puts A, C and D first because they are self-contained. B's gate (Step 6) is the bottleneck: it needs
line-neutral wiring in `flow/stages/calibrate.py`, which sits exactly at its frozen 349-line budget. Its new logic is
isolated in the new module `flow/review/conflict_gate.py`. The approved-post call goes into `flow/review/posting.py`,
which has 45 lines of headroom, so `flow/review/loop.py` (952/952) and `flow/stages/review.py` (305/305) need no new
lines.

Aggregation:

- **p_success:** the naive product of the step probabilities is about 0.32. That is too pessimistic, because each step's
  failure is caught by its own targeted test run and fixed in place: there is no external dependency and no irreversible
  action. So the overall figure is anchored on the bottleneck (Step 6, 0.74) with a small discount for the zero-headroom
  budgets elsewhere (Step 4). Result: 0.72.
- **impact:** the step impacts (98 in total) are normalised to the intent's value. The secret-leak closure (D) and never
  approving a conflicting head (B) dominate, which gives 72.
- **cost:** the sum of the step costs, 22.5.
- **learning value:** about 4. The step values sum to 4.3, and the main learning is how far the frozen budgets constrain
  small fixes.
- `EV = P(success) * Impact + mu * LearningValue - lambda * Delta_S - Cost = 0.72 * 72 + 0.5 * 4 - 0.3 * 13.5 - 22.5 = 51.84 + 2.0 - 4.05 - 22.5 = 27.29`.

Strong assumptions:

- `redact_agent_secrets` is the canonical, superset redactor. The survey confirmed it covers every class the intent
  lists except `HOLON_AGENT_SETTINGS`, which Step 3 adds.
- `run_calibrate_stage` is the single Stage 5 entry point. It is used by both `pipeline.py:195` and
  `calibrate_rerun.rerun_calibration` through `pipeline.py:158`.
