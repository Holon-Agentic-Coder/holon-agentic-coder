### Strategy Rationale

The macOS leg (median 7.0 min, up to 9.5 min) gates every pipeline wait. The cheapest lever that keeps every test
running is a deterministic file-level partition across two macOS runners. Evidence gathered while planning:

- `uv run pytest --collect-only -q -m "not integration_test and not stress"` collects 9,531 tests in 345 files (19 s
  locally). A sha256-of-path mod 2 split gives 175 / 170 files (50.7 % / 49.3 %, inside the 40–60 % criterion) and 4,108
  / 5,423 tests (43 % / 57 %). Even if test time follows test count, the slower shard runs ~57 % of today's test time,
  plus setup and a ~20–30 s collection pass, so a shard should land around 4–4.5 min against 7.0 min.
- `scripts/ci_bookkeeping_chain.py` `match_job` returns `None` when two jobs match a job name and runner label, so two
  legs both named `unit (macos-latest, …)` and told `os: macos-latest` would make the bookkeeping gate and the main-push
  gate unable to find their previous run. Each shard therefore passes a unique leg label (`shard 1 of 2`,
  `shard 2 of 2`) that appears among its job name's values, and `match_job` keeps working unchanged.
- `scripts/ci_timing_gate.py` keys artefacts by `ci-timing-<workflow>-<job>-<os>`; passing `--job unit-shard-1` /
  `unit-shard-2` on macOS yields per-shard records and baselines with no script change, while the ubuntu leg keeps
  `--job unit` and its existing artefact history. New shard artefacts cold-start (ceiling-only check) for 5 main pushes,
  which the gate already handles (`::notice::Cold start`).
- `apps/sandbox-executor/tests/test_ci_bookkeeping_wiring.py` refuses a workflow with more than one job, and
  `test_macos_relevance_wiring.py` pins `os: [ubuntu-latest, macos-latest]`. Keeping one job with `os × shard` minus
  `ubuntu/shard 2`, plus include fields, keeps both constraints and keeps the ubuntu check name `unit (ubuntu-latest)`.
- pytest 9 reads arguments from a file given as `@path`, so the shard's file list reaches pytest with no shell word
  splitting and no `mapfile` (macOS bash 3.2 lacks it).

Aggregation: `p_success` is the product of the bottleneck steps' success probabilities (Step 3 workflow edit 0.88 and
Step 4 existing-test updates 0.92, both must pass; Steps 1, 2, 5 near 0.95 each), adjusted upward because failures are
cheap to repair in the review loop: `0.95 * 0.95 * 0.88 * 0.92 * 0.97 ≈ 0.71`, raised to 0.78 for in-loop repair.
Entropy is the sum of step entropies (`0.6 + 0.8 + 2.0 + 1.4 + 0.6 + 1.0 = 6.4`). Impact is set by Steps 3 and 6 (the
wall-clock reduction). Cost is the sum of step costs (`1.5 + 1.5 + 3.0 + 2.5 + 1.0 + 1.5 = 11.0`). Learning value is the
max-plus-half-rest judgement dominated by Step 6.
`EV = P(success) * Impact + mu * LearningValue - lambda * Delta_S_intent - Cost` with `mu = 0.5`, `lambda = 0.3`,
`Delta_S_intent = 6.4`: `EV = 0.78 * 72.0 + 0.5 * 4.5 - 0.3 * 6.4 - 11.0 = 56.16 + 2.25 - 1.92 - 11.0 = 45.49`, reported
as 45.5.

Strong assumptions: the GitHub account allows at least two concurrent macOS jobs (free plans allow 5); macOS minutes per
run rise by roughly one runner setup (~1 min), which is accepted against the wall-clock gain; branch protection is
updated by a maintainer when this merges.

### Intent & Git Integration

- **Step Intent:** Provide a stable, pure mapping from test file path and shard count to a shard index, and a CLI that
  prints one shard's files from a pytest collection.
- **Git branch:** I-1795741229-macos-unit-sharded/P-1795741321-CLA-CO5.5/E-{timestamp}-CLA-CO5.5/\_
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Create `scripts/unit_test_shard.py` with `#!/usr/bin/env python3`, `from __future__ import annotations`, imports
   `argparse`, `hashlib`, `sys`, `collections.abc.Iterable/Sequence`. Stdlib only, so CI can run it with `python3`
   before or after `uv sync`.
2. `shard_of(path: str, shards: int) -> int`: normalise the path to POSIX form and strip a leading `./`, take
   `hashlib.sha256(path.encode("utf-8")).digest()[:8]` as a big-endian integer, return `value % shards + 1`. Raise
   `ValueError` for `shards < 1`. Add a `# why:` comment that the built-in `hash()` is salted per process, so it cannot
   give every runner the same split.
3. `test_files_from_collection(lines: Iterable[str]) -> list[str]`: keep lines containing `::` whose part before the
   first `::` ends with `.py`; return the sorted unique file parts. Lines such as
   `9531/9552 tests collected (21 deselected) in 19.01s`, blank lines and warning summaries are ignored.
4. `files_in_shard(files: Sequence[str], shard: int, shards: int) -> list[str]`: return the files whose `shard_of`
   equals `shard`, in input order; raise `ValueError` when `shard` is outside `1..shards`.
5. `main(argv: Sequence[str] | None = None, stdin = sys.stdin, stdout = sys.stdout) -> int`: argparse with required
   integer `--shard` and `--shards`; read stdin; exit code 2 with a message on stderr when the collection holds no test
   file or the chosen shard is empty or out of range; otherwise print one file per line and return 0. Guard with
   `if __name__ == "__main__": raise SystemExit(main())`.
6. No docstrings and no comments other than `# why:`. Names carry the meaning. Keep every function far below the ruff
   complexity limits.
