# Execution Record: E-1795697352-CLA-CO5.5

## Summary

Implements plan `P-1795697035-CLA-CO5.5`. A Stage 3 resume now adopts the plan's newest execution branch when it has
real commits past the plan tip and no `executions.jsonl` summary row. Uncommitted tracked leftovers, the branch's own
notes file included, are committed first as labelled partial work. A superseding `failure` row then records the tip as
`partial_head`, and the unchanged `_resumable_partial_branch` and executor continuation prompt pick it up. The snapshot
is refreshed so the executor's next branch is the only new one, the checkpoint's execution branch follows the adopted
branch, and a dirty worktree that would still block the checkout fails with the file names. `execute.py` is unchanged.

Deviation: the new detection helpers and `_has_summary_row` are `_`-prefixed. `tests/flow/test_package_exports.py`
requires every public definition in `flow/` to be re-exported from `flow/__init__.py`, which is outside the intent's
scope. The repository already shares `_`-prefixed helpers across flow modules (`git_refs`), so this follows that idiom.

### Step 2: Detection module

- Added `flow/unrecorded_branch_adoption.py` (160 lines): `find_unrecorded_branch` considers only the newest execution
  branch of the plan (the origin snapshot plus local-only branches). It requires no summary row on the origin or local
  ref, at least one commit past the plan tip and a non-empty `changed_paths` diff. Local and origin that have diverged
  are logged and left alone.
- `resume_start`, `checkout_blocking_paths` and `blocking_checkout_error` name the tracked dirty files that would block
  the executor's checkout. The start used is the newest recorded partial head, else the plan tip. Using the real start
  instead of always the plan tip avoids false failures on a resume from a partial head.
- Added `has_summary_row` to `flow/partial_head.py`.

### Step 3: Wire adoption into `salvage_for_resume`

- `salvage_leftovers` gained a keyword-only `include_notes` (default off, behaviour unchanged). When it is on, the
  branch's own notes file is committed with the leftovers and the row carries `adopted_unrecorded: true`.
- `_salvage_row` takes an `extras` mapping. `_publish_partial` takes a row builder and skips the push when origin
  already holds every local commit, so an origin-only branch only gets its superseding row appended.
- `salvage_for_resume` detects, salvages, adopts (a `failure` row with `partial_head` set to the tip), sets
  `context.execution_branch`, refreshes the snapshot and finally reports blocking files by name.
- `execute.py` is unchanged (430 lines). `partial_salvage.py` is now 303 lines.
- 363 tests across `tests/flow/stages/` and the salvage tests passed unchanged.
