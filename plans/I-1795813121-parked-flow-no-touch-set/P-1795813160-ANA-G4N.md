### Strategy Rationale

The intent is accepted as-is because it directly resolves a high-impact operational bottleneck (chain-blocking and
wasted slot capacity caused by parked flows holding planned touch sets) within a small, well-isolated set of modules.

The core insight from inspecting `apps/sandbox-executor/src/sandbox_executor/flow/` is that `holon flow` already tracks
every live runner process via `<git-common-dir>/holon-flow-run-<slug>.lock` (`flow/run_lock.py` and
`flow/run_lock_record.py`): a live runner holds an exclusive `fcntl.flock` on its run lock file and writes a
`RunLockHolder` JSON payload containing `pid`, `host`, and `worktree`. On clean exit, `release_flow_run_lock()`
truncates the file and releases the lock; on crash, the kernel releases the flock (and if a forked child inherited the
file descriptor, `RunLockHolder.is_dead_here()` detects the dead PID on the local host).

By adding a non-blocking `fcntl.flock(LOCK_SH | LOCK_NB)` liveness probe (`live_runner_worktrees`) in
`admission_lock.py` and filtering local `InFlightFlow` and `BlockedWaiter` entries in `admission_decision.py` against
the set of live runner worktrees:

1. **Open PRs always block:** flows with `flow.number is not None` (`BLOCKED_BY_PULL_REQUEST`) are never filtered out.
2. **Parked flows release their touch sets:** any local flow (`admitted`, `blocked`, or legacy `admission=None`) without
   a live runner holding its flow run lock is excluded from both `flows` and `waiters`, so an overlapping candidate is
   admitted (and when no open PRs or live runners exist, the base branch is not even listed).
3. **Concurrent resumes of parked flows preserve original admission order:** when two parked flows resume at once, both
   hold live flow run locks while contending for `holon-admission.lock`. Regardless of which process acquires
   `holon-admission.lock` first, `older_waiter_flows` ensures the older flow claims the touch set and the newer flow
   refuses with a named `local_flow` blocker pointing to the live older flow.
4. **External compatibility is preserved:** `admitted_record().to_dict()` keeps its exact schema
   (`{"state": "admitted"}` plus optional refresh/override fields), keeping out-of-scope tests (`test_plan_refresh.py`,
   `test_checkpoint.py`, `test_in_flight.py`, `test_package_exports.py`) green without touching files outside the
   allowed scope.

2. Add a small private helper `_read_lock_text(descriptor: int) -> str` that reads up to 4096-byte chunks from the start

3. Add a small private helper `_live_holder_worktree(path: str) -> str | None`:
   - Open `path` with `os.open(path, os.O_RDONLY)`; return `None` on `OSError` (e.g. lock unlinked concurrently).
   - In a `try`/`finally` that always closes `descriptor`, attempt
     `fcntl.flock(descriptor, fcntl.LOCK_SH | fcntl.LOCK_NB)`.
   - If `flock` succeeds, immediately release `fcntl.flock(descriptor, fcntl.LOCK_UN)` and return `None` (no runner
     holds the exclusive lock).
   - If `flock` raises `BlockingIOError`, parse `RunLockHolder.from_text(_read_lock_text(descriptor))`. If
     `holder is None` or `holder.is_dead_here()`, return `None`; otherwise return `os.path.realpath(holder.worktree)`.
4. Add `live_runner_worktrees(repo_dir: str, run_git: GitRunner | None = None) -> frozenset[str]`:
   - Derive `common_dir = os.path.dirname(admission_lock_path(repo_dir, run_git))` so the injected `run_git` is honored
     and git failures raise `AdmissionLockError`.
   - Glob `os.path.join(common_dir, f"{RUN_LOCK_PREFIX}*.lock")` (which excludes `*.takeover` files) and return
     `frozenset` of non-`None` results from `_live_holder_worktree(path)`.
5. Keep code self-explaining: no docstrings, only concise `# why:` comments where non-obvious (e.g. why
   `LOCK_SH | LOCK_NB` probes an exclusive lock without mutating files, and why `is_dead_here()` handles inherited fds).
