## Plan Description & Strategy

Stage 3 admission currently treats local plan branches and worktree checkpoints as sufficient evidence that another flow
is in flight, and never prunes remote-tracking refs before checking. As a result, a merged flow whose remote branch was
deleted continues to block unrelated flows until local state is cleaned up, and overlap refusals omit where each blocker
ref was found and its PR state.

This plan fixes admission in five focused steps:

1. Add `flow/in_flight_liveness.py` to own `git fetch --prune origin`, origin-only `I-*` ref verification
   (`refs/remotes/origin/...`), live runner process detection against a worktree path, and PR closed/merged state
   lookup; extend `WorktreeCheckpoint` with `execution_branch` and register the new module in `flow/lazy_exports.py`.
2. Update `flow/in_flight.py` so open PRs only count when their PR state is `OPEN` and their `I-*` head exists on
   `origin`, and worktree checkpoints only count as in flight when their `I-*` branch exists on `origin`, a live runner
   process holds their worktree, and their PR is not merged or closed; attach blocker provenance (`ref_name`,
   `ref_source`, `pr_state`) to `InFlightFlow`.
3. Update `flow/admission_decision.py` and `flow/admission.py` to run `git fetch --prune origin` fail-closed at the
   start of every Stage 3 admission check and include each blocker's ref name, local-vs-remote source, and PR
   number/state in refusal messages and logs without altering touch-set comparison in `touch_set_overlap.py`.
4. Add `tests/flow/test_admission_remote_in_flight.py` covering all required hermetic scenarios and align the four
   existing admission test files with remote-backed `I-*` refs, liveness seams, and provenance assertions.
5. Run the affected tests, the full unit test suite once, and both lint tasks in the foreground while verifying
   `holon-config/hygiene/module_budgets.json` and `touch_set_overlap.py` remain unchanged.
