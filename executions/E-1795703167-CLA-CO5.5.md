# Execution Record: E-1795703167-CLA-CO5.5

## Summary

Implements plan `P-1795702946-CLA-CO5.5`: a read-only `holon intent-check <intent.json>` command that reports missing
scope paths, proposed companion files and acceptance-criteria warnings. It is three new source modules
(`intent_scope_graph.py` 176 lines, `intent_scope_check.py` 194 lines, `cli/commands/intent_check.py` 40 lines) and two
new test modules (197 and 115 lines). No existing module changed: `discover()` picks up the command, and `ORDER = 11`
places it right after `intent`. Exit codes: `0` with no proposals, `1` with proposals, `2` for an unreadable intent
file.

Design decisions and deviations:

- Scope entries marked new use a trailing ` (new)` or a leading `new:` (case-insensitive). The marker is stripped before
  every check.
- The plan's `test_importers` helper is named `importing_tests`. A source function named `test_*` would be collected as
  a test by pytest wherever a test module imports it.
- `imported_sources` drops a package when a module under it also resolved, so `from pkg import core` proposes
  `pkg/core.py` and not also `pkg/__init__.py`.
- Test modules are capped at 200 lines like the source modules, because acceptance criterion 6 says "every new module".
  The plan only asked for 400.
- In this container, `uv run holon` resolves a pre-installed copy of `sandbox_executor` at `/home/holon/src` ahead of
  the workspace. The smoke run therefore used `PYTHONPATH=apps/sandbox-executor/src`. Pytest uses the workspace source
  through its `pythonpath` setting.

## Steps Executed

### Step 1: Confirm the reuse points

- `cli/commands/__init__.py::discover` imports every non-`_` module exposing `register` and `run`, sorted by `ORDER`.
- `cli.main.main` calls `args._run(args)` and `sys.exit(ret)` for a non-`None` return, so `run` returns its exit code
  and tests wrap `cli.main` in `pytest.raises(SystemExit)` as `test_models_cli.py` does.
- `git.run_git(args, cwd, check)` runs `git` without a shell and captures output; `git.is_metadata_path` covers
  bookkeeping prefixes.
- `tests/conftest.py` sets a session-wide hermetic git config; the `Popen` guards block only network and `gh` writes, so
  local `git init`, `add`, `commit` and `log` in `tmp_path` are allowed.
- Ruff also selects `PLR0911` (return count), so helpers keep return statements few.

### Step 2: `intent_scope_graph.py`

- Added `module_name`, `is_test_path`, `python_files` (`git ls-files -z -- *.py`), `build_module_index`,
  `imported_modules` (`ast`, relative imports resolved by level), `importing_tests`, `imported_sources`,
  `reexporting_init` and `co_changed`. `co_changed` runs
  `git -c core.quotePath=false log -n 200 --no-merges --no-renames --name-only --format=%x1e` with `check=False`, so an
  empty repository simply has no history. 176 lines, ruff clean.

### Step 3: `intent_scope_check.py`

- Added `ScopeEntry`, `DraftIntent`, `Proposal`, `IntentScopeReport` (`has_proposals`), `load_intent`,
  `check_intent_scope`, `render_text` and `to_json`. Proposals are de-duplicated with the first reason kept (import
  reasons come before co-change reasons), in-scope paths are dropped, and the result is sorted by path. Warnings match
  the path, file name, stem or dotted module name on word boundaries. Absolute paths count as missing. 194 lines.

### Step 4: `cli/commands/intent_check.py`

- `ORDER = 11`, positional `intent_file`, shared `--target-worktree`, `--json`. `run` returns the exit code, and
  `cli.main` passes it to `sys.exit`. 40 lines.

### Step 5: rule tests

- `tests/test_intent_scope_check.py`: hermetic `tmp_path` repositories, with one commit per layout file so the setup
  adds no co-change pairs. Covers each proposal kind, the 3-commit threshold (2 commits do not propose), `plans/`
  partners, an empty repository, missing and new-marked paths, warnings and how naming a file clears them, merge
  ordering, `load_intent` errors and rendering.
- Two test-fixture bugs found on the first run and fixed in the tests: the single initial commit counted as a co-change,
  and the co-change helper overwrote the test file's import.

### Step 6: CLI tests

- `tests/cli/test_intent_check_cli.py`: discovery order and an unchanged `intent` parser, exit codes `0`, `1` and `2`,
  the exact JSON keys, and the read-only check. The read-only check covers index bytes and `st_mtime_ns`,
  `git status --porcelain --untracked-files=all` with `GIT_OPTIONAL_LOCKS=0`, `HEAD`, and the `.git/refs` listing,
  captured around a text run and a `--json` run on a dirty worktree.

### Step 7: validation

- Line counts: 176, 194 and 40 for the source modules; 197 and 115 for the tests.
  `git diff --exit-code main -- holon-config/hygiene/module_budgets.json` is clean. `git diff --name-only main` lists
  only the five touch-set files plus `executions/`, `plans/` and `holon-knowledge/` bookkeeping.
- Smoke run on this repository with this intent's scope and acceptance criteria (copied to `/tmp/smoke/intent.json`)
  exited `1` in about 1.4s. Its output:
  - Missing: none.
  - Proposed: `apps/sandbox-executor/src/sandbox_executor/cli/commands/__init__.py`, because the CLI test imports
    `discover`. This is a false positive: the test reads that module and does not need it changed.
  - Warnings: all five files, since the criteria describe the files only by role ("a new command module under
    cli/commands") and never by name.
  - `git status --porcelain` was empty afterwards.
- Learning: a test's import of an unchanged helper module is the main source of false positives, and the name-based
  warning fires on criteria that describe files by role.
