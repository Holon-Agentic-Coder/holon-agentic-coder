### Strategy Rationale

The intent is accepted as-is because consolidating per-runner mount rules, defaults, harness markers, auth/session
detection metadata, and model-discovery hooks onto `RunnerSpec` eliminates cross-file duplication across
`agent_defaults.py` and `launcher/*mounts*.py` while keeping all public APIs intact.

Two architectural constraints shape the implementation:

1. **Import-cycle ratchet (`test_import_cycle_ratchet.py`)**: `agent_defaults`, `runners`, `local_llm`, and
   `claude_credential` already form a strongly connected component with fixed edge-count caps
   (`("runners", "local_llm"): 3`, `("runners", "claude_credential"): 1`, `("agent_defaults", "runners"): 1`,
   `("agent_defaults", "claude_credential"): 1`). The plan preserves all caps: `runners/pi.py` reuses its existing
   `local_llm` import for `_session_mounts`, `runners/claude.py` imports `resolve_claude_credential` on its existing
   `from sandbox_executor.claude_credential import ...` line, `agent_defaults.py` imports all runner symbols on a single
   `from sandbox_executor.runners import (...)` statement and drops its direct `claude_credential` import (reducing that
   cycle edge from `1` to `0`), and `launcher/` imports `runners/` unidirectionally (acyclic because `runners/` never
   imports `launcher`, `preflight`, or `config_env`).
2. **Self-explaining code & module line budgets**: `scripts/check_self_explaining.py` and `test_self_doc_modules.py`
   enforce zero docstrings and zero non-`# why:` comments on all touched modules (superseding the legacy docstring rule
   in `holon-config/world/ruleset.md`), and `holon-config/hygiene/module_budgets.json` stays untouched while
   `agent_defaults.py` and `launcher/mounts.py` shrink well below their limits.
