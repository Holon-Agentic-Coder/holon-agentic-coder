### Strategy Rationale

The planner bisected the problem and found the root cause, which is a pytest 9.1 collection behaviour and not a module
that shadows a package:

- pytest 9.1.1 (installed) no longer parses a `conftest.py` when the plugin is registered. `FixtureManager` keeps it in
  `_pending_conftests` and parses it in its `pytest_make_collect_report` wrapper, with `node=` the first `Directory` or
  `Package` collector for that path. After that the entry is popped.
- `FixtureManager._matchfactories` matches a conftest fixture by node identity:
  `fixturedef.node in node.iter_parents()`. Autouse names are kept per node object (`_node_autousenames`).
- `Session.collect` skips its collection cache (`handle_dupes = False`) when the only remaining part is a file path. The
  comment there says "files given directly multiple times on the command line should not be deduplicated". So when a
  later argument is a file that sits directly in a directory already collected for an earlier argument, that directory
  is collected again. This creates new `Package` objects for its sub-directories.
- Those duplicate `Package` nodes never get the conftest fixtures, because the pending entry was already popped. Every
  test under a duplicate node therefore loses:
  - the conftest's named fixtures, which gives "fixture not found"
  - the conftest's autouse fixtures, which explains the 5 plain failures in `test_conflict_gate.py` and
    `test_pipeline.py` (fake reviewers and the npx and gh guards are missing).

Minimal reproductions confirmed during planning:

- **no_origin_reconcile:** `stages/test_children.py flow/test_git_refs.py stages/test_replan_request.py` gives 8 errors.
  `--collect-only` shows two `<Package stages>` nodes under `<Package flow>`.
- **flow_repos:** `flow/stages/test_children.py tests/test_naming.py flow/test_git_refs.py` gives 10 errors. Adding
  `flow/review/test_conflict_gate.py` adds 3 failures from the missing autouse fixtures. Here the duplicated node is
  `tests`, collected again for `test_naming.py`, so `flow` is a new object.
- **Cheap detection:** `--setup-plan` reports the same "fixture ... not found" errors without running any test body (10
  and 8 matches). That makes a fast subprocess regression test possible.
- **Prototype fix:** an out-of-tree `-p` plugin. It is a `pytest_make_collect_report` wrapper with `tryfirst=True`, so
  it is the outermost wrapper and runs after the fixture manager has popped the pending conftest. When a `Directory`
  collector is not the first one seen for its path, it parses that directory's registered conftest
  (`pluginmanager.get_plugin(str(path / "conftest.py"))`) onto the duplicate node. With it, both lists pass: 44 passed,
  and 133 passed serially and with `-n 2`.

The fix makes fixture visibility independent of argument order, which is what the intent asks for, and it lives in a
single in-scope file. Other options were rejected:

- Moving the flow fixtures up to `tests/conftest.py` would apply flow-only autouse fakes to the whole suite, which
  changes behaviour.
- Sorting `config.args` changes the run order and only hides the problem.
- Pinning pytest is outside the scope list.

The bottleneck is Step 3 (the hook). It uses private pytest API (`session._fixturemanager.parsefactories`), and an
interaction with the full suite under xdist is possible. Overall metrics:

- p_success is the product of the per-step success rates, rounded up a little because the prototype already passed:

### Implementation Details (No code blocks, only logic/steps)

1. In `apps/sandbox-executor/tests/conftest.py`, add a module-level `pytest.StashKey` holding a dict from directory
   `Path` to the first collector node seen for it.
2. Add a hook `pytest_make_collect_report(collector)` decorated with `pytest.hookimpl(wrapper=True, tryfirst=True)`.
   `tryfirst` makes it the outermost wrapper, so its post-yield code runs after the fixture manager's own wrapper has
   popped and parsed the pending conftest for the first node. The hook:
   - yields to get the report
   - does nothing more unless the collector is a `pytest.Directory`
   - looks up the per-session map in `collector.config.stash`, with `setdefault` on first use
   - records the collector if this is the first node for `collector.path`
   - otherwise gets the registered conftest plugin with
     `collector.config.pluginmanager.get_plugin(str(collector.path / "conftest.py"))`, and if it exists, calls
     `collector.session._fixturemanager.parsefactories(holder=plugin, node=collector)`
   - returns the report
3. Docstring, 3 to 5 lines, in the file's existing style:
   - pytest 9.1 binds a conftest's fixtures to the first collector of its directory
   - a later file argument in an already-collected directory makes pytest collect that directory again (`handle_dupes`),
     which creates new nodes
   - the hook gives those nodes the same fixtures, so any file selection and order sees what the full run sees
   - name the regression test module
4. Keep it before or next to the existing `pytest_configure`. Stay within the complexity limits, using a guard clause or
   a small helper if needed.
5. Leave `tests/flow/conftest.py` and `tests/flow/stages/conftest.py` unchanged. If a reviewer asks for a pointer, add
   at most a one-line docstring note there. Both files are in scope.
6. Run the Step 2 test again. Both cases must now pass. Also run both lists normally, without `--setup-plan`, with
   `-p no:xdist` and with `-n 6`. Expect 44 passed and 52 passed.
