### Implementation Details (No code blocks, only logic/steps)

2. Extract the body of one attempt into a helper (for example `_rerun_timing_once(check, record, run_ids)`) that:
   dispatches every run id through `seams.rerun_dispatcher` or `_dispatch_rerun` (the adapter's `rerun_failed`, which
   reruns only the failed jobs); returns None when any dispatch fails; otherwise waits with the existing
   `_wait_for_rerun_start` and returns the `(record, ci_status)` pair from `_classify_settled(check)`.
3. Rewrite `_retry_timing_noise` as a loop over attempts 1 to `MAX_TIMING_RERUNS` holding the current
   `(record, ci_status)`:
   - Before each attempt call `_eligible_run_ids(check, current_record, current_status)`. This re-applies all guards
     (still a timing-gate-only failure, no pending checks, approved head known, measured head resolvable, change set
     bookkeeping-only or empty, run ids parseable). If it returns None, stop.
   - Log one line per attempt, for example "Final-head CI: rerunning timing-gate failure on unchanged code (attempt N of
     3): <run ids>". Replace the current "bookkeeping-only head" wording.
   - If dispatch fails on attempt 1, return the original record with
     `timing_rerun = {"attempted": False, "reason": "the rerun could not be dispatched"}` exactly as today (no
     re-probe). If dispatch fails on a later attempt, stop and keep the last classified record, adding the same `reason`
     string to the `timing_rerun` record.
   - Append the classified state to an `outcomes` list. Stop when the state is not `failed` (`success` ends green;
     `unknown`, for example pending at budget, is never retried). A `failed` state continues only if the next
     eligibility check passes, so a mixed failure stops the loop.
4. When at least one attempt ran, return the last classified record merged with
   `timing_rerun = {"attempted": True, "run_ids": <run ids of the first attempt>, "outcome": <last state>, "attempts": <len(outcomes)>, "outcomes": <outcomes>}`.
   After three failures the record is the last failed record (same `state`, `failed_checks`, `failed_details` shape as
   the original), so the caller withdraws consensus only after the last attempt.
5. When no attempt is eligible, return the record unchanged with no `timing_rerun` key (today's behaviour).
6. Keep each function under the complexity limits (aim for C901 at most 6 per function; no more than 5 parameters; no
   `# noqa`). Add a short docstring to the new helper and to `_retry_timing_noise` stating the bound.
7. Check the module length with `wc -l`. If it exceeds 344, move the loop and the single-attempt helper into a new
   sibling module `flow/github/ci_timing_rerun.py` (importing `_FinalHeadCheck` types without a cycle, or passing the
