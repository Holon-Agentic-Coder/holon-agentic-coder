### Strategy Rationale

pull request's real changed files; the defect is that `flow/admission_decision.py::_conflict` also compares the pull

## Plan Description & Strategy

Semantics adopted (one definition used everywhere admission compares two sets):

- **Base files:** the set of repository paths on the flow's target branch (`intent_data.target_branch` or `main`),
  resolved with `_resolve_branch_ref` and listed with `git ls-tree -r --name-only -z <ref>`, metadata paths dropped.
- **Expansion of a declared entry:** a literal path expands to itself (whether or not it exists); a folder or glob entry
  expands to the base files it matches (`entry_matches`), never to a path absent on the base.
- **Declared against declared (local flow, older waiter):** the overlap is the intersection of the two expanded sets; so
  a new literal file overlaps only an identical literal, and folder/glob entries meet only on existing files.
- **Declared against a pull request:** the pull request's changed files are compared, never its declared set. A changed
  file present on the base overlaps when any own entry matches it; a changed file absent on the base (an added file)
  overlaps only an identical own literal entry.
- **Refusal:** lists the concrete files (sorted, de-duplicated), capped at 20 in the message with "and N more"; the
  payload `conflicts[].files` and `blocked_by[].files` carry the full concrete list.

The work stays in one execution: two new focused modules, three small edits in the admission path, one Stage 2 warning,
the docs paragraph, and the hermetic tests.
