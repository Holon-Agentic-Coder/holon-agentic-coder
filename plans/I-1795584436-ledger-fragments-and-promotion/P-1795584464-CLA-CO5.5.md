## Step 2: Route every ledger append to per-root-intent pending fragments

- **Sub‑intent recommendation:** STRONGLY_YES
- **Reasoning:** This is the bottleneck. It touches the write path of every stage, plus pathspec and exclude owners
  across entrypoints and flow, and carries the exploratory funnel design. A failure here must not leak into the
  promotion and workflow work.
- **Step Type:** IMPLEMENTATION
- **Exploration level:** BALANCED

- **Hypothesis being tested:** `atomic_ledger_append(filepath)` can keep its signature and every caller unchanged. It
  yields a buffered text handle; on exit it splits the buffer into lines, derives each row's fragment path, and appends
  under the fragment's `LedgerLock` with `assert_ledger_prefix`. The alternative, changing about 9 callers to a
  row-based API, would not be needed.
- **Learning target:** Whether any caller relies on side effects of writing to the canonical handle: reading the file
  back inside the `with` block, `f.tell()`, or partial writes. Also how many `git add`/exclude sites must learn the
  `pending/` path.
- **Maximum acceptable cost for this learning:** 3 cost units. If the buffered handle breaks more than two callers, fall
  back to an explicit `append_ledger_rows(canonical_path, rows)` API in `ledger/fragments.py` and convert the callers.
  That stays inside the step's discard budget.

### Intent & Git Integration

- **Step Intent:** No append through the ledger package writes a canonical ledger file. Two flows started from the same
  main produce branches that merge in either order without any conflict under `holon-knowledge/`.

### Implementation Details (No code blocks, only logic/steps)

1. In `ledger/lock.py`, `atomic_ledger_append` checks `fragments.ledger_name_of(filepath)`.

   - Ledger paths yield an `io.StringIO`. On a clean exit, the step groups the lines by
     `fragment_path(filepath, json.loads(line))`. Per group it takes the fragment's `LedgerLock`, records the prefix
     bytes, writes, flushes and calls `assert_ledger_prefix`. On an exception, nothing is written (same atomicity as
     today).
   - The routing helper lives in `ledger/fragments.py` or a new `ledger/fragment_write.py`, keeping `lock.py` near its
     current size. `lock.py` must not import `rows.py`, to avoid a cycle.
2. In `rows.py`:
   - Change the default factories for `created_at` on `ActionRecord` and `SummaryRecord` to `order.utc_now_z`.
   - In the funnel, normalise `created_at` on new rows. A `+00:00` or naive UTC value becomes the Z form, through
     `canonical_created_at`, applied in `append_action_record`, `try_append_ledger_line` and `append_summary_record`.
     Copies made by reconcile and promotion bypass this.
   - Point `append_summary_record`'s post-write `validate_ledger_file_unique_ids` at the merged view: add a
     `validate_merged_unique_ids` in `merged.py` and keep the old function for canonical-only callers.
   - Keep `rows.py` from growing: the logic lives in the new modules.
3. Direct callers that build rows by hand: `intent_creator.py:112`, `planner.py:644`, `outcome.py:188`,
   `sub_intents.py:63`, `sync_conflict.py:66`, `knowledge/records.py:153` and `flow/git_refs.py:292`.
   - With the buffered handle these need no write change, but each one stages files. Replace each
