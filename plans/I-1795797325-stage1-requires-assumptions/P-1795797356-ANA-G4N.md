### Implementation Details (No code blocks, only logic/steps)

1. Create `apps/sandbox-executor/src/sandbox_executor/intent_assumption_rules.py` using
   `from __future__ import annotations`, with zero docstrings and no comments other than `# why:` where strictly needed.
2. Define clear domain constants:
   - Required risk fields tuple: `likelihood`, `testability`, `score`, `response`.
   - High-score numeric threshold constant (`HIGH_RISK_SCORE_THRESHOLD = 6`, matching 3x3 risk matrices
     `medium * high = 6` and `high * high = 9` as well as 1–10 high scores) and high-score string set (`"high"`,
     `"critical"`).
   - Untestable testability markers (`"untestable"`, `"none"`, `"false"`, or boolean `False`).
   - Low/medium impact markers (`"low"`, `"medium"`) where `pr_question` is forbidden.
3. Implement small, intention-revealing helpers (each staying well within `C901 <= 10`, `PLR0912 <= 12`, `PLR0913 <= 5`,
   `PLR0915 <= 50`):
   - Extract and normalize each assumption item from `payload.get("assumptions")`: require a non-empty `list`; for dict
     items, extract key from `id`, `assumption`, `statement`, or `text`, plus optional `impact`, `mitigation`, and
     `pr_question`; for string items, require non-empty stripped text as the key. Record a violation for
     missing/empty/non-list `assumptions` or blank assumption items.
   - Index `payload.get("assumption_validation")`: require a non-empty `list` or `dict`. For a `dict`, map stripped keys
     to non-empty validation entries; for a `list`, index dict entries by `assumption_id`, `assumption`, or `id`
     (requiring non-empty validation content via `validation`, `method`, `check`, `how`, `test`, or any non-empty
     descriptive value). Record a violation if `assumption_validation` is absent/empty or if any declared assumption has
     no matching non-empty validation entry.
   - Index `payload.get("assumption_risk")`: require a `list` or `dict` where every declared assumption has a matching
     dict risk entry. For each assumption's risk entry, verify all four required fields (`likelihood`, `testability`,
     `score`, `response`) are present and non-empty (rejecting `None`, empty strings, and booleans for numeric `score`).
   - Check high-score untestable mitigation: determine whether the risk entry is high-score (numeric
     `score >= HIGH_RISK_SCORE_THRESHOLD` or string in `{"high", "critical"}`) and untestable (`testability` is `False`
     or normalized string in `{"untestable", "none", "false"}`). If both hold, require a non-empty `mitigation` on
     either the risk entry or the assumption item; otherwise record a refusal violation naming the assumption.
   - Check `pr_question` impact gating: if either the assumption item or its risk entry carries a non-empty
     `pr_question`, resolve `impact` from the assumption item or risk entry (normalized lowercase). If `impact` is
     `"low"` or `"medium"`, record a refusal violation naming the assumption and stating that `pr_question` is not
     permitted on low or medium impact assumptions.
4. Expose `assumption_violations(payload: dict[str, Any]) -> list[str]` as the primary entry point, plus a small helper
   (e.g. `default_assumptions_fields(statement: str, validation: str) -> dict[str, Any]`) if helpful for
   `e2e_harness.py` so `e2e_harness.py` stays concise and within its line budget.
