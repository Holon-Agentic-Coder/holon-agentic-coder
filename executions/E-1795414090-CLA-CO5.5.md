  with no id or the plan's own execution id is an execution row), `is_execution_row`, and `is_infrastructure_failure`
  over `summary`, `error` and `failure_reason` with anchored harness patterns (container dispatch exited or failed,
  usage or session limit, harness or turn timeout, `budget of N s exceeded`).

  the Stage 4 approval) and `calibration_predicted.py`, so it is unchanged. A new `is_matching_execution_record` in
  `calibration_ev.py` adds the execution-row filter for the dual EV; the "no match" fallback now only uses execution
  rows.
- `calibration_outcome.py`: a failing row (failed, non-zero exit or `sync_conflict`) followed by a later delivered
  (converged, zero-exit) execution row is resolved; a `sync_conflict` is also resolved by a later delivered row of any

  this, drag is identically 0 once a later delivery resolves every earlier failure, and the plan's matrix (success then

### Step 3: Measure the patch from the merge-base of the execution head with the target branch

  `git merge-base <target> <head>`, recomputed from the current head on every run.

  measured against their plan branch (`test_calibrate_nested_refs.py` unchanged apart from one assertion that now
  ignores the read-only `merge-base --is-ancestor` probes).
