### Strategy Rationale

**Intent assessment.** The intent is accepted as is. Reading
`apps/sandbox-executor/src/sandbox_executor/flow/git_refs.py` shows `_append_ledger_row` already has a `finally` that
removes the worktree, prunes and deletes the temp directory. Three real gaps remain, and they are what this plan closes:

1. **Killed runs.** A host process that dies (SIGKILL, SIGTERM, power loss) never reaches the `finally`, and nothing
   clears its registration later. Each leftover is then scanned by `flow/in_flight.py` (`_other_worktrees`) on every
   admission check.
2. **Cleanup order.** The prune runs before the `rmtree`, so a failed or timed-out `worktree remove` leaves a
   registration behind (reproduced, see Exploration).
3. **Unguarded cleanup.** `run_git(..., check=False)` still raises `TimeoutError` (and `OSError`). Raised inside the
   `finally`, it skips the `rmtree`, replaces a `LedgerRewriteError` in flight, or turns a row that is already pushed
   into a crash.

**Chosen strategy.** Move the worktree lifecycle into a new module `flow/ledger_worktree.py` as one private context
manager, and have `_append_ledger_row` enter it. This is forced as much as chosen: `git_refs.py` cannot grow by a single
line and the budget file is frozen, so the sweep cannot live there. The context manager does four things: clear stale
registrations, create the temp directory and take an owner lock, register the detached worktree, and on exit always
remove, delete, prune and release, each guarded so the next one still runs.

**Ownership by advisory lock.** "No live process owns" is decided with `fcntl.flock`, the mechanism
`flow/admission_lock.py` already uses. The step holds an exclusive lock on `owner.lock` inside its `holon-flow-ledger-*`
directory (beside `worktree/`, so never staged) for as long as the worktree is registered. The kernel releases the lock
when the process dies, however it dies. The sweep probes each leftover with a non-blocking lock: lock refused means a
live owner, so skip; lock granted or no lock file (a leftover from the current code, which writes none) means unowned,
so remove. Rejected alternative: a pid in the directory name checked with `os.kill(pid, 0)`. It is fooled by pid reuse
and pid namespaces, and needs an extra in-process registry; the lock needs neither, and two handles in one process
conflict, which makes the live-owner case deterministic to test.

**Patch seam preserved.** Many tests outside this intent's scope patch `sandbox_executor.flow.git_refs.run_git` (for
example `FakeGit` in `tests/test_ledger_append_only.py` and `refuse_push` in `tests/flow/stages/test_plan_decision.py`).
The new module therefore imports no git runner: `_append_ledger_row` passes its own `run_git` binding in at call time,
so every worktree command still goes through the patched name. With `FakeGit` (empty stdout) the sweep finds nothing and
the step behaves as today.

## Plan Description & Strategy

The ledger step appends one row to a ledger file in a temporary detached worktree, commits it and pushes it. This plan
makes that worktree impossible to leave registered.

A new module, `flow/ledger_worktree.py`, owns the worktree's whole life as one private context manager. On entry it
first clears what earlier runs left: it prunes registrations whose directory is gone, then removes every registered
`holon-flow-ledger-*/worktree` that no live process holds a lock on, then prunes again. It then creates the temp
directory with the unchanged `holon-flow-ledger-` prefix, takes an exclusive lock on an `owner.lock` file inside it, and
registers the detached worktree. On exit, whether the body returned, returned an error or raised, it removes the
worktree, deletes the temp directory, prunes (now after the delete, which fixes the ordering defect) and releases the
lock. No cleanup action can raise.

`_append_ledger_row` in `flow/git_refs.py` keeps its signature, its `try`/`except` clauses, and its append, validate,
add, commit, rev-parse and push lines. It only swaps the hand-rolled `mkdtemp`, `worktree add` and `finally` for a
`with` on the context manager, passing its own `run_git` so existing test patches keep working. The file ends shorter
than its frozen `407`-line limit.

Tests live in a new file, `tests/flow/test_ledger_worktree_cleanup.py`, against real repositories from the existing
`flow_repos` fixture, plus one seam test in `tests/flow/test_git_refs.py`. The success-contract tests are written first
and run against today's code, so "same commit and push as before" is demonstrated rather than asserted. The failure and
killed-run tests follow the implementation. Verification runs the affected tests, then the full suite once, then both
lint tasks, all in the foreground.

### Implementation Details (No code blocks, only logic/steps)

1. Create `apps/sandbox-executor/src/sandbox_executor/flow/ledger_worktree.py` with a module docstring describing the
   lifecycle, the owner lock and the sweep. Imports: standard library (`contextlib`, `fcntl`, `logging`, `os`, `shutil`,
   `subprocess` for the type, `tempfile`, `collections.abc`) and `redact_agent_secrets` only. Do not import `run_git`,
   `git_refs` or anything from `entrypoint`; the git runner is always a parameter.
2. Constants: `LEDGER_WORKTREE_PREFIX` (`holon-flow-ledger-`, unchanged from today), the leaf name `worktree`, the lock
   file name `owner.lock`, and the tuple of tolerated cleanup errors (`RuntimeError`, `TimeoutError`, `OSError`).
   Constants are exempt from the export contract; every function below is `_`-prefixed, typed and has a docstring.
3. `_quiet_git(git, args, repo_dir)`: call the runner with `cwd=repo_dir, check=False`; on a tolerated error log a
   redacted warning and return `None`; otherwise return the completed process.
4. `_claim_owner_lock(tmp_root, create)`: open `<tmp_root>/owner.lock` (creating it only when `create` is true) and take
   `fcntl.flock` with `LOCK_EX | LOCK_NB`. Return the descriptor on success. On any `OSError` (lock refused, file
   unreadable) close the descriptor if one was opened and return `None`. The caller owns the returned descriptor and
   closes it.
5. `_discard_worktree(repo_dir, worktree, git)`: `_quiet_git` for `worktree remove --force <worktree>`, then
   `shutil.rmtree` on the parent directory with `ignore_errors=True`, but only when the parent's base name starts with
   the prefix, the leaf is `worktree` and the parent is not a symlink.
6. `_leftover_worktrees(porcelain, repo_dir)`: pure parser over `git worktree list --porcelain` output. Split into
   blank-line-separated blocks; keep a block's path when its leaf is `worktree`, its parent's base name starts with the
   prefix, the block has a `detached` line and no `locked` line, the block is not the first one (the main worktree) and
   the path does not resolve to `repo_dir`. Blocks with a `prunable` line are left to the prune.
7. `_clear_stale_ledger_worktrees(repo_dir, git)`: `_quiet_git` for `worktree prune`; `_quiet_git` for
   `worktree list --porcelain` and return when it failed or exited non-zero; for each leftover path whose directory
   exists: when its `owner.lock` file is absent (a leftover from today's code, which writes none) discard it; when the
   file is present, claim it without creating it, skip the leftover when the claim returns `None` (a live owner),
   otherwise `_discard_worktree` and close the descriptor in a `finally`. Finish with one more `worktree prune` only
   when something was discarded. With an empty listing (as under `FakeGit`) this is two harmless calls.
8. `_ledger_worktree(repo_dir, ref, git)`: a `contextlib.contextmanager` generator yielding the worktree path.
   - Run `_clear_stale_ledger_worktrees` first.
   - `tempfile.mkdtemp(prefix=LEDGER_WORKTREE_PREFIX)`, then, inside a `try` whose `finally` is the cleanup, claim the
     owner lock with `create=True` (when the claim fails on a fresh directory, log a warning and continue unlocked,
     which is no worse than today), then run `git(["worktree", "add", "--detach", worktree, ref], cwd=repo_dir)` with
     the default `check=True` so a failed add raises exactly as today, then `yield worktree`.
   - Cleanup, in this order, each step guarded: `_discard_worktree` (remove, then delete the temp directory),
     `_quiet_git` for `worktree prune` (now after the delete), close the lock descriptor last.
   - The generator never suppresses the body's exception and never raises from cleanup.
9. Keep every function under the ruff complexity limits by keeping the helpers this small; confirm the file is well
   under `200` lines.
10. Run `uv run ruff check apps/sandbox-executor/src/sandbox_executor/flow/ledger_worktree.py` and
    `uv run ruff format --check` on the same path in the foreground for early feedback.

### Implementation Details (No code blocks, only logic/steps)

1. A helper that plants a leftover the way a killed step leaves it: create `<temp>/holon-flow-ledger-<name>/worktree`
   with a real `git worktree add --detach` from the host, optionally write an unheld `owner.lock`, optionally delete the
   directory afterwards.
2. Raise midway (criterion 2): patch `sandbox_executor.flow.git_refs.validate_ledger_file_unique_ids` to raise
   `LedgerRewriteError`. Assert the error propagates, and that afterwards no ledger worktree is registered, the temp
   directory is empty and origin's branch tip is unchanged. The patched validator records the host's registered
   worktrees just before it raises; assert that record contains one ledger worktree, so the test shows the removal
   happened on the way out.
3. Error-return path: make the recorder raise `RuntimeError` on `push`. Assert the step returns a non-empty string and
   leaves no registration and no temp directory.
4. Failed removal: make the recorder raise `TimeoutError` for `worktree remove`. Assert a successful append still
   returns `None` (the row is on origin) and that nothing stays registered, which exercises the delete-then-prune order.
5. Killed run, directory present (criterion 3), parametrised over a leftover without a lock file (today's layout) and
   one with an unheld `owner.lock`: plant it, confirm it is registered, run a successful ledger step, assert no
   `holon-flow-ledger-*` worktree is registered and the leftover's directory is gone.
6. Killed run, directory gone (criterion 3): plant a leftover and delete its directory, confirm git lists it, run a
   successful step, assert it is no longer registered.
7. Really killed process: start a child process (`sys.executable`) that enters `_ledger_worktree` on the host with the
   real `run_git`, prints the worktree path and sends itself `SIGKILL`. Assert the registration survived the kill, then
   run a successful step in the test process and assert none is registered. This checks that the kernel releases the
   owner lock on death. One child process, no retries.
8. Live owner is respected: plant a leftover with `owner.lock`, hold `fcntl.flock` on it from the test, run a successful
   step, assert the leftover is still registered and its directory intact; release the lock, run another step, assert it
   is gone.
9. Unrelated worktrees survive: add a detached worktree at a path without the prefix and a prefix-named one that is
   `git worktree lock`ed; run a step; assert both are still registered.
10. Sweep failure is harmless: make the recorder raise `TimeoutError` for `worktree list`; assert the append still
    succeeds and cleans up after itself.
11. Run `uv run pytest apps/sandbox-executor/tests/flow/test_ledger_worktree_cleanup.py` in the foreground.
