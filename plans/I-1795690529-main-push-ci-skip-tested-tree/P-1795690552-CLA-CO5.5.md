   positive evidence skips; every error is the gate's `api-error`"), standard library only, Python 3.9 syntax.
2. Imports: `GateClient`, `GateContext`, `pulls_for_commit`, `commit_tree`, `list_head_runs`, `list_jobs` from

   `FULL_RUN_STEP` from `scripts.ci_bookkeeping_chain`. No import of `scripts.ci_bookkeeping_gate` (avoids a cycle,
   since the gate imports this module).
3. Constants: `MAIN_REF = "refs/heads/main"`, `MAIN_BRANCH = "main"`,
   `GATED_WORKFLOWS = ("test-unit.yml", "test-stress.yml")` with a comment that only these two workflows hold
   `pull-requests: read`.
4. Rule names (kebab-case, each with a `main-push-` prefix so they never collide with the pull-request rules):
   `main-push-rerun-attempt`, `main-push-incomplete-event`, `main-push-no-pull-request`,
   `main-push-several-pull-requests`, `main-push-pull-request-not-merged`, `main-push-tree-mismatch`,
   `main-push-head-job-missing`, `main-push-head-job-not-finished`, `main-push-head-job-not-successful`,
   `main-push-head-job-unverified`; skip rule `main-push-tested-tree`. Export `MAIN_PUSH_RUN_RULES` (ordered tuple) and
   `MAIN_PUSH_SKIP_RULES = ("main-push-tested-tree",)`.
5. `is_main_push(context) -> bool`: true only for `event_name == "push"`, `ref == MAIN_REF` and
   `workflow_file in GATED_WORKFLOWS`. Everything else (pull requests, `schedule`, `workflow_dispatch`, pushes to other
   refs, other workflows, an empty context) falls through to the existing gate rules unchanged, so a `schedule` or
   `workflow_dispatch` run is decided by the existing named rule `event-not-pull-request` (full run).
6. `decide_main_push(context, client) -> Decision`, built from small helpers so that each function stays under the ruff
   limits (no helper above about 6 branches):
   - `_event_check`: `run_attempt > 1` -> `main-push-rerun-attempt` (detail `attempt N`); missing `sha`, `job_name`,
     `workflow_file` or `run_number`/`run_attempt` of 0 -> `main-push-incomplete-event`.
   - `_merged_pull_request`: `pulls_for_commit`; 0 -> `main-push-no-pull-request`; more than 1 ->
     `main-push-several-pull-requests` (detail lists the count); the one pull request must have `merged` true,
     `base_ref == MAIN_BRANCH` and `merge_commit_sha == context.sha`, else `main-push-pull-request-not-merged` with a
     detail naming which of the three failed (for example `#42 base dev` or `#42 merge commit abc123456789`). Returns
     either a run decision or the `PullRef`.
   - `_tree_check`: `commit_tree(sha)` versus `commit_tree(pull.head_sha)`; different -> `main-push-tree-mismatch` with
     both short tree ids in the detail.
   - `_head_job_check`: `list_head_runs(workflow_file, pull.head_sha)`; walk at most the newest 5 runs, newest first,
     and stop at the first run whose `list_jobs` answer holds exactly one job that `match_job` accepts for
     `(job_name, os_name)`. None found -> `main-push-head-job-missing`. Job not `completed` ->
     `main-push-head-job-not-finished`. `classify_job` gives `REAL_SUCCESS` or `GATE_SKIPPED` -> evidence holds;
     `UNVERIFIED` (no `Full run completed` step) -> `main-push-head-job-unverified`; anything else ->
     `main-push-head-job-not-successful` with the conclusion in the detail.
   - Final statement only:
     `Decision(True, "main-push-tested-tree", "#N head <12-char sha> run <number> <real success | gate-skipped>")`. The
     detail distinguishes a real success from a gate-skipped head job, which Step 8 uses as the learning signal.
7. No `try/except` in the module: every exception (HTTP 403/404/5xx, malformed JSON, missing keys) propagates to the
   gate's `safe_decide` and becomes `api-error` with a full run. The detail never contains the token or exception text
   (already guaranteed by `safe_decide`).
