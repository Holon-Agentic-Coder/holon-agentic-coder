## Summary

Complete. When Stage 3 admits a flow whose checkpoint shows it waited (blocked, then admitted), the host merges
`origin/<target>` into the plan branch before the execution branch is cut and the executor is dispatched:

- the admitted admission object keeps `waited_since` (from `blocked_since`) and later `refreshed_to`, so the refresh
  decision reads the checkpoint alone and a resume after a refresh conflict retries it; a first-check admission is still
  exactly `{state: "admitted"}` and is never touched;
- new `flow/plan_refresh.py` merges through the existing temporary-worktree merge (`merge_branch_detailed`, merge only,
  no force, ledger-only conflicts interleaved by `created_at`); any other conflict aborts the merge and fails Stage 3
  before dispatch with the files named (`dispatched=False`, `plan_refresh_conflicts`), leaving the checkpoint resumable;
- the refreshed target commit is recorded as a `plan_refresh` row on the plan branch's `executions.jsonl` (inherited by
  every execution branch), as `refreshed_to` in the checkpoint's admission object, and as `plan_refreshed_to` in the
  Stage 3 payload;
- the partial-resume lineage rule accepts a genuine refresh merge (subject prefix plus `git merge-tree` tree check), so
  resumed partial work survives a refresh; Step 5's fallback was not needed;
- documented in `docs/git_flow.md`, `docs/touch_set.md` and one sentence in `docs/ledger_schema.md`.

### Step 5: Let a resumed execution's partial work survive a refresh merge

Hypothesis confirmed; the fallback was not needed.

- `entrypoint/partial_resume.py::plan_lineage_refusal` keeps today's fast path (the whole range since the fork point is
  ledger-only) and otherwise walks the plan branch's first-parent commits after the fork (`_engine_owned_since`). A
  commit is engine-owned when it changes only `holon-knowledge/ledger/*.jsonl` against its first parent, or it is a
  refresh merge (`_is_refresh_merge`): two parents, a subject starting with `REFRESH_MERGE_PREFIX`, and a tree that,
  outside the ledgers, equals `git merge-tree --write-tree <parents>` (exit 1 still prints the tree; ledger conflicts
  are excluded from the comparison).
- The tree check replaces the plan's proposed diff-to-diff comparison: it is one git call and stays exact when both
  sides touched the same file without conflicting.
- The prefix constant comes from the shared pure module `plan_paths.py`, so the entrypoint imports nothing from the flow
  engine.
- All existing `tests/test_resume_tip.py` cases pass unchanged. New: partial work forked before a real
  `plan_refresh_stage_failure` refresh resumes from the recorded head and the new branch contains main's change (this
  test fails against the old rule); a forged-subject merge that also edits the plan and a plain merge of main are both
  refused.
