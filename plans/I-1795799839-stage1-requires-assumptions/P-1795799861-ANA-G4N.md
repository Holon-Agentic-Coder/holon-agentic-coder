   - Define constants for allowed risk levels, high-score threshold (e.g., `HIGH_RISK_SCORE_THRESHOLD = 6` on a 1–9

   - Implement a helper to normalise `assumptions`: require `payload.get("assumptions")` to be a non-empty `list`; emit
     a violation if missing, not a list, or empty. Extract each assumption's canonical identifier (`id`, or
     `statement`/`assumption` for dicts, or stripped string for string items) and optional `impact` level. Emit a
     violation for malformed/empty entries or duplicate IDs.
   - Implement a helper to index `assumption_validation` (supporting both a `list` of dicts keyed by
     `assumption_id`/`id` and a `dict` keyed by assumption ID): emit a violation if `assumption_validation` is missing
     or empty, and emit a violation for every assumption ID that has no non-empty validation entry.
   - Implement a helper to index `assumption_risk` (supporting both a `list` of dicts keyed by `assumption_id`/`id` and
     a `dict` keyed by assumption ID): emit a violation for every assumption ID lacking an `assumption_risk` dict entry,
     and validate that each entry provides non-empty `likelihood`, `testability`, numeric (non-bool) `score`, and
     non-empty `response`.
   - Implement the high-score untestable mitigation rule: when an assumption's risk entry has
     `score >= HIGH_RISK_SCORE_THRESHOLD` and normalised `testability == "untestable"`, require a non-empty `mitigation`
     (on the risk entry or assumption entry); refuse with a descriptive violation if missing. Accept the assumption when
     it carries both a non-empty `mitigation` and a valid `pr_question` (on a high-impact assumption).
   - Implement the `pr_question` impact restriction: whenever a non-empty `pr_question` is present on an assumption or
     its risk entry, inspect the assumption's `impact` (from the assumption entry or risk entry, normalised lowercase);
     if `impact` is `"low"` or `"medium"`, emit a refusal violation stating that `pr_question` is refused on low or
     medium impact assumptions.
   - Expose `assumption_violations(payload: dict[str, Any]) -> list[str]` as the primary entry point and
     `default_assumptions_fields() -> dict[str, Any]` returning a fresh, minimal, valid
     `{"assumptions": [...], "assumption_validation": [...], "assumption_risk": [...]}` dict for schema propagation in
     harnesses and child intents.
2. Update `apps/sandbox-executor/src/sandbox_executor/intent_payload_rules.py`:
   - Import `assumption_violations` from `sandbox_executor.intent_assumption_rules`.
   - In `check_intent_payload(payload, worktree=None)`, append `*assumption_violations(payload)` to `violations`
     alongside `scope_shape_violations` and `harness_reference_violations`.
   - Leave `scope_shape_violations`, `harness_reference_violations`, `hub_file_warnings`, and `intent_texts` completely
     unchanged.
3. Verify `apps/sandbox-executor/src/sandbox_executor/flow/intent_questions.py`:
   - Confirm `validate_intent_questions(intent_data)` invokes `check_intent_payload(intent_data).violations` and appends
