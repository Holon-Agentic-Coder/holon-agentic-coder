## Steps Executed

### Step 1: Sentinel and `None` budget core

- New leaf module `budget_limits.py` (standard library only, no `budgets` import): `UNLIMITED`, `is_unlimited`,
  `minutes_text` (the old `format_minutes` body; `budgets.format_minutes` is a thin wrapper), `format_budget_minutes`,
  `unlimited_stage_warning`, `unbounded_supervision_warning`.
- `budgets.py`: `_read_positive(..., allow_unlimited=True)` returns `None` for the sentinel with a WARNING naming the
  variable (never the value). The numeric validation moved into `_parse_seconds`, because the extra early return tripped
  `PLR0911`; this was fixed by extraction, with no new `noqa`. The overloads carry `allow_unlimited` with
  `Literal[False]` for the `float` return.
- `StageBudgets` fields, `for_stage`, `TurnBudgets.turn_seconds` and `Budgets.stage_seconds` are `float | None`.
  `Budgets.stage_override_unlimited` is the third state of `HOLON_STAGE_BUDGET_SECONDS`. `Budgets.unlimited_stages()`
  lists the stages with no ceiling.
- `StageTimer`: a `None` budget is kept as `None`. It adds `unlimited`, `has_time_left()` and `remaining_capped(cap)`;
  `remaining()` returns `None` and `breached()` returns False when unlimited. `breach()` asserts a finite budget.
- `format_stage_summary` prints `execute: ok (73.2 min / unlimited)`. `stage_budget_handdown_env` hands down
  `{"HOLON_STAGE_BUDGET_SECONDS": "unlimited"}` for an unlimited timer. The non-finite guard is kept.

### Step 2: Turn supervision

- `turns.silence_window(budgets, streaming)`: streaming uses `stall_seconds`; non-streaming uses `max(stall, turn)`, or
  `max(stall, DEFAULT_TURN_SECONDS)` when the turn timeout is unlimited.
- `_turn_breach(...)` returns `None` for an unlimited turn timeout. `run_turn` uses both helpers; its existing `noqa` is
  unchanged. The stall check is unchanged.
- `supervise_authoring_turn` uses `stage_timer.has_time_left()` in place of `remaining() > 0`.

### Steps 3-4: `None`-safe consumers and warnings (one commit; the warning helpers landed with Step 1)

- `flow/pipeline.py` (419 to 426 lines, limit 431): `stage_budget_seconds` returns `None` for an unlimited stage,
  including review (`None` per iteration). `timed_execute_stage` logs
  `WARNING: Stage '<stage>' runs with no wall-clock ceiling ...` when the timer is unlimited. After the stage it records
  `payload["stage_budget"] = "unlimited"` and returns before the overrun comparison.
- `flow/context.py` (280, line-neutral): `summary_line` falls back to the bare form only when `elapsed_seconds is None`.
  This assumption was verified: `after_stage` always fills `budget_seconds`, and every timed stage sets both fields.
- `flow/review/loop.py` (939 to 936): the registration timeout is
  `iteration_timer.remaining_capped(resolve_ci_registration_timeout(...))`. `flow/stages/review.py` needed no change.
- `entrypoint/executor.py`: the summary row keeps `budget_seconds` (`null` when unlimited) and adds
  `budget: "unlimited"`. `planner.py` and `review_ensemble.py` pass `None` straight into `StageTimer`; no edit.
- `load_budgets` logs one ERROR via `unbounded_supervision_warning` when the turn timeout is `unlimited`, stall is `0`
  and some stage is unlimited (warn, not refuse).
- `cli._report_budgets` prints `turn=unlimited`, `<stage>=unlimited` (else `<n>min`), `stage_override=unlimited`, and
  the `WARNING: Unbounded agent supervision ...` line in the all-disabled case. The hand-down call site is unchanged;
  the sentinel replaces any forwarded host value, as a test now shows.
- mypy is not installed in this environment (`uv run task lint` is ruff, format and module budgets only). Every consumer
  was checked by hand with a search for `budget_seconds`, `.remaining()`, `stage_seconds(`, `for_stage(` and
