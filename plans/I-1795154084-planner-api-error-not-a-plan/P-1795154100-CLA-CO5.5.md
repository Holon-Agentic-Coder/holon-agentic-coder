### Strategy Rationale

The incident has three independent defects that chain together:

1. The planner entrypoint's stdout fallback (`entrypoint/planner.py`, the `report is None or not report.exists` branch)
   writes whatever the agent printed to the plan path. An `API Error: 400 ...` line becomes the plan, and the metrics
   check then reports `missing or non-numeric overall metrics` instead of the real error.
2. Nothing removes that file on failure. The planner runs in the mounted host worktree, so the untracked
   `plans/{intent}/P-*.md` outlives the container and blocks a resume until someone deletes it by hand.
3. `token_reduction/payload_cleaner.py::_inject_anthropic_cache_control` adds `{"type": "ephemeral"}` blocks (default
   ttl 5m) to the last tool, the last system block and `messages[-2]`. The API reads the cache prefix in the order
   tools, system, messages. The claude CLI already puts `ttl: "1h"` blocks on its system blocks. A 5m block injected on
   the last tool therefore sits before a 1h system block, which is exactly the
   `system.2.cache_control.ttl ... must not come after a ttl='5m'` 400.

So the plan fixes each defect at the module that owns it, and adds new focused modules rather than growing files that
are already over the ~400-line guide (`planner.py` is 603 lines, `payload_cleaner.py` is 552) or at their line budget
(`flow/stages/plan.py` is 208 of 208):

- `sandbox_executor/agent_api_error.py` (new): a pure, runner-agnostic detector.
- `sandbox_executor/plan_attempt.py` (new, neutral package level so neither the flow engine nor the entrypoint imports
  the other): failure detail file and untracked plan file cleanup.
- `token_reduction/cache_control.py` (new): ordered slot model and TTL-consistent injection, which `payload_cleaner.py`
  delegates to (so `payload_cleaner.py` shrinks).

Aggregation: `p_success` is a qualitative product-style estimate held up by the two bottleneck steps. Step 3 (host-side
stage wiring and line budget, 0.82) and Step 2 (entrypoint wiring inside an already complex `main`, 0.85) are the
weakest links. A naive product of all steps (`0.93 * 0.85 * 0.82 * 0.85 * 0.90 = 0.50`) understates success because
failures are mostly cheap to fix within the same execution (lint or test feedback loops). So the overall value is set at
0.80, just below the weakest step. Entropy is the sum of step entropies (`1.2 + 2.2 + 2.3 + 2.3 + 1.0 = 9.0`). Impact is
a weighted judgement (82): the fix removes a misleading failure mode and a whole class of proxy 400s. Cost is the sum of
step costs (`2.0 + 3.5 + 3.5 + 3.0 + 1.5 = 13.5`) rounded down to 12.0 because Steps 1 and 2 share fixtures. Learning
value 5.0 comes from Step 4's verification of the cache ordering rule.

## Step 1: Add a runner-agnostic API error detector

- **Sub‑intent recommendation:** NO

### Intent & Git Integration

- **Step Intent:** Recognise an API failure in an agent's captured stdout/stderr without misreading a real plan that
  mentions API errors.
- **Git branch:** I-1795154084-planner-api-error-not-a-plan/P-1795154100-CLA-CO5.5/E-{epoch}-CLA-CO5.5/\_ (the plan's
  single execution branch)
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

- Create `apps/sandbox-executor/src/sandbox_executor/agent_api_error.py` with a module docstring explaining the incident
  (an API 400 written as a plan).
- Public function `detect_api_error(*texts: str) -> str | None`. For each text, in order, return the first match as a
  single trimmed message, or None:
  - First non-empty line (ANSI stripped) starting with `API Error:`, case-sensitive as the claude CLI prints it. Return
    that line plus up to the next few continuation lines of the same paragraph.
  - A line that matches an HTTP status line with a 4xx/5xx code at line start (`HTTP/1.1 400 Bad Request`,
    `HTTP/2 529`). Return that line.
  - The whole stripped text, or a line of it, parses as JSON whose top level has `"type": "error"` with an `error`
    object, or an `error` object carrying `type` and `message`. Return a compact
    `API error {error.type}: {error.message}` string. Also accept the claude CLI JSON result envelope with
    `is_error: true` whose `result` text starts with `API Error:`.
- Anchoring rule (false-positive guard): the `API Error:` marker counts only on the first non-empty line, or on any line
  when the whole text is at most about 20 lines and contains no `# Plan for` header. Document this in the docstring,
  with the reason that a valid plan may quote the marker.
- Clamp the returned message to `MESSAGE_MAX_CHARS = 2000`. Redaction is the caller's job (see Step 2), so the module
  stays free of credential imports. Keep every function under the ruff complexity limits by splitting the three matchers
  into private helpers.
- Add `apps/sandbox-executor/tests/test_agent_api_error.py`, parameterised over: the exact incident line
  (`API Error: 400 {"type":"error","error":{"type":"invalid_request_error","message":"system.2.cache_control.ttl: a ttl='1h' cache_control block must not come after a ttl='5m' cache_control block"}}`),
  an HTTP 529 status line, a bare error JSON body, a claude `is_error` envelope, and stderr-only errors. Negative cases:
  a full plan quoting `API Error:` mid-document, an empty string, and normal agent chatter.
- Run `uv run pytest apps/sandbox-executor/tests/test_agent_api_error.py`.

  `messages[*].content[*]`. A block without `ttl` counts as 5m, a 1h block must not follow a 5m block, and at most 4
  blocks are allowed per request. Choosing each injected block's ttl from its neighbours, and skipping a slot when no
  ttl fits, removes the 400 while keeping caching benefits.
- **Learning target:** Whether TTL-aware injection keeps at least one injected breakpoint in typical claude CLI
  payloads, where the system blocks are already 1h. The result tells us whether the proxy's caching still adds value
  next to the CLI's own breakpoints, or whether injection should be skipped whenever the client already sets blocks.
  This goes in the execution notes.
- **Maximum acceptable cost for this learning:** 1.5x this step's `cost_pred` (4.5); no live API calls.
