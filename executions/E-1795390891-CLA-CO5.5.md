and `_save_runner_checkpoint` helpers drive `_resolve_checkpoint_and_intent`, then `_build_flow_context`

- Test A, `test_a_stored_skip_review_is_dropped_and_logged_when_the_resume_does_not_pass_it`: a checkpoint with
  `skip_review` and `skip_calibrate` set, resumed without either flag, runs review and calibrate. The "Resume dropped
  the stored ..." WARNING is in `caplog` and `context.logs`, and the saved checkpoint holds both switches false.
  `test_only_the_switches_passed_to_this_run_take_effect` checks that a skip passed in this run is honoured.
- Test B, `test_agent_on_resume_overrides_the_checkpoint_runner_for_review_and_calibration[flag|env]`: an

  default model from `default_model_for`, the override is logged, and the reloaded checkpoint records both values.
  Deviation from the plan: `cli.resolve_model(agent, None)` does not fall back to the runner default. Model resolution

- Test C, `test_a_resume_without_agent_or_model_keeps_the_checkpoint_runner`: with `HOLON_AGENT` / `HOLON_MODEL`
  pointing at claude, a flagless resume still uses the checkpoint's `antigravity-agent` runner and its model.
- Test D, `test_a_checkpoint_without_switches_or_attribution_still_loads_and_resumes`: a raw JSON checkpoint with no
  `schema_version` or `agent` / `model` keys and no switches loads with the switches false, falls back to
  `LEGACY_DEFAULT_AGENT` / `LEGACY_DEFAULT_MODEL`, and resumes through review and calibrate.
