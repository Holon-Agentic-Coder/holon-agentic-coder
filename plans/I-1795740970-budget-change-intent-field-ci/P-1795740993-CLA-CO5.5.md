- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Add constants: `INTENT_FIELD = "module_budget_change"`, `INTENT_LEDGER = "holon-knowledge/ledger/intents.jsonl"`,
   `PENDING_INTENTS = "holon-knowledge/ledger/pending/intents/*.jsonl"` (a git pathspec; git treats `*` in pathspecs as
   a glob by default).
2. Add `added_intent_lines(base, head) -> list[str] | None`: run
   `git diff --unified=0 --no-color {base}...{head} -- INTENT_LEDGER PENDING_INTENTS` with `check=False`; return `None`
   on `OSError` or non-zero return code; otherwise return the content (prefix stripped) of lines starting with `+` but
   not `+++`.
3. Add `intent_rows(lines) -> list[dict]`: parse each line with `json.loads`, skip `json.JSONDecodeError` and non-dict
   values.
4. Add `carries_budget_change(row) -> bool`: value is a `str` and `value.strip()` is non-empty. Add a `# why:` comment
   stating it must agree with the flow's `module_budget_change_authorised`, so the flow gate and CI accept the same
   intents.
5. Add `intent_field_refusal(base, head) -> str | None`: if `added_intent_lines` is `None`, return a message that the
   intent rows added between base and head cannot be read so `module_budget_change` cannot be confirmed; if no added row
   carries the field, return a message naming `module_budget_change` as missing or empty in every intent row the pull
   request adds; else `None`. Message format:
   `"{BUDGET_CONFIG} changed, but ... the '{INTENT_FIELD}' field ... Only an intent quoting the maintainer's instruction in '{INTENT_FIELD}' authorises a module budget change."`.
6. In `main`, after the unchanged-config early return and before the token check, compute `intent_field_refusal`; if it
   is not `None`, print it to stderr and return 1. Keep the unchanged-file pass message and all label code untouched.
   Update the success message to mention both halves (label by administrator, intent field present), and the argparse
   description to name both.
7. Keep every function under the ruff complexity limits; no docstrings; only `# why:` comments. Keep the module well
   under 400 lines.
