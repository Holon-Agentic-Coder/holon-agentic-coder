## Plan Description & Strategy

**Root cause (from code reading).** `FlowContext.target_worktree` defaults to `"."`
(`apps/sandbox-executor/src/sandbox_executor/flow/context.py:150`), and `save_checkpoint` writes to
`get_default_checkpoint_path(context.target_worktree, slug)` = `<cwd>/.holon/flow/checkpoint-<slug>.json`
(`flow/checkpoint.py:158-161`). Many tests build `FlowContext(token_reduce=False, intent_data={"slug": "parent"}, ...)`
without `repo_dir`/`target_worktree` and without a `chdir` — e.g. `tests/flow/test_pipeline_touch_set.py:47`,
`tests/flow/stages/test_decomposition.py` (lines 377, 427, 455, 475, 515, 564, 610, 825, 837, 918-1060),
`tests/flow/stages/test_children.py:355` — so when a pipeline run, Stage 3 admission (`save_admission`) or the children
stage saves a checkpoint, it lands in the pytest working directory. The root `pyproject.toml` runs pytest from the
repository root (`testpaths = ["apps/sandbox-executor/tests"]`), so the stray file is the repository's
`.holon/flow/checkpoint-parent.json`, next to the live flow's own checkpoint.

**Strategy.**

1. Build the guard first (a small, focused helper module plus thin fixtures in `tests/conftest.py`): a per-test autouse
   guard for attribution (mirroring `checkout_ledger_guard`) and the required autouse **session** guard that fails the
   run if anything under the repository's `.holon/` (and the invocation directory's `.holon/` when different) was
   created, modified or deleted during the session.
2. Run the suite once under the guard to enumerate every offender (not only the `parent`-slug candidates).
3. Fix each offender by pinning the context's worktree to `tmp_path` (pass `repo_dir=str(tmp_path)`, or a class-level
   fixture that does so / `monkeypatch.chdir(tmp_path)` where a test builds many contexts). No production code changes:
   the default `"."` is the CLI's contract and changing it is out of scope.
4. Prove the guard fails a session with a dedicated test that points the guard at a temporary root (never the real
   `.holon/`).
5. Document the guard in `apps/sandbox-executor/docs/hermetic_testing.md`, then validate: affected tests, the full suite
   once via `uv run task test`, `uv run task lint`, `uv run task lint-docs`, and a before/after listing of `.holon/`.

No `src/` module changes are planned, so no module budget is at risk and `holon-config/hygiene/module_budgets.json`
stays untouched. Test modules are not budget-checked, but the guard logic goes into a new focused module so
`tests/conftest.py` (326 lines) grows only by two thin fixtures.

### Strategy Rationale

The intent is accepted as is: the root cause is clear from code reading (`FlowContext.target_worktree` defaults to
`"."`, and tests that omit `repo_dir` save checkpoints into the pytest working directory, which is the repository root),
the fix is test-only, and the guard copies a pattern the suite already uses twice. Building the guard first turns the
open-ended "find every test" goal into a measured list (Step 2) and keeps it enforced afterwards. A production change
(e.g. making `save_checkpoint` refuse a relative worktree) was considered and rejected: it changes CLI behaviour,
touches a budgeted `src/` module (`flow/checkpoint.py`, limit 228) and is outside the intent's scope.

**Aggregation.**

- `entropy_pred` is the sum of step entropies: `1.4 + 0.8 + 1.8 + 1.0 + 1.1 = 6.1`.
- `cost_pred` is the sum of step costs: `2.5 + 1.5 + 3.5 + 1.5 + 2.0 = 11.0`.
- `p_success_pred`: the bottleneck chain is Steps 1, 3 and 5; the independent product is `0.93 * 0.90 * 0.92 = 0.77`,
  raised to 0.82 because the steps are positively correlated (the same guard both finds and verifies the fixes) and
  Steps 2 and 4 have explicit fallbacks. Step 3 is the bottleneck step.
- `impact_pred` = 70.0 by qualitative judgement: it removes a live-checkpoint corruption hazard for every flow and adds
  a permanent regression guard, but changes no product behaviour.
- `learning_value_pred` = 4.0, mainly from Step 2 (complete offender inventory, whether non-checkpoint `.holon/` writes
