## Steps Executed

### Step 1: layered configuration loader (`config_env`, `config_env_keys`, `config_env_model`, `config_env_parse`)

- Ported the four modules from the previous execution ref, then aligned them with this plan where it differs:
  - An empty value (`KEY=`) now means "not set in this layer" and falls back to the next broader layer with a non-empty
    value (or the built-in default). The empty layer is listed among the shadowed layers as `<layer> (empty)`.
    `apply_to_environ` fills keys that are absent or empty in the process environment.
  - A shell `export` prefix is rejected with a line-number warning (strict subset), instead of being accepted.
- Per-key resolution moved into `_resolve_key` to keep complexity low. No `expandvars`, `shlex` or subprocess use in the
  loader or parser. All four modules are under 200 lines (`config_env.py` is 191 lines).

### Step 2: secret files, permission warnings and dispatcher OAuth mapping

- `config_env_secrets.py`: `HOLON_AGENT_OAUTH_TOKEN_FILE` is read into `HOLON_AGENT_OAUTH_TOKEN` in the same layer, with
  warnings for loose file modes and for a git-tracked project `.env` that holds secrets (list argv `git ls-files`, 10 s
  timeout, silent on failure). Warnings name only the path, mode or key.
- `claude_credential.py`: `HOLON_AGENT_OAUTH_TOKEN` is used after an explicit `CLAUDE_CODE_OAUTH_TOKEN` or
  `ANTHROPIC_API_KEY`. Added the shared `pin_claude_credential`. The `HOLON_AGENT_SETTINGS` path still works.
- `redaction.py`: `HOLON_AGENT_OAUTH_TOKEN` added to `_CREDENTIAL_ENV_NAMES`. `agent_runner.py`: a comment saying
  `HOLON_AGENT_SETTINGS` no longer carries the token.
- `role_dispatcher.sh`: exports `CLAUDE_CODE_OAUTH_TOKEN` from `HOLON_AGENT_OAUTH_TOKEN` for the claude agent when no
  explicit credential is set, without echoing it.
- Guardrail tests: `test_claude_credential.py`, `test_credential_hermeticity.py` and `test_redaction.py` gave 377 passed
  and 1 skipped.
- Note: `git checkout <ref> -- <files>` staged the Step 2 files, so Steps 1 and 2 share commit `9e12f54e`
  (`step 1: add the layered configuration loader`). History is not rewritten.

### Step 3: resolve once per invocation and forward through the 0600 env-file

- `cli/__init__.py`: `main` calls `resolve_layered_configuration()` before building the parser. It prints warnings to
  stderr (redacted), fills only absent or empty `os.environ` keys and remembers the provenance for `holon doctor`. An
  invocation that already has `HOLON_CONFIG_RESOLVED=1` reads no layer file.
- `launcher/container_env.py`: every role container gets `HOLON_CONFIG_RESOLVED=1` in its 0600 env-file. The claude
  credential pin moved to the shared `claude_credential.pin_claude_credential`. Multi-line values keep the existing
  name-only `-e NAME` passthrough in `env_files`.
- `preflight.py`: `HOLON_AGENT_OAUTH_TOKEN` added to `_SENSITIVE_ENV_VARS`. `build_probe_docker_cmd` uses the shared pin
  and the marker.
- Step 3 tests gave 702 passed and 6 failed. The 6 failures are the pinned env-file lines and the pinned doctor payload,
  which Step 6 updates.

### Step 4: doctor configuration report and `.env.example` scaffolding

- `config_env_report.py`: one row per effective setting with value, source and shadowed layers. Secrets render as

  as `set (<layer>; value withheld)`. It also renders the commented `.env.example`, whose empty-value line now matches
  the fall-back semantics.
- `cli/__init__.py` (`run_doctor`, from Step 3's port): adds a `configuration` section to the text and `--json` output.

  `_update_gitignore` already deduplicates.
