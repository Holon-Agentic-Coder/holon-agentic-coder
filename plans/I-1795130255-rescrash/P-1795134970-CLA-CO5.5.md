## Plan Description & Strategy

The fix enforces one invariant end to end: **a finding leaves the review loop only through an explicit disposition
supplied by a resolver that ran: `applied`, or `rejected` with a stated reason. Anything else keeps it open, and an open
finding blocks approval, even across a resume.**

1. **Fail-closed parsing** (`resolver_evidence.py`, `review_report.py`):
   - A finding with no resolver entry defaults to `open` at every severity.
   - A `rejected` entry whose reason is empty, unknown or `unspecified` is refused and settles as `open`, with an audit
     note. This applies at every severity.
2. **No usable output is a failure** (`entrypoint/review_loop.py`):
   - A non-zero exit fails the turn even when a dispositions file exists.
   - A zero exit with findings but no dispositions file fails with "no usable output".
   - Output that names a usage or session limit is reported as such in the error.
3. **No ledger rows after a failed pass** (`flow/review/loop.py`, `flow/review/resolver.py`):
   - After a resolver error, the end-of-loop fallback writes nothing. The loop result carries `open_findings`.
   - `_dispatch_review_resolver` and `_invoke_resolver_pass` return no fallback dispositions on error.
4. **Carry and resume** (new `flow/review/carried_findings.py`, `flow/context.py`, `flow/review/loop.py`):
   - `FlowContext.carried_review_findings` is saved in the checkpoint.
   - `_run_engine_review_loop` stores the loop's open findings there.
   - `run_review_loop` sends carried findings to the resolver before the first new ensemble iteration, merges any that
     stay open into each later iteration's resolver input, and refuses consensus while any carried finding has no
     disposition.
5. **PR #203 nits** (`flow/calibrate_rerun.py`): both are applied, with a test each.
6. **Ledger correction** (`holon-knowledge/ledger/executions.jsonl`): two appended `ACT-COR` rows void the false rows.
7. **Budgets, docs, validation:** `flow_module_budgets.json`, `docs/review_consensus.md` and `docs/ledger_schema.md` are
   updated, then the affected tests, `uv run task test`, `uv run task lint` and `uv run task lint-docs` run.

Tests changed or added (declared under world ruleset §3):

- `tests/test_review_resolver_failure.py`, `tests/test_review_loop.py` and `tests/test_calibrate_rerun.py`, all new
  tests.
- `tests/test_resolver_evidence.py` and `tests/test_review_report.py`, to update existing assertions that encode the

## Step 4: Carry open findings in the checkpoint, resolve them first on resume, and gate approval on their disposition

- **Sub‑intent recommendation:** NO
- **Reasoning:** This is the largest and riskiest step and the bottleneck. It still fits the budget, and splitting it
  from step 3 would leave `open_findings` without a consumer. The logic goes in a new focused module, so the risk is
  contained.
- **Step Type:** IMPLEMENTATION
- **Exploration level:** EXPLOIT

### Intent & Git Integration

- **Step Intent:** Make goal 3 and acceptance criterion 2 true. A resume of the review stage sends the open findings to
  the resolver before any new review iteration, and approval is not reachable while any of them has no disposition.
- **Git branch:** same execution branch
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Create `flow/review/carried_findings.py` (target under 150 lines, with a docstring for the module and every public
   function). It holds:
   - `serialize_open(findings, action_ids)`: one dict per `FindingRow` (`id`, `severity`, `path`, `line`, `summary`,
     `recommendation`, `reviewers`, `introduced_by_action_id`), reusing `serialize_finding_for_resolver` where it fits.
   - `deserialize_carried(raw)`: returns `(rows, action_ids)`, fail-closed. Malformed entries are skipped and logged,
     never treated as approved.
   - `merge_findings(fresh, carried)`: deduplicates by `finding_signature`, carried first, so the resolver input order
     is stable.
   - `undisposed(carried, recorded_keys)`: the carried rows whose signature has no applied or rejected ACT-RES row
     recorded in this run.
   - `resolve_carried_first(...)`: runs one resolver pass on the carried rows before the ensemble. Its arguments are the
