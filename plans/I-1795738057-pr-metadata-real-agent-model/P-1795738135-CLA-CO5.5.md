### Strategy Rationale

The intent is small, well-specified and low-risk, so it is executed as one plan of three sequential steps on a single
execution branch: (1) teach the pure renderer to accept a supplied runner with the precedence plan payload, then runner,
then intent, then `N/A`; (2) make `_semantic_pr_text` supply the flow context's agent and model; (3) run the affected
tests, lint and the full suite once.

Aggregation: `p_success` is the product of the step probabilities, nudged up because the steps are strongly correlated
(same author, same tiny surface): `0.93 * 0.92 * 0.95 = 0.81`, judged `0.86`. Entropy is the sum of step entropies
`1.2 + 1.0 + 0.5 = 2.7`. Impact is the sum of step impacts `25 + 15 + 5 = 45`. Cost is the sum `2.5 + 2.0 + 2.0 = 6.5`.
Learning value is the sum `1.0 + 1.0 + 0.5 = 2.5`. With `mu = 0.5` and `lambda = 0.3`:
`EV = 0.86 * 45.0 + 0.5 * 2.5 - 0.3 * 2.7 - 6.5 = 38.70 + 1.25 - 0.81 - 6.50 = 32.64`.

The bottleneck is Step 1: it owns the precedence rule and the self-explaining-code gate on added lines. Step 2 is the
only place a wiring mistake could leave the real PR body unchanged, which is why it gets its own acceptance test through
the real `_semantic_pr_text`.

Design decision: pass the runner as a separate keyword argument (`runner`, a mapping with `agent` and `model`) rather
than merging it into the plan payload dict in `ensemble.py`. A dict merge like `{**runner, **plan}` would let an empty
or `None` agent in the plan payload overwrite the real runner; resolving precedence in one function in `pr_metadata.py`
with "first non-empty value wins" keeps "N/A only when genuinely absent" true for every source and keeps the rule
testable without a FlowContext.
