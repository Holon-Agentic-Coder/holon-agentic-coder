3. Docstring finder: walk `ast.parse(source)`. For each `ast.Module`, `ast.ClassDef`, `ast.FunctionDef` and
   `ast.AsyncFunctionDef` node where `ast.get_docstring(node, clean=False)` is not None, return the line number and the
   node name. Name it something like `docstring_locations`.
4. Comment classifier `is_permitted_comment(line_number, column, text)`:
   - A shebang is allowed only on line 1, column 0.
   - An encoding cookie is allowed on line 1 or 2.
   - Otherwise strip the leading hashes and spaces from the body. Allow it if the body starts with `why:`
     (case-insensitive, to match `scripts/self_explaining_comments.py`), or if it matches a machine-directive pattern
     anchored at `noqa`, `type:`, `pragma:` or `fmt:`.
5. Comment finder: tokenize the source and keep the `COMMENT` tokens that are not permitted.
6. Three parametrised tests over the 12 files: the file exists; it has no docstrings; it has only permitted comments.
   Each failure message names the path and lists the findings.
7. Add one small parametrised classifier test that pins the allowlist. A `# why:` reason, `# noqa: PLR0913`,
   `# type: ignore[arg-type]`, `# pragma: no cover`, `# fmt: off`, a line-1 shebang and a line-1 encoding cookie are
   allowed. A plain describing comment, a shebang on line 5 and `# Why this is here` without a colon are refused. This
   stops the guard from quietly widening.
8. The new file must itself carry no docstrings or comments, so it passes `scripts/check_self_explaining.py`. Name
   helpers in the domain language (`cleaned_test_file_source`, `forbidden_comments`, `docstring_locations`).
9. Run `uv run pytest apps/sandbox-executor/tests/test_self_doc_tests_47.py` in the foreground. The existence and
   classifier cases should pass, and the docstring and comment cases should fail for the files listed in the baseline
   (expected red). The calibrate_nested_refs, conflict_classes, conflict_resolver_tiers and end_of_flow_sync files fail
   only on docstrings.
