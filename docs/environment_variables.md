# Environment variables

Every `HOLON_*` environment variable that the sandbox executor, the role containers, the agent runners, the entrypoint
scripts and CI read or forward, with one row per variable, grouped by area.

The page is backed by the typed registry `apps/sandbox-executor/src/sandbox_executor/env_registry.py` and enforced by
`apps/sandbox-executor/tests/test_environment_reference.py`: the test scans the source tree for `HOLON_*` names and
fails when code reads a name missing from the registry or this page, or when either lists a name the code no longer
reads. Adding or retiring a variable therefore means updating the registry and this page in the same change.

## How values are resolved and forwarded

- **Layers.** Each variable resolves on its own, from broadest to most specific: built-in defaults, `~/.holon/.env`,
  `<repo>/.env`, the process environment and explicit CLI flags; the most specific layer that sets a non-empty value
  wins. Only `HOLON_*` keys and `GITHUB_TOKEN` are accepted in a layer file. Host-set keys (marked "(internal)" below,
  plus `HOLON_SKIP_PREFLIGHT` and `HOLON_IN_SANDBOX`) and the retired `HOLON_REPO_URL` are refused there, and the
  project file `<repo>/.env`, which a repository can commit, may not set a credential, a token-file reference or a key
  that reaches the host (the rows saying "refused in a project `.env`"). `holon doctor` lists every effective setting
  and the layer it came from; see the
  [layered configuration section of the executor README](../apps/sandbox-executor/README.md).
- **Forwarding.** "env-file" means the host forwards the value to the role container through the `0600` docker
  `--env-file`, as it does for every host `HOLON_*` value except retired ones; a value no env-file line can carry (a
  line break or a non-UTF-8 byte) goes as a bare `-e NAME` passthrough, its value set in the docker client environment,
  so no value is ever on the command line. "argv" means the host sets the variable explicitly on the proxy sidecar's
  command line (`HOLON_IN_CONTAINER=1` and the value-less `-e HOLON_COHERENCE_WEB_PASSWORD`). "not forwarded" means the
  host withholds it.
- **Read by.** "host" is the `holon` process on the operator's machine, "container" a role container (or the proxy
  sidecar), "both" either, "CI" the GitHub Actions workflows, and "CI, container" the workflows and a role container's
  lint run.
- **Secret.** "yes" marks a credential, as decided by `config_env.is_secret_key`. Secret values are redacted from logs
  and command echoes and never belong in a committed file.
- **Internal.** "(internal)" marks a variable the host, the flow or a maintainer sets for one run; operators do not set
  it.

Budget semantics (the `unlimited` sentinel, the 7-day maximum, stall detection) are described in
[budgets.md](budgets.md); the token-reduction proxy in
[token_reduction_architecture.md](optimisation/token_reduction_architecture.md); runner credentials in
[agent_credentials_requirements.md](executor/agent_credentials_requirements.md).

## Examples

Placeholders only: never paste a real token or key into a committed file. Credentials belong in `~/.holon/.env` or the
process environment, never in `<repo>/.env`.

The claude credential belongs in the OS keychain (see `docs/executor/agent_credentials_requirements.md` for the store
commands), which needs no line in any `.env`. To override the keychain entry with a claude subscription token by file
reference, in `~/.holon/.env` (the file holds the token, mode `0600`):

```dotenv
HOLON_AGENT=claude
HOLON_AGENT_OAUTH_TOKEN_FILE=<path-to-token-file>
```

An API key for another runner:

```dotenv
HOLON_AGENT=codex
HOLON_AGENT_KEY=<your-api-key>
```

`HOLON_AGENT_KEY` versus OAuth for claude: the claude runner never consults `HOLON_AGENT_KEY` and drops it from its
container. It takes an explicit `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` first, then `HOLON_AGENT_OAUTH_TOKEN`
(filled from `HOLON_AGENT_OAUTH_TOKEN_FILE`), then the OS keychain. The OS keychain is the recommended store: the token
is then in no plaintext file at all. `HOLON_AGENT_OAUTH_TOKEN_FILE` is an explicit override of the keychain entry, and
is preferred only over an inline `HOLON_AGENT_OAUTH_TOKEN` value, because it keeps the token out of every layer file. A
reference to the retired `~/.holon/secrets/claude-oauth-token` is ignored with a warning: that file is only imported
into the keychain once and is never read as the credential. `HOLON_AGENT_KEY` is the credential channel of every other
runner, which the role dispatcher exports under the vendor's own variable name.

Token reduction and an unbounded execute stage for one run:

```bash
HOLON_TOKEN_REDUCE=1 HOLON_STAGE_BUDGET_EXECUTE_MINUTES=unlimited holon flow ...
```
