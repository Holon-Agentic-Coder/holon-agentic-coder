- Create `scripts/check_self_doc_behavior.py` using only Python standard library modules (`__future__`, `argparse`,
  `ast`, `dataclasses`, `json`, `os`, `pathlib`, `re`, `subprocess`, `sys`, `collections.abc`) so it runs directly on
  `python3` in CI.
- Enforce self-explaining code throughout: no docstrings and no explanatory comments; only `# why:` comments where a
  non-obvious constraint must be recorded, and keep every function within ruff complexity limits (`C901 <= 10`,
  `PLR0912 <= 12`, `PLR0913 <= 5`, `PLR0915 <= 50`) and total module length <= 350 lines.
- Implement pure AST-normalisation helpers:
  - `is_docstring_statement(statement: ast.stmt) -> bool`: returns `True` iff `statement` is an `ast.Expr` whose `value`
    is an `ast.Constant` with `isinstance(value.value, str)`.
  - `DocstringStripper(ast.NodeTransformer)`: visits `Module`, `ClassDef`, `FunctionDef`, and `AsyncFunctionDef` by
    first running `generic_visit(node)`, then removing `node.body[0]` when `node.body` is non-empty and
    `is_docstring_statement(node.body[0])` is `True`. For `ClassDef`, `FunctionDef`, and `AsyncFunctionDef` (not
    `Module`), if stripping `node.body[0]` leaves `node.body` empty, set `node.body = [ast.Pass()]`.
  - `normalise_python_source(source: str) -> str`: parses `source` with `ast.parse(source)`, transforms it with
    `DocstringStripper().visit(tree)`, and returns `ast.dump(tree, include_attributes=False)` (note: `ast.parse` already
    discards all comments and formatting).
  - `FileComparison` frozen dataclass (`path: str`, `equivalent: bool`, `detail: str`) and
    `compare_python_sources(path: str, before: str, after: str) -> FileComparison`: calls `normalise_python_source` on
    `before` and `after`, catches `SyntaxError` to return `equivalent=False` with a clear parse-error detail, and
    compares the two normalised AST dumps for exact equality.
- Implement pure trigger-detection helpers:
  - `ChangedFileEntry` frozen dataclass (`status: str`, `old_path: str`, `new_path: str`, `before_text: str | None`,
    `after_text: str | None`).
  - `TriggerDecision` frozen dataclass (`should_run: bool`, `reason: str`).
  - `parse_labels_json(raw: str) -> tuple[str, ...]`: parses GitHub's `toJSON(github.event.pull_request.labels)` payload
    (accepting a JSON list of dicts with `"name"` or a JSON list of strings) and returns lowercase label strings,
    returning `()` on empty/invalid input.
  - `matches_self_doc_label(labels: Iterable[str]) -> bool`: returns `True` if any normalised label contains `self-doc`,
    `self_doc`, `self-explaining`, or `self_explaining`.
  - `matches_self_doc_title(title: str) -> bool`: returns `True` if `title` matches case-insensitive regex
    `\bself[-_ ]?(?:doc|explaining)\b`.
  - `is_self_doc_test_path(path: str) -> bool`: returns `True` for Python test files whose filename matches
    `test_*self_doc*.py` or `test_*self_explaining*.py`.
  - `is_comment_or_docstring_only_diff(entries: Sequence[ChangedFileEntry]) -> bool`: returns `False` if `entries` is
    empty; otherwise returns `True` iff every entry is either a self-doc test path
    (`is_self_doc_test_path(entry.new_path)`) or a modified/renamed Python file (`entry.status` starting with `M` or `R`
    and `.py` suffix) with both `before_text` and `after_text` present whose `compare_python_sources` result is
    `equivalent=True`.
  - `should_run_self_doc_gate(labels: Iterable[str], title: str, entries: Sequence[ChangedFileEntry]) -> TriggerDecision`:
    returns `(True, "label")` if `matches_self_doc_label`, `(True, "title")` if `matches_self_doc_title`,
    `(True, "diff-only")` if `is_comment_or_docstring_only_diff`, else `(False, "not-self-doc")`.
- Implement git revision-range helpers:
  - `run_git(root: Path, *args: str) -> subprocess.CompletedProcess[bytes]`: runs `git` in `root` with
    `capture_output=True` and `check=False`.
  - `diff_entries(root: Path, base: str, head: str) -> list[ChangedFileEntry]`: runs
    `git -c core.quotePath=false diff --name-status -z --find-renames <base> <head>`, parses NUL-delimited status/path
    records (`M`, `A`, `D`, `R...`, `C...`), and for modified/renamed `.py` files reads `before_text` via
    `git show <base>:<old_path>` and `after_text` via `git show <head>:<new_path>` (UTF-8 decoded). Raise `RuntimeError`
    if `git diff` returns a non-zero exit code.
  - `check_changed_python_files(entries: Sequence[ChangedFileEntry]) -> list[FileComparison]`: runs
    `compare_python_sources` on every modified/renamed `.py` entry (excluding `is_self_doc_test_path` only? No: include
    all modified `.py` files when running the check; if a self-doc test file is newly added `A`, it has no `before_text`
    and is not a modified file; if a self-doc test file is modified in a self-doc PR, wait — a PR might modify a
    self-doc test alongside docstrings, so only skip `is_self_doc_test_path` when checking modified files OR check
    non-self-doc-test modified `.py` files; specifically, check all modified `.py` files that are not self-doc test
    files when triggered by `diff-only` or check all modified `.py` files: to be cleanest and match "compares
    `ast.dump(tree, include_attributes=False)` before vs after for every modified Python file", compare every
    modified/renamed `.py` file except when `is_self_doc_test_path` is explicitly excluded? Actually, in a self-doc
    slice PR, self-doc tests are not modified; and in a PR touching this gate's own tests, excluding
    `is_self_doc_test_path` from the AST-equivalence failure list prevents the gate from failing on PRs that add/update
    self-doc gate tests! Let's make `check_changed_python_files` check every modified/renamed `.py` file where
    `not is_self_doc_test_path(entry.new_path)` and note that clearly).
- Implement CLI `parse_arguments(argv)` and `main(argv=None) -> int`:
  - Accepts `--base`, `--head`, `--range` (mutually exclusive with `--base`/`--head`, split on `..`), `--root` (default
    repo root), `--auto-trigger`, `--pr-title` (default `os.environ.get("PR_TITLE", "")`), `--pr-labels-json` (default
    `os.environ.get("PR_LABELS", "")`), and repeatable `--pr-label`.
  - When `--auto-trigger` is passed, calls `should_run_self_doc_gate`; if `not decision.should_run`, prints a clear skip
    line and returns `0`.
  - Runs `check_changed_python_files(entries)`; prints failures to `stderr` and returns `1` if any comparison has
    `equivalent=False`, otherwise prints a concise pass summary with checked file count and returns `0`. Returns `2` on
    git errors or invalid revision arguments.

### Implementation Details (No code blocks, only logic/steps)

- Create `apps/sandbox-executor/tests/test_check_self_doc_behavior.py` with self-explaining test names, zero
  docstrings/explanatory comments, and total line count <= 350 lines.
- Add pure AST-normalisation tests:
  - Removing module, class, function, async function, and nested docstrings plus standalone/inline comments produces
    identical normalised AST dumps and passes `compare_python_sources`.
  - Removing a docstring from a class, function, or async function whose body contained only that docstring and
    replacing it with `pass` passes `compare_python_sources` (empty-body `pass` substitution).
  - Removing a docstring from a docstring-only module so the file becomes empty (or comment-only) passes
    `compare_python_sources`.
  - Removing a non-leading string expression (e.g., second statement in a function body or string expression inside an
    `if` block) FAILS `compare_python_sources`.
  - Sneaking a code change alongside docstring/comment removal (e.g., changing a return value, operator, default
    argument, or adding a statement) FAILS `compare_python_sources`.
  - Passing invalid Python syntax in `before` or `after` returns `equivalent=False` with a syntax error detail.
- Add trigger-detection tests for `should_run_self_doc_gate` and `parse_labels_json`:
  - Label trigger: PR labelled `self-doc` or `Self-Explaining` (parsed from GitHub `toJSON` label object array) triggers
    with reason `"label"`, even when the diff contains a code change.
  - Title trigger: PR titled `refactor: self-doc cleanup` or `[self-doc] strip comments` triggers with reason `"title"`,
    even when the diff contains a code change.
  - Diff-only trigger: PR with unrelated title and no labels whose diff only strips docstrings/comments from `.py`
    files, or only touches a self-doc test file, or combines both, triggers with reason `"diff-only"`.
