### Step 3: Add the append-only row diff check script

- Added `scripts/check_ledger_rows_append_only.py`: `merge_base`, `ledger_paths_at` (`git ls-tree`, filtered with the
  Step 1 `classify`), `read_blobs` (one `git cat-file --batch` call per side instead of one call per file), `rows`,
  `compare_rows` (capped at 20 problems per file), `promoted`, `check_append_only` (returns the problems and the number
  of base files checked) and `main`. Any git failure maps to exit 2.
- `uv run python -m scripts.check_ledger_rows_append_only --base main --head HEAD` (no `origin/main` in this sandbox):
  exit 0, `114 files checked`.
- History check, each commit against its parent: the last four first-parent commits on `main` pass. Commit `4e358955`
  (PR #314, before fragments existed) reports 116 `moved` rows at the tail of `executions.jsonl`: a real reorder from
  the legacy conflict era, already an ancestor of `main`, so it never is inside a future pull request's diff.
- Promotion simulation on a throw-away clone: `holon ledger promote --force` appended 1,969 rows and deleted 113
  fragments; the check against the pre-promotion commit passes (`116 files checked`).
- Residual risk: promotion skips a fragment row whose identity is already in the canonical file; if such a row differs
  in text from the canonical copy, the deleted fragment is reported as `fragment removed` (verbatim check only, by
  design, since the scripts must not import `sandbox_executor`).
