## Plan Description & Strategy

Add a standard-library CI script, `scripts/check_module_budget_label_actor.py`, in four layers:

1. **Changed-path probe (local git, no network):** `git diff --name-only <base>...<head>` decides whether
   `holon-config/hygiene/module_budgets.json` changed. If the config did not change, the script exits 0 before any token
   or API use. If git fails, the config counts as changed.
2. **Thin API functions:** `fetch_issue_events(...)` (paginated `GET /repos/{repo}/issues/{number}/events`) and
   `fetch_collaborator_permission(...)` (`GET /repos/{repo}/collaborators/{login}/permission`). They are the only code
   that touches the network, through an injectable `Opener`.
3. **Pure decision functions:** `active_label_event(events, label)` returns the latest `labeled` event for
   `module-budget-change` that has no later `unlabeled` event for it, plus the reason when there is none (missing, or
   removed). `label_actor_refusal(event, permission)` returns `None` when the actor is a `User` with `admin` permission,
   and a reason otherwise (`Bot`, or a non-admin naming the permission). `refusal_message(reason)` names the file, the
   label and the reason.
4. **`main(argv, environ, opener)`:** parses `--pr`, `--repo`, `--base` and `--head`, reads `GITHUB_TOKEN` from the
   environment, then composes the layers above and returns the exit code.

The hygiene job gets one new step right after "Check module budgets", with the standard bookkeeping guard. Its `run:`
block runs the script only when `$GITHUB_EVENT_NAME` is `pull_request`. The job's permissions gain `issues: read` and
`pull-requests: read`. A new test module covers the decision matrix, the no-API path, the workflow wiring and network
isolation.

### Implementation Details (No code blocks, only logic/steps)

1. Module constants:
   - `BUDGET_CONFIG = "holon-config/hygiene/module_budgets.json"`
   - `BUDGET_CHANGE_LABEL = "module-budget-change"`
   - `API_ROOT = "https://api.github.com"`

   Standard library only (`argparse`, `json`, `subprocess`, `sys`, `urllib.request`, `urllib.error`). Add
   `from __future__ import annotations`. Do not import from `scripts.ci_timing_gate`: the step runs the file path
   directly, and a self-contained module keeps the network-isolation test simple.

2. Changed paths (no network):
   - `changed_paths(base, head) -> list[str] | None` runs `git diff --name-only <base>...<head>` with
     `check=False, capture_output=True, text=True`. It returns `None` on `OSError` or a non-zero exit.
   - `config_may_change(paths) -> bool` returns `True` when `paths is None` (fail closed) or when `BUDGET_CONFIG` is
     among them.
3. Thin API functions. These are the only functions that may reference `urllib`, `urlopen` or the opener:
   - `build_request(url, token)`: `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, and
     `Authorization: Bearer` through `add_unredirected_header`, with a `# why:` comment: an unredirected header never
     follows a redirect to another host.
   - `default_opener(request)`: `urlopen` with the timeout, returns the body.
   - `fetch_issue_events(repo, number, token, opener) -> list[dict]`: loops `issues/{number}/events?per_page=100&page=N`
     from page 1 and stops when a page holds fewer than `PAGE_SIZE` entries. It raises `ValueError` when an answer is
     not a JSON array.
   - `fetch_collaborator_permission(repo, login, token, opener) -> str`: returns the `permission` field, and returns
     `"none"` on `HTTPError` 404 (not a collaborator). Any other error propagates. URL-quote the login.
4. Pure decision functions (no I/O). Each stays well within C901 10:
   - `label_events(events, label)` keeps the events whose `event` is `labeled` or `unlabeled` and whose
     `label.name == label`, in API order (chronological).
   - `active_label_event(events, label) -> tuple[dict | None, str]`:
     - No matching events: `(None, "the label was never applied")`.
     - Last matching event is `unlabeled`: `(None, "the label was removed after it was last applied")`.
     - Otherwise: `(last labeled event, "")`.
   - `label_actor_refusal(event, permission) -> str | None`:
     - Actor `type` is not `User`: `"applied by <login>, an actor of type <type>, not a User"` (covers `Bot`).
     - Permission is not `admin`: `"applied by <login>, whose permission is '<permission>', not 'admin'"`.
     - Otherwise `None`.
   - `refusal_message(reason) -> str`:
     `"<BUDGET_CONFIG> changed, but the '<label>' label does not authorise it: <reason>"`, ending with the rule that
     only a repository administrator's label authorises a budget change.
   - `actor_login(event)` returns the actor's login, or an empty string.
5. `check(repo, number, token, opener) -> str | None` composes the steps above. It fetches events, picks the active
   event and returns the refusal reason. It fetches the permission only when the actor is a User, which saves one call
   for bots.
6. `main(argv=None, environ=os.environ, opener=default_opener) -> int`:
   - Parse `--pr` (int), `--repo`, `--base` and `--head` with argparse (or a small `parse_arguments` helper).
   - If `config_may_change(changed_paths(base, head))` is False: print a one-line notice and return 0, with no token
     read and no API call.
   - An empty token returns 1 with a message naming the missing `GITHUB_TOKEN`.
   - Otherwise run `check`. On a refusal, print `refusal_message` to stderr and return 1. On success, print the
     authorising admin's login and return 0.
   - Wrap `urllib.error.URLError` and `ValueError`/`KeyError`/`TypeError` from answer parsing into exit 1 with a message
     that never contains the token.
7. Add `if __name__ == "__main__": sys.exit(main())`.
8. No docstrings and no comments except `# why:` comments. Keep `main` under PLR0913 (3 parameters). Run
   `uv run ruff format`.
