## Summary

Plan `P-1795493435-CLA-CF5.2` is implemented in full (Steps 1 to 6, one commit per step). The stored tier of claude
credential discovery now reads only the OS secret store: the macOS keychain through `security`, the Linux Secret Service
through `secret-tool`, service `holon`, account `claude-oauth-token`. No discovery path opens
`~/.holon/secrets/claude-oauth-token` any more. Pre-flight imports an existing plaintext file once (token on standard
input, read-back, delete only after an identical read-back, never an overwrite of a different entry) and otherwise fails
closed with the store one-liner of the platform and `claude setup-token`. Explicit `CLAUDE_CODE_OAUTH_TOKEN` and
`ANTHROPIC_API_KEY` and the layered `HOLON_AGENT_OAUTH_TOKEN` keep their precedence. The generated `.env.example`, the
environment reference, both agent credentials documents and the package README describe the keychain and the migration.

Verification: the affected run and the full suite pass (`6605 passed, 7 skipped`), and `uv run task lint` passes. Three
points need the reader's attention; details are in `## Tests Run` and `## Open Items`:

- `uv run task lint-docs` exits `1` because of 36 files under `plans/` that this branch does not touch. The five
  Markdown files this branch changed pass prettier.
- The full suite failed twice during collection in this sandbox (`import file mismatch` for identical paths, different
  files each time, no test executed) and passed once the bytecode cache was moved off the host-mounted checkout with
  `PYTHONPYCACHEPREFIX`. No repository file was changed for that.
- Neither `security` nor `secret-tool` exists in the execution environment, so the real tools were never called. Their
  contract is covered by the in-memory fake and by the run-time read-back only.
