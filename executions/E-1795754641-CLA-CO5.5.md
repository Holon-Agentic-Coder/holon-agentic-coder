## Steps Executed

### Step 1: Retry a rejected host push with bounded exponential backoff

- `flow/host_remote.py`: the one-shot push is now `push_commit_once`; `push_commit` retries it up to `PUSH_ATTEMPTS = 3`
  times, sleeping `PUSH_BACKOFF_SECONDS * 2 ** (attempt - 1)` (1 s, then 2 s) and logging each failure with
  `attempt N of 3` and the redacted remote output through an optional `log`.
- Permanent refusals are not retried: input-validation refusals, ref too long, missing workflow scope and (beyond the
  plan) stale-tip refusals (`non-fast-forward`, `fetch first`), because a retry cannot succeed without a fetch and
  existing non-fast-forward tests would otherwise pay 3 s of backoff each.
- `push_branch` and `publish_new_child_branches` forward `log`; `_pin` in `execution_recovery.py` uses
  `push_commit_once` so the best-effort recovery pin adds no retry delay.
