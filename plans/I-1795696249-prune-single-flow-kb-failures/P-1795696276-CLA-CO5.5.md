## Plan Description & Strategy

The plan adds one focused, standalone maintenance script that classifies failure-mode KB files against the merged
execution ledger, plus a unit test module on small fixture trees. The script is run once with `--apply` on the branch
tree and the resulting deletions are committed. The whole change is verified against the acceptance criteria:

- the count delta equals the dry run;
- every kept file is byte-identical to `main`;
- `patterns/` and `wisdom/` are untouched;
- `make lint-json` passes;
- `load_index` builds;
- lint and the module budget check pass;
- tests are green.

No production module changes. The promotion guard already prevents new chatter. The script reuses
`REVIEW_ACTION_ID_PREFIXES` from `sandbox_executor.knowledge.promotion_rules`, so "review row" keeps one definition. It
also reuses `read_merged_rows` from `sandbox_executor.ledger.merged`, so pending ledger fragments count as ledger rows
exactly as the rest of the system counts them. Neither import touches entrypoints or the flow engine.

### Implementation Details (No code blocks, only logic/steps)

1. Module docstring. Explain the purpose (one-off, repeatable clean-up for intent `I-1795696249`), the classification
   rule (the four conditions in the Strategy Rationale), and that the ledgers are only read. Give usage:
   `uv run python scripts/prune_kb_single_flow_failures.py [--repo DIR] [--apply]`. Follow the style of
   `scripts/migrate_plan_layout.py`.
2. Constants:
   - `FAILURE_MODES_DIR` = `holon-knowledge/kb/failure_modes`
   - `EXECUTIONS_LEDGER` = `holon-knowledge/ledger/executions.jsonl`
   - the file glob `KB-failure-*.json`
   - a compiled regex for an intent root, `I-\d+(?:-[^/\s]*)?`. It must match inside `"Failure mode in I-…/…"`, which
     the private `_flow_key` regex does not, because that regex anchors on start or `/`.
3. `load_review_roots(repo) -> dict[str, str | None]`. Call `read_merged_rows` on the canonical executions ledger (this
   includes `pending/executions/*.jsonl`). Map each row's `action_id` to the intent root parsed from the row's `target`,
   or `None`. Map only rows whose `action_id` starts with `REVIEW_ACTION_ID_PREFIXES`. A ref that maps to a non-review
   row cannot occur, because the ref id itself must already carry a review prefix. A malformed ledger line is passed to
   an `on_bad_line` handler that counts it. The run then refuses `--apply` (exit code 2), because an unreadable ledger
   could hide a second root.
4. A frozen dataclass `Verdict` with `path`, `prune: bool` and `reason: str`. The reasons are:
   - `single-flow-chatter`
   - `unreadable`
   - `no-refs`
   - `non-review-ref`
   - `no-resolved-ref`
   - `no-intent-root`
   - `multiple-intent-roots`
5. `classify_failure_file(path, review_roots) -> Verdict`. It applies the rule in order:
   - Parse the JSON. On an `OSError` or `ValueError`, keep the file (`unreadable`).
   - Read `evidence.ledger_refs`. Keep the file if the list is missing, not a list, or empty.
   - Keep the file if any ref is not a string or lacks a review prefix.
   - Compute `payload_root` from `payload.name`.
   - For each ref, take the resolved root if the ref is a key in `review_roots`. Otherwise use `payload_root` and count
     the ref as unresolved.
   - Keep the file if no ref resolved, if any root is `None`, or if there is more than one distinct root.
   - Otherwise prune it.

   Keep each helper under the ruff limits (C901 ≤ 10, PLR0912 ≤ 12) by splitting it into `_review_refs(envelope)`,
   `_payload_root(envelope)` and `_ref_roots(refs, review_roots, payload_root)`.

6. `classify_tree(repo) -> list[Verdict]`. Sort `failure_modes/KB-failure-*.json` by name and classify each file
   deterministically. It never touches `patterns/` or `wisdom/`.
7. `apply_prunes(verdicts, failure_dir) -> int`. For each pruning verdict, confirm that the path's parent resolves to
   `failure_dir`, that the path is a regular file and not a symlink, and that the name matches the glob. Then call
   `unlink()`. Return the count. Nothing is written or renamed.
8. `main(argv: Sequence[str] | None = None) -> int`. The `argparse` options are:
   - `--repo` (default: the repository root, derived from `Path(__file__).resolve().parents[1]`)
   - `--apply` (store_true)
   - `--list` (print each prunable path)

   The output is:
   - one summary line, `single-flow review chatter: N of T KB-failure files (dry run|deleted)`;
   - a kept breakdown, as one `kept <reason>: n` line per reason, sorted.

   Exit 0 on success. Exit 2 if bad ledger lines were seen while `--apply` was requested. When the failure-modes
   directory is missing, print `0 of 0` and exit 0.

9. Add `if __name__ == "__main__": raise SystemExit(main())`. Give every public function full type hints and a short
   docstring. Do not add `# noqa`.
10. Run `uv run ruff check scripts/prune_kb_single_flow_failures.py` and
    `uv run ruff format --check scripts/prune_kb_single_flow_failures.py` in the foreground. Confirm `wc -l` ≤ 400
    (target < 200).
