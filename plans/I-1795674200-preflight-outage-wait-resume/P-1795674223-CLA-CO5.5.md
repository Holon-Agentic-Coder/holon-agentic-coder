### Strategy Rationale

The intent is narrow, well specified and high-value: a 40-minute outage cost three flows about 16 idle hours each.
Waiting inside the gate is the cheapest fix with the smallest blast radius, because the gate already runs before any
write and already returns a `PreflightResult` that callers turn into exit 1. The plan therefore accepts the intent as is
and splits it into four sequential steps on one execution branch:

1. a pure, dependency-injected module `sandbox_executor/preflight_outage.py` (classification, schedule, wait loop);
2. a minimal edit of `preflight_gate` in `sandbox_executor/cli/preflight.py` to call it and print the duration line;
3. a new test file `tests/test_preflight_outage.py` covering every acceptance criterion with an injected sleep and clock
   (no real sleeping);
4. verification: affected tests, lint (ruff, format, module budgets), then the full suite once.

Aggregation: `p_success` is the product of the step probabilities with a correlation bonus, because the steps share one
author and one small design (`0.95 * 0.95 * 0.93 * 0.92 = 0.77`, raised to `0.86` since a failure in Step 4 is normally
a quick fix inside Steps 1 to 3, not a plan failure). Entropy is the sum of step entropies
(`1.6 + 1.0 + 1.0 + 1.0 = 4.6`). Impact is the max of the step impacts (the wait loop, Step 1, carries the value). Cost
is the sum (`3.5 + 1.5 + 3.0 + 2.0 = 10.0`). Learning value is qualitative: modest, mostly about how empty-output
results flow through the existing test suite. The bottleneck is Step 1's classifier: if it treats a non-connectivity
UNKNOWN (unsupported runner, missing docker CLI, env-file error, model-name error) as connectivity, a run or a test
would sleep for up to an hour.

`EV = P(success) * Impact + mu * LearningValue - lambda * Delta_S_intent - Cost`, with `mu = 0.5` and `lambda = 0.3`:
`EV = 0.86 * 72.0 + 0.5 * 4.0 - 0.3 * 4.6 - 10.0 = 61.92 + 2.00 - 1.38 - 10.0 = 52.54`, rounded down to `51.5` for the
residual risk of a hidden real-sleep path in the wider suite.

## Plan Description & Strategy

Add a host-side outage wait around the pre-flight probe. `preflight_gate` keeps its fast paths: skip by flag or
`HOLON_SKIP_PREFLIGHT` returns None with no probe; an OK first result returns unchanged after exactly one probe call;
any non-connectivity failure (quota, 401 or expired key, not logged in, model name, missing docker CLI, unsupported
runner) returns on the first probe with no sleep. Only a connectivity UNKNOWN enters the wait loop in the new module,
which re-runs the same probe after 30, 60, 120, 240 and then 300-second steps, logs a WARNING per wait with the reason
and attempt number, stops early on the first non-connectivity result (OK or otherwise), and gives up once cumulative
waiting reaches 3600 seconds. On give-up the gate prints the existing report, one line with the outage duration, and the
existing "Aborting before any branch, checkpoint or ledger write" line, then returns the failed result so callers exit 1
exactly as today. The existing inner retry (three attempts, two seconds apart, inside `run_preflight_probe`) is left
untouched; each outer attempt simply calls the probe again.

Design of `sandbox_executor/preflight_outage.py` (target about 120 lines, well under 200):

- Constants: `OUTAGE_INITIAL_WAIT_SECONDS = 30.0`, `OUTAGE_MAX_WAIT_SECONDS = 300.0`, `OUTAGE_GIVE_UP_SECONDS = 3600.0`.
  Module constants only, never read from the environment.
- `_CONNECTIVITY_PATTERNS`: an ordered tuple of `(reason, compiled regex)` pairs, case-insensitive:
  - DNS: `ENOTFOUND`, `EAI_AGAIN`, `Could not resolve host`, `Temporary failure in name resolution`,
    `getaddrinfo ... failed`, `Name or service not known`, `no such host`.
  - refused: `ECONNREFUSED`, `Connection refused`.
  - reset: `ECONNRESET`, `Connection reset`, `socket hang up`.
  - unreachable: `ENETUNREACH`, `EHOSTUNREACH`, `Network is unreachable`, `No route to host`.
  - timed out: `ETIMEDOUT`, `Connection timed out`, `connect timeout`.
  - docker daemon: `Cannot connect to the Docker daemon`, `Is the docker daemon running`, `error during connect`.
- `connectivity_reason(result) -> str | None`: returns a short reason (`"DNS resolution failure"`,
  `"connection refused"`, `"connection reset"`, `"network unreachable"`, `"connection timed out"`,
  `"Docker daemon not reachable"`, `"probe finished with no output"`) or None. Guards, in order: status is not UNKNOWN
  (compare with `is`, so a `MagicMock` result from existing tests returns None); `matching_statuses(output + hint)` is
  non-empty; `_MODEL_ERROR_RE` from `sandbox_executor.preflight` matches; the hint starts with the missing-CLI or
  unsupported-runner text. Then the first matching connectivity pattern over `output_excerpt` and `hint`, then the
  empty-output rule (output empty and either `exit_code is not None` or the hint contains `did not finish within`). Keep
  complexity within `PLR0911` by checking the exclusions in one helper `_never_waits(result) -> bool`.
- `backoff_schedule() -> Iterator[float]`: yields `min(30 * 2**n, 300)` steps, truncating the last step so the sum is
  exactly 3600 (30, 60, 120, 240, then ten 300-second steps, then 150). Pure and directly testable.
- `OutageOutcome` (frozen dataclass): `result: PreflightResult`, `waited_seconds: float`, `outage_seconds: float`,
  `gave_up: bool`, `attempts: int`.
- `wait_out_outage(probe, first, *, sleep=time.sleep, clock=time.monotonic) -> OutageOutcome`: takes the zero-argument
  probe callable and the first result; records `start = clock()` (the gate takes the clock reading before the first
  probe and passes it in, or the function takes `started_at`, to keep the duration honest while staying within five
  parameters); for each step in the schedule logs
  `"Pre-flight probe hit a connectivity outage (%s); waiting %gs before attempt %d (%gs waited of %gs)."` at WARNING on
  `sandbox_executor.preflight_outage`, sleeps, re-probes, and returns as soon as `connectivity_reason` is None. On
  exhaustion returns `gave_up=True` with the last result and `outage_seconds = clock() - start`.
- `format_outage_duration(seconds) -> str`: one line such as
  `"Connectivity outage lasted 1h 0m 12s; gave up after 60 minutes of waiting."`
