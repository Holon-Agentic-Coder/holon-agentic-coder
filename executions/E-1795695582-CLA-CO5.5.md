## Steps Executed

### Step 1: Add the shared RunnerSpec definition in runners/spec.py

- New `runners/spec.py` (about 50 lines): frozen `RunnerSpec` with `agent_id`, `image`, `default_model`, `ticker`,
  `api_key_env_vars` and a `credential_check` callable field (`repr=False, compare=False`); `check_credentials()`
  delegates to it.
- Helpers `has_api_key` (plain `os.getenv` truthiness, as in today's validate), `any_path_exists` (path as given or
  after `os.path.expanduser`, both through the `os` module so global `patch("os.path.exists")` still applies) and
  `generic_missing_message` (today's `_missing_credentials_message` text for non-claude agents). Imports only
  `local_llm`.

### Step 2: Add one spec module per agent and the runners registry

- `runners/antigravity.py`, `claude.py`, `pi.py`, `codex.py`, `opencode.py` each define one `SPEC` with the image,
  default model, ticker (`None` for codex and opencode) and accepted credential variables, plus a private
  `_check_credentials`. Messages, session paths and exemptions are copied from the pre-change `validate`: antigravity and
  codex keep their exact path probes (absolute paths as given, `~` paths expanded); claude and pi keep the double probe
  via `any_path_exists`; codex keeps the case-sensitive `HOLON_AGENT_OSS_MODE in ("true", "1")` exemption; pi keeps the
  local-LLM exemption and `PI_CODING_AGENT_DIR/models.json` first. The claude spec takes its variables from
  `CLAUDE_CREDENTIAL_ENV_NAMES`.
- `runners/__init__.py` exposes `RUNNER_SPECS` (order antigravity, claude, pi, codex, opencode), `runner_spec_for`
  (normalised with `local_llm.normalize_agent_id`) and re-exports `RunnerSpec`. Importing the package leaves
  `agent_defaults` and `agent_runner` out of `sys.modules` (checked with `uv run python -c ...`). Largest module: 52
  lines.

### Step 3: Derive AGENT_IMAGE_MAPPING, AGENT_TICKERS and DEFAULT_MODELS from the specs

- `agent_defaults.py` imports `RUNNER_SPECS` and builds the three tables as plain `dict[str, str]` comprehensions;
  `AGENT_TICKERS` skips specs whose ticker is `None`. Values and keys equal the previous literals (only the insertion
  order of `AGENT_TICKERS` now follows the registry; its only reader, `naming.py`, sorts or uses `.get`).
- `RUNNER_CAPABILITIES`, model resolution, `_RUNNER_API_KEY_ENV_VARS` and `_detect_session_dir_present` untouched.
- `agent_defaults.py`: 494 to 481 lines. `uv run pytest tests/test_agent_defaults.py tests/test_naming.py
  tests/test_gemini_runner_purged.py`: `81 passed in 0.84s`.

### Step 4: Make StandardAgentRunner.validate delegate to the agent's spec

- `validate` now calls `resolve_credentials()`, looks up `runner_spec_for(self.agent_id)`, returns for an unregistered
  id, and otherwise prints `spec.check_credentials()`'s error to stderr and calls `sys.exit(1)`. Its `# noqa: C901` is
  gone; no agent-id comparison remains in it.
- Removed the `custom_validator` parameter/attribute from `StandardAgentRunner` and all subclasses, and removed
  `AgentRunner._missing_credentials_message` (text now in the specs). `PiAgentRunner`, `ClaudeAgentRunner` and
  `OpenCodeAgentRunner` default `required_keys` to their spec's `api_key_env_vars`. Dropped the now-unused
  `claude_keychain` and `CLAUDE_CREDENTIAL_ENV_NAMES` imports.
- Behaviour note: credential checks are now owned by the spec, so a registered runner constructed with an empty
  `required_keys` is still checked (no caller or test does this; previously pi/claude/opencode skipped the check then).
- `agent_runner.py`: 779 to 688 lines. `uv run pytest tests/test_agent_runner.py tests/test_claude_credential.py
  tests/test_gemini_runner_purged.py tests/test_local_llm.py`: `168 passed, 2 skipped, 557 subtests passed in 0.90s`.

### Step 5: Pin the specs, the derived views and the credential behaviour with tests

- New `tests/test_runner_specs.py` (45 tests): registry keys and order, `runner_spec_for` normalisation, frozen specs,
  every image present as a `tags = [...]` entry in `docker-bake.hcl` and every agent id as a case label in
  `entrypoint/role_dispatcher.sh` (both only read), a subprocess import check that `agent_defaults` and `agent_runner`
  stay out of `sys.modules`, and a hermetic credential matrix (environment cleared, `HOME` at `tmp_path`,
  `os.path.exists` patched): exact missing-credential message per agent, `HOLON_AGENT_KEY` accepted (claude rejects it
  and accepts `CLAUDE_CODE_OAUTH_TOKEN` / `ANTHROPIC_API_KEY`), empty key rejected, each of the 15 session paths,
  opencode has no session path, codex OSS mode (`true` and `1` pass, `TRUE` and `yes` do not), pi local-LLM exemption
  (needs `HOLON_LOCAL_LLM` plus base URL or `PI_CODING_AGENT_DIR`; pi only) and `PI_CODING_AGENT_DIR/models.json`.
- `tests/test_agent_defaults.py`: one test pinning the literal values of the three tables and their equality with the
  comprehensions over `RUNNER_SPECS`.
- `tests/test_agent_runner.py`: `validate` source has no `custom_validator`, `agent_id ==`, `agent_id in` or `norm_id`;
  parametrised test that each registered runner with no credentials prints the spec message to stderr and exits 1.
  Existing assertions unchanged.
