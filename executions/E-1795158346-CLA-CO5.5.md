### Step 2: Add the shared HEAD guard module `worktree_head.py`

- New `apps/sandbox-executor/src/sandbox_executor/worktree_head.py` at package top level (imports only `git.run_git`
  and `redaction.redact_agent_secrets`, so no entrypoint→flow edge).
- `HeadState` (`on_branch`, `detached_at_tip`, `detached_elsewhere`), `read_head_state`, and `reattach_branch`
  returning `ReattachOutcome` (`ON_BRANCH`, `REATTACHED`, `REFUSED` with a message). The re-attach is
  `git symbolic-ref -m ... HEAD refs/heads/<branch>` on exact SHA equality only; every other state is refused.
- `head_guard(repo_dir, branch, step_label, log, run)`: armed only when the branch is checked out before the block; on
  exit it logs the step that moved HEAD and re-attaches, recording a refusal in the yielded `HeadGuardReport`. It never
  raises and never replaces the block's exception.
- `restore_branch(...)` (host side, an addition to the plan's helper list): the same repair, then a plain non-forcing
  `git checkout <branch>` when the re-attach is refused; it leaves an unreadable HEAD or a missing local branch alone,
  so test contexts whose worktree is not a git repository see no change.
- Every git call takes an injectable `run` seam; ruff passes with no `noqa`.
