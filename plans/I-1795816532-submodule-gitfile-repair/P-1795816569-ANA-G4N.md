## Plan Description & Strategy

Introduce a dedicated, dependency-light module `apps/sandbox-executor/src/sandbox_executor/submodule_gitfile.py` that
inspects `.gitmodules` entries in a repository or linked worktree, detects any submodule `.git` gitfile or module
`core.worktree` setting whose target is unresolvable or non-relative (such as container mount paths left behind by role
containers), resolves the authoritative module gitdir via `git rev-parse --git-path modules/<name>`, and rewrites both
the gitfile `gitdir:` line and the module config's `core.worktree` to POSIX-normalized relative paths. Whenever a broken
submodule gitfile cannot be resolved or rewritten, the helper returns a clear error naming the offending gitfile path.

Wire this helper into two layers:

1. **Container-side repair (`entrypoint/executor/repair.py`):** `_probe_git_repo` detects broken or non-relative
   submodule gitfiles/worktree paths, and `_repair_git_repo` repairs them so mounted worktrees leave the container with
   host-valid relative paths.
2. **Host-side Stage 4 and Stage 5 pre-checkout guards (`flow/stages/review.py` and `flow/stages/calibrate.py`):**
   `_checkout_execution_branch` in `review.py` runs submodule gitfile repair before `reattach_branch` checks whether
   HEAD is already on the execution branch, and `_prepare_execution_branch` in `calibrate.py` guards before calibration
   checkout, failing the stage cleanly with the offending path if repair fails.

Finally, add hermetic tests in `test_executor_repair.py`, `test_review_keeps_branch.py`, and `test_calibrate.py`
covering both repair and fail-closed rejection (including when already on the execution branch), and run foreground
pytest, lint, and docs-lint checks.

3. Implement submodule discovery from `<repo_dir>/.gitmodules`:
   - If `<repo_dir>/.gitmodules` does not exist, return an empty list without spawning git.

     broken with the offending path `<rel_path>/.git`.
   - Resolve the recorded `gitdir:` target against `<repo_dir>/<rel_path>` (if relative) or directly (if absolute).
   - Detect whether the gitfile is broken or drifted: either the resolved target is not an existing directory on disk,
     or (when `require_relative=True`) the raw `gitdir:` value is an absolute path, or `core.worktree` in
     `<resolved_gitdir>/config` is set to an unresolvable path or (when `require_relative=True`) an absolute path.
5. Implement module gitdir resolution via `git rev-parse --git-path modules/<name>` (run with `cwd=repo_dir`):
   - If the output is relative, resolve it against `repo_dir`.
   - Verify the resolved directory exists (if not, check whether `git rev-parse --git-common-dir` + `modules/<name>`
     exists as a linked-worktree fallback).
   - If no valid module gitdir directory exists on disk, return a clear error message naming the offending gitfile path
     (e.g.,
     `submodule gitfile '<rel_path>/.git' points to unresolvable gitdir ... and module gitdir could not be resolved`).
6. Implement repair for each broken/drifted submodule:
   - Compute the POSIX relative path from `<repo_dir>/<rel_path>` to `<module_git_dir>` via `os.path.relpath` and
     convert path separators to `/`.
   - Write `gitdir: <rel_gitdir>\n` to `<repo_dir>/<rel_path>/.git`.
   - Compute the POSIX relative path from `<module_git_dir>` to `<repo_dir>/<rel_path>` and update `core.worktree` in
     `<module_git_dir>/config` via `git config --file <module_git_dir>/config core.worktree <rel_worktree>` using the
     injected `run` callable.
   - If writing the gitfile or updating `core.worktree` fails, return a clear redacted error naming `<rel_path>/.git`.
7. Expose clean public helpers:
   - `find_broken_submodule_gitfiles(repo_dir: str, *, require_relative: bool = False, run: GitRunnerCallable | None = None) -> list[str]`
     (for probing in `repair.py`).
   - `repair_submodule_gitfiles(repo_dir: str, *, require_relative: bool = False, run: GitRunnerCallable | None = None) -> SubmoduleRepairResult`
     (for both container repair and host Stage 4/Stage 5 pre-checkout guards).
8. Environment Overlay Discipline note: updating `core.worktree` in `<module_git_dir>/config` and rewriting
