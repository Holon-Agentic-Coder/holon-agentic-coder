### Strategy Rationale

The intent is accepted as-is (`ACCEPT_AS_IS`). Currently, `RUNNER_CAPABILITIES` in
`apps/sandbox-executor/src/sandbox_executor/agent_defaults.py` lists `"fable"` under `claude-opus-5-5`
(`aliases=["opus", "claude-opus", "fable"]`), and `resolve_model()` returns the raw input string without normalising
aliases to their canonical model ID. Consequently, `--model fable` silently resolves to Opus when normalised or fails to
display the canonical ID in `holon doctor` and the resolved-model log line, while `holon models` omits
`claude-fable-5-2` entirely.

The strategy executes in three tightly scoped, sequential steps:

1. Update `agent_defaults.py` (and `cli/commands/doctor.py` / `cli/commands/models.py` as needed) to add the
   `claude-fable-5-2` capability entry for `claude-agent` with `aliases=["fable", "claude-fable"]` before
   `claude-opus-5-5`, remove `"fable"` from `claude-opus-5-5` aliases, and update `resolve_model()` so that recognised
   aliases resolve to `canonical_model` while recording the alias in the resolution reason (and `holon doctor` /
   resolved-model log lines display both the canonical ID and the alias when they differ).
2. Add the family-word invariant test in `apps/sandbox-executor/tests/test_model_alias_families.py` and update
   `test_agent_defaults.py` and `test_models_cli.py` to cover `claude-fable-5-2` resolution, `holon models` text/JSON
   output, and alias-aware `resolve_model` / `holon doctor` reporting.
3. Update `docs/agents.md` to document model alias resolution and canonical model reporting in the runner and model
   resolution section, and run the full verification suite (`uv run pytest`, `uv run task lint`,
   `uv run task lint-docs`).
