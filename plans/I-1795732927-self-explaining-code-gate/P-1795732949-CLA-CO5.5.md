## Plan Description & Strategy

The change is one executable plan of seven steps on the plan branch; no sub-intents. The gate is split into three small
modules under `scripts/` so each stays far below the 400-line default budget and every function stays within the ruff
complexity limits:

1. `scripts/self_explaining_diff.py` finds the added lines: which files changed and which line numbers in each file are
   new, against `git merge-base HEAD origin/main` (working tree, plus untracked files as wholly added) or, with
   `--staged`, against `HEAD` using the index content.
2. `scripts/self_explaining_comments.py` finds comments and docstrings in a file's text, per language: Python via `ast`
   (docstring spans) and `tokenize` (COMMENT tokens), `#` languages (shell, Makefile, Dockerfile, YAML, TOML) via a
   quote-aware line scanner, JavaScript via a small state machine for `//`, `/* */` and `/** */`. It also owns the
   allowlist (`# why:`, shebang, encoding line, `# noqa`, `# type:`, `# pragma`, `# fmt:`, `# shellcheck`).
3. `scripts/check_self_explaining.py` is the CLI: it intersects the two, prints one `path:line: kind` line per
   violation, and exits 1 on any, 0 otherwise, and 0 with a notice when there is no merge base.

The check is then wired into the lint task, the staged mode of `scripts/pre_commit_check.py` and a named step in the
hygiene workflow; the four prompt templates gain the invariant, and tests cover the gate and the prompt phrases.

Self-application is the dominant risk: every line this change adds is itself scanned by the new gate in CI (and by
`task lint` once the lint task runs it). All added Python (the three scripts, the edit to `pre_commit_check.py`, both
test files), the added `pyproject.toml` line and the added workflow step therefore carry no docstring and no comment.
Test fixtures that need comments or docstrings build them inside string literals, which the gate (via `tokenize`)
correctly ignores; the new test module has no module docstring. Existing docstrings and comments are left untouched.

### Implementation Details (No code blocks, only logic/steps)

- Add a frozen dataclass for one changed file: repository-relative path, the frozenset of added line numbers, and the
  file text to scan.
- Add a `run_git(root, *args)` helper returning the completed process or `None` on `OSError` (same shape as
  `module_budget_freeze.run_git`; reuse that function by import with the same
  `try: from scripts.x ... except ImportError: from x` pattern `check_module_budgets.py` uses, rather than duplicating
  it).
- Add `merge_base(root)`: `git merge-base HEAD origin/main`; `None` when git fails (no remote, shallow clone, no common
  ancestor). Callers treat `None` as "skip quietly with a notice".
- Add `added_line_numbers(diff_text)`: parse `git diff -U0` output; for each `+++ b/<path>` header start a file; for
  each `@@ -a,b +c,d @@` hunk add `range(c, c + d)` (a missing `,d` means 1; `d == 0` adds nothing). Ignore

- Branch mode: `git diff -U0 --no-color --no-ext-diff --diff-filter=ACMR <base>` (working tree against the merge base,
  so uncommitted work is checked too) and read each file's text from disk; then add untracked files from
  `git ls-files --others --exclude-standard` with every line counted as added.
- Staged mode: `git diff --cached -U0 --no-color --no-ext-diff --diff-filter=ACMR` and read the text from the index with
  `git show :<path>`, so a partially staged file is judged by what is committed.
- Skip files that cannot be decoded as UTF-8 (binary) silently.
- Write no docstrings and no comments in this module (it is itself added code). Names carry the meaning: `merge_base`,
  `added_line_numbers`, `changed_files_against_merge_base`, `staged_changed_files`.

## Step 2: Add the comment and docstring finders `scripts/self_explaining_comments.py`

- **Sub‑intent recommendation:** NO
- **Reasoning:** The riskiest logic (false positives on `#` in strings), but it is pure, text-in and findings-out, and
  fully unit-testable without git; splitting it into a child intent adds overhead without lowering risk.
- **Step Type:** IMPLEMENTATION
- **Exploration level:** EXPLOIT

### Intent & Git Integration

- **Step Intent:** Given a path and its text, return every comment or docstring as `(line, kind, text)`, with machine
  directives and `why:` reasons already excluded.
- **Git branch:** plan branch, same commit series
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

- Language from the path: `.py` is Python; `.sh`, `.bash`, an extensionless file whose first line is a `sh`/`bash`
  shebang, `Makefile`, `GNUmakefile`, `*.mk`, `Dockerfile`, `Dockerfile.*`, `*.dockerfile`, `*.yml`, `*.yaml` and
  `*.toml` are hash languages; `.js`, `.mjs`, `.cjs` are JavaScript; anything else returns no findings (Markdown, JSON
  and JSONL are never scanned).
- Python docstrings: `ast.parse` the text; for the module and every `ClassDef`, `FunctionDef` and `AsyncFunctionDef`,
  when the first body statement is an `Expr` holding a `str` `Constant`, emit one finding of kind `module docstring`,
  `class docstring` or `function docstring` spanning `lineno..end_lineno`. A `SyntaxError` yields no docstring findings
  (ruff reports the syntax error).
- Python comments: `tokenize.generate_tokens` over the text; every `COMMENT` token is a candidate with its start line.
  Strings never produce `COMMENT` tokens, so `"#"` and `'# not a comment'` are never reported. A `TokenizeError` falls
  back to no comment findings for that file.
- Hash languages: scan each line left to right tracking single and double quotes (and a backslash escape); a `#` outside
  quotes that starts the line (after optional whitespace) or follows whitespace starts a comment running to the end of
  the line. This keeps `$#`, `${#var}`, `\#` in Makefiles and URL fragments like `a.html#x` from counting.
- JavaScript: one state machine over the whole text with states code, single quote, double quote, template literal, line
  comment and block comment; emit `//` comments with their line, and `/* */` and `/** */` (JSDoc) comments with their
  full line span.
- Allowlist, applied to the comment text with its marker and leading whitespace stripped: starts with `why:`; starts
  with `noqa` (bare or with codes such as `noqa: E501`), `type:`, `pragma`, `fmt:` or `shellcheck`; a `#!` shebang on
  line 1; an encoding line on line 1 or 2 matching the PEP 263 pattern `coding[:=]`. Keep the prefixes in one
  module-level tuple named `MACHINE_DIRECTIVE_PREFIXES` and the reason prefix in `REASON_PREFIX = "why:"`.
- Keep each function small (one per language plus `is_allowed_comment`) so C901, PLR0912 and PLR0915 hold without any
  `# noqa`. No docstrings, no comments.

### Dependencies & Criticality

- **Depends on:** NONE

### Safety & Constraint Considerations

- **Relevant rules:** ruff complexity limits in `pyproject.toml` (`C901 <= 10`, `PLR0912 <= 12`, `PLR0913 <= 5`,

- **Discard:** If the quote-aware scanner shows more than a handful of false positives across the tracked tree, narrow
