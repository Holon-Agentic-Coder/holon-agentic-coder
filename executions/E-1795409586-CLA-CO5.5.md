### Step 3: Launcher attach-only path

- `launcher/sidecar.py::get_token_reduction_mounts_and_envs` takes `proxy_attach: bool = False`. Without an opt-in and
  without an explicit opt-out it calls `proxy_attach._attach_external_proxy()` (via `_attach_running_proxy`), never
  `setup_token_reduction_proxy`. The spawn/attach selection for opt-ins moved unchanged into
  `_opted_in_mounts_and_envs` to stay within the complexity limits. The new keyword shadows the `proxy_attach` module
  inside the function, which is why the module call goes through a module-level helper.
- `launcher/containers.py` (`ContainerLaunchOptions`, `ContainerLaunch`) and `launcher/role_dispatch.py`
  (`RoleLaunchOptions`, forwarded only when truthy) carry the keyword. Network isolation stays keyed on `token_reduce`.
- `flow/dispatch.py` adds `proxy_attach=True` to the dispatched kwargs only when the context sets it.
- Teardown in attach mode is a no-op: `teardown_token_reduction_proxy` only removes what `_sidecar_state` recorded,
  and the attach path records nothing.
