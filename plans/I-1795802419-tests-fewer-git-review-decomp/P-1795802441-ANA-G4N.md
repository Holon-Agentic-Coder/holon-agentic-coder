### Strategy Rationale

The intent targets the five remaining git-heavy unit test files (`test_sync_points.py`, `test_ledger_commit.py`,
`test_loop.py`, `test_decomposition.py`, and `test_approval_fingerprint.py`) to cut git subprocess spawns by at least
30% with measurable wall-clock time reduction and zero production-code changes. Inspecting all five files and the
existing test infrastructure reveals four high-leverage, low-risk optimizations that require no new production code:

1. **Template-backed `build_flow_worktree`** (`review_flow_repo.py` -> `test_ledger_commit.py` and `test_loop.py`):
   `build_flow_worktree` currently spawns 10 git processes per call across 16 cases in `test_ledger_commit.py` and 7
   cases in `test_loop.py` (~230 setup git spawns). Adding a `shared_template` + `copy_template` helper
   (`flow_worktree_copy`) reduces setup to 3 git spawns once per session.
2. **Template-backed `sync_work` / `flow_history_copy`** (`test_sync_points.py`): 9 test functions (10 cases, including
   3 separate repos in `test_prepare_execution_branch_syncs_before_calibrated_and_retry_reanchors`) build fresh repos
   via `build_flow_repos` + `commit_on` / `_inject_ledger_conflict`. Switching initial repo setups to
   `tests.flow.sync_boundary_repos.sync_work` and `flow_history_copy` eliminates ~250+ setup git spawns while keeping
   post-sync mutations in the test bodies.
3. **Overlap deduplication and `stage_start` templates** (`test_decomposition.py`):
   `test_explicit_sub_intent_list_runs_child_pipelines_in_order_and_records_each_child_pr` (3 full pipelines) overlaps
   heavily with `test_child_that_itself_decomposes_in_the_same_second_gets_its_own_branches_and_lists_its_children` (5
   full pipelines). After Step 1 proves subset line coverage via `--cov-context=test`, folding all assertions into the
   surviving 2-level scenario eliminates an entire 3-pipeline run, and starting later-stage tests from
   `stage_start("plan", ...)` skips redundant Stage 1–2 git work.
4. **Batched `git fast-import` DAG construction** (`test_approval_fingerprint.py`): The 17-example Hypothesis property
   test currently runs ~15–35 git spawns per example (`checkout`, `add`, `commit`, `push`, `_merge_target_ledger_only`).
   Building each example's entire disjoint merge DAG in a single `git fast-import` call (plus one dedicated real
   `_merge_target_ledger_only` test to preserve merge-helper coverage and mutation score) and batching the 14
   bookkeeping/reviewable path cases onto one `fast_import` repo cuts ~400+ git spawns with zero loss of defect-finding
   coverage.
