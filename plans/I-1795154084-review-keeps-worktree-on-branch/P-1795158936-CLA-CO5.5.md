## Plan Description & Strategy

Stage 4 must hand the shared flow worktree back on the execution branch, whatever moved HEAD. The resolver and the
review-loop container must re-attach a HEAD detached exactly at the branch tip without touching the index or the working
tree, and must refuse any other detached HEAD with a message naming both SHAs. The design comes from the previous
execution, which passed every gate:

1. A new package-level module, `sandbox_executor/worktree_head.py`, owns the HEAD logic. It holds the state
   (`on_branch`, `detached_at_tip`, `detached_elsewhere`) and `reattach_branch`, which runs
   `git symbolic-ref HEAD refs/heads/<branch>` only when the SHAs match exactly. It also holds `head_guard`, a context
   manager that logs the step that moved HEAD and repairs it, and `restore_branch`, the host-side repair with a
   non-forcing `git checkout <branch>` fallback. The module imports only `git` and `redaction`, so no entrypoint to flow
   import edge is added.
2. Container side (`entrypoint/review_loop.py`): workspace validation re-attaches a branch target that is detached at
   its tip, or refuses with a clear message. The reviewer ensemble and the resolver turn each run inside `head_guard`.
   The resolver fails closed (nothing committed) when the repair is refused.
3. Host side (`flow/stages/review.py`): `run_review_stage` becomes a thin `try/finally` wrapper around
   `_run_review_stage_body`, which keeps the existing `noqa`, and the wrapper calls `restore_branch`.
   `_checkout_execution_branch` tries `reattach_branch` before its plain checkout. In `flow/calibrate_sync.py`,
   `record_starting_branch` records a start detached at the execution tip as the branch, so the pipeline exit never
   re-detaches it.
4. A prompt rule in `review_loop.template.md` and in the resolver prompt forbids moving HEAD in the shared worktree.
   `git checkout <rev> -- <path>` stays allowed for the lockfile rule.
5. Hermetic tests use real git in `tmp_path`, plus a static scan for bare-commit checkouts in the review-stage modules.

The previous execution branch is still present locally, so Steps 1–3 port its diff file by file with
`git diff <prev-exec>~ -- <path>` or `git checkout <prev-exec> -- <path>` against this plan's execution branch. Each
port is limited to touch-set paths, and each file is re-read before it is committed. If the branch is gone, the same
design is re-implemented from this description. The `test_decomposition.py` follow-up is now declared (ruleset §3: test
changes must be declared in the plan).
