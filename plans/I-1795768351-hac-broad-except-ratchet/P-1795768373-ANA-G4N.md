## Plan Description & Strategy

Implement a single, self-contained, fast AST-based ratchet test module at
`apps/sandbox-executor/tests/test_broad_except_ratchet.py`. The module defines pure helper functions to parse Python
source text with `ast.parse`, count broad `except Exception` handlers per module and per package under
`apps/sandbox-executor/src/sandbox_executor/`, and evaluate actual counts against locked per-module and per-package
ratchet ceilings (`actual <= cap`).

The module stores:

1. `MODULE_BROAD_EXCEPT_BASELINES: dict[str, int]` mapping each POSIX relative module path (relative to
   `apps/sandbox-executor/src/sandbox_executor/`) that currently has at least one broad `except Exception` catch to its
   exact baseline count. Any scanned module not listed has an implicit cap of `0`.
2. `PACKAGE_BROAD_EXCEPT_BASELINES: dict[str, int]` mapping each package directory relative to
   `apps/sandbox-executor/src/sandbox_executor/` (using `""` for the root `sandbox_executor` package, matching
   `test_self_doc_modules.py` convention, and `"calibration"`, `"cli"`, `"cli/commands"`, `"entrypoint"`,
   `"entrypoint/executor"`, `"flow"`, `"flow/github"`, `"flow/review"`, `"flow/stages"`, `"knowledge"`, `"launcher"`,
   `"ledger"`, etc.) to the sum of its modules' baseline counts. Any scanned package not listed has an implicit cap of
   `0`.

Ratchet evaluation is strictly upper-bounded (`actual <= baseline`): counts equal to or below baseline pass cleanly so
follow-up narrowing PRs can lower catches without breaking CI before tightening the baseline table, while any increase
above a module cap, any increase above a package cap, or any new broad catch in an unlisted module/package fails CI with
an actionable diff listing offending modules, packages, actual counts, and baseline caps.

### Intent & Git Integration

- **Step Intent:** Create `apps/sandbox-executor/tests/test_broad_except_ratchet.py` with the AST broad-`Exception`
  counter, package aggregation, locked per-module and per-package baseline tables, and live repository ratchet tests.
- **Git branch:** I-1795768351-hac-broad-except-ratchet
- **Sub-intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Define `PACKAGE_DIR = Path(__file__).resolve().parents[1] / "src" / "sandbox_executor"` to locate the target source
   tree.
2. Implement `_is_broad_exception_type(expr: ast.expr | None) -> bool`:
   - Return `False` when `expr is None` (bare `except:` is distinct from `except Exception`; keep matcher strictly
     focused on broad `Exception` catches).
   - Return `True` when `expr` is `ast.Name` with `expr.id == "Exception"`.
   - Return `True` when `expr` is `ast.Attribute` with `expr.attr == "Exception"` and `isinstance(expr.value, ast.Name)`
     with `expr.value.id == "builtins"`.
   - Return `any(_is_broad_exception_type(elt) for elt in expr.elts)` when `expr` is `ast.Tuple`.
   - Return `False` for all other AST nodes (so `http.client.HTTPException`, `ValueError`, `BaseException`, etc. are not
     counted as `except Exception`).
3. Implement `count_broad_except_in_source(source: str) -> int` using `ast.parse(source)` and `ast.walk(tree)` to count
   all `ast.ExceptHandler` nodes where `_is_broad_exception_type(node.type)` is `True` (this naturally covers both
   `try/except` and `try/except*`).
4. Implement `scan_package_broad_except_counts(package_dir: Path) -> tuple[dict[str, int], dict[str, int]]`:
   - Walk `sorted(package_dir.rglob("*.py"))` skipping any path with `"__pycache__"` in `path.parts`.
   - Compute POSIX relative module path (`path.relative_to(package_dir).as_posix()`) and package key (`""` when
     `path.parent == package_dir`, else `path.parent.relative_to(package_dir).as_posix()`).
   - Parse each file once and record non-zero module counts in `module_counts` and summed non-zero package counts in
     `package_counts` (or all discovered packages with their integer totals so package aggregation is explicit).
5. Implement
   `find_ratchet_violations(module_counts: dict[str, int], package_counts: dict[str, int], module_baselines: dict[str, int], package_baselines: dict[str, int]) -> list[str]`:
   - For each `(module, count)` in `sorted(module_counts.items())`, compare against
     `cap = module_baselines.get(module, 0)`; if `count > cap`, append a clear violation message naming the module,
     actual count, and cap.
   - For each `(package, count)` in `sorted(package_counts.items())`, compare against
     `cap = package_baselines.get(package, 0)`; if `count > cap`, append a clear violation message naming the package
     (displaying `"<root>"` for `""`), actual count, and cap.
   - Return the list of violation strings (empty list when all counts are `<=` baseline).
6. Populate `MODULE_BROAD_EXCEPT_BASELINES: dict[str, int]` and `PACKAGE_BROAD_EXCEPT_BASELINES: dict[str, int]` with
   the exact sorted baseline counts measured by running the scanner against
   `apps/sandbox-executor/src/sandbox_executor/`.
7. Add live repository tests:
   - `test_broad_except_baseline_consistency`: verifies `PACKAGE_BROAD_EXCEPT_BASELINES` matches the per-package sum of
     `MODULE_BROAD_EXCEPT_BASELINES` and that all baseline counts are positive integers.
   - `test_sandbox_executor_broad_except_ratchet`: scans `PACKAGE_DIR`, asserts files were found (guarding against an
     empty/wrong path), and asserts `find_ratchet_violations(...) == []`.
8. Keep all functions small, typed, and self-explaining: zero docstrings, zero explanatory comments (only `# why:` if
   strictly needed), and well within ruff complexity limits (`C901 <= 10`, `PLR0912 <= 12`, `PLR0913 <= 5`,
   `PLR0915 <= 50`).
