## Plan Description & Strategy

Today the flow handles a target-branch conflict in four different ways and resolves only ledger files. The plan replaces
those variants with one routine, `sync_with_target(context, stage)`, built bottom-up so each layer is testable on its
own and each child intent merges something useful:

1. **Core (Step 1):** a cheap probe (`target_probe.py`: `git fetch`, then `git merge-tree --write-tree` keyed on the
   target SHA, cached per (head SHA, target SHA)), a classifier for the mechanical conflict classes
   (`conflict_classes.py`: ledgers by append-merge reusing `ledger_reconcile.py`; timestamp-only knowledge-base and
   wisdom entries keep the target copy; delete-on-target versus mechanical touch keeps the deletion; both-appended lists
   such as lazy-export maps and `__all__` by ordered union), and the routine itself (`target_sync.py`: fetch, probe,
   merge with a normal merge commit, classify, resolve, verify, commit, push, append one executions ledger row), plus
   adoption of a merge already in progress on resume. `check_and_resolve_stage_conflicts` becomes a thin wrapper.
2. **Resolver role (Step 2):** `conflict_resolver_role.py` runs a containerised conflict-resolver role on the lowest
   model tier of the configured runner, escalating one tier after a failed lint, failed tests or explicit cannot-decide,
   and failing closed when the top tier is exhausted.
3. **Stages 1-3 (Step 3):** call the routine at flow start, at stage start and end, at each planner turn and each
   executor turn or step, merging at a turn boundary only on a conflict, and tell the next turn's agent what changed.
   The Stage 3 `sync_conflict` success-without-resolution path is removed.
4. **Stages 4-5 (Step 4):** replace the Stage 4 conflict gate's abort with the routine (before reviewers are dispatched
   and before the consensus is posted, plus each resolver turn); carry approval over after mechanical-only merges and
   scope re-review to resolved files after agent-resolved merges; Stage 5 calibrates after a clean merge and stops
   calling ledger or knowledge-base conflicts "code conflicts".
5. **End of flow (Step 5):** `end_of_flow_sync.py` loops sync, Stage 4 and Stage 5 on the merged head until the pull
   request is mergeable and clean; "completed successfully" is printed only then.
6. **Verification (Step 6):** full suite, lint, docs lint, and documentation of the routine in `docs/git_flow.md`.

Each of Steps 1-5 is a child intent (see `## Sub-intent list`), run in order because each builds on the previous one;
Step 6 is folded into every child's own acceptance and repeated once on the root branch.

### Implementation Details (No code blocks, only logic/steps)

1. `flow/target_probe.py`: `probe_target(worktree, target_branch, last_probe)` runs `git fetch origin <target>`,
   resolves the target SHA, returns a frozen `TargetProbe` (target SHA, head SHA, merge-base, `moved`,
   `conflicted_paths`) and short-circuits without merge-tree when (head SHA, target SHA) equals the cached last probe.
   Conflicted paths come from `git merge-tree --write-tree --name-only -z` (exit status 1 means conflicts). No agent is
   involved.
2. `flow/conflict_classes.py`: `ConflictClass` enum (`LEDGER`, `KB_TIMESTAMP_ONLY`, `DELETE_VS_TOUCH`, `APPENDED_LIST`,
   `CODE`) and `classify_path(worktree, path, merge_base, ours, theirs)` using stage blobs from `git ls-files -u`.
   Rules: ledger jsonl under `holon-knowledge/ledger/`; knowledge-base and wisdom entry JSON under `holon-knowledge/kb/`
   or `holon-knowledge/wisdom/` whose two sides are equal after dropping timestamp keys; delete on target with a
   branch-side diff that is whitespace, import order or formatting only; a Python file whose only conflict hunks are
   additions to the same `__all__` list or lazy-export mapping on both sides. Everything else is `CODE`. One resolver
   function per class in `conflict_classes_resolve.py` (append-merge via the existing `ledger_reconcile` helpers;
   `git checkout --theirs`; `git rm`; ordered union keeping target order then branch-only entries). Each resolver
   re-checks for conflict markers and returns False to downgrade the path to `CODE`.
3. `flow/target_sync.py`: `sync_with_target(context, stage, *, boundary)` where `boundary` is one of `FLOW_START`,
   `STAGE_START`, `STAGE_END`, `TURN`, `PUSH`, `CALIBRATE`, `FLOW_END`. Decision rule: probe; if not moved, return a
   no-op result (no merge, no push, no ledger row); if moved without conflict and `boundary is TURN`, return without
   merging; otherwise `git merge --no-ff --no-edit origin/<target>` in the flow worktree (never rebase, never
   force-push), classify and resolve mechanical paths, hand `CODE` paths to an injected `code_resolver` callable (Step 2
   supplies the real one; the default fails closed), verify no unmerged paths and no markers remain, commit with review
   trailers, push with the existing `host_remote.push_commit`, then append one executions ledger row. Returns a frozen
   `SyncResult` (merged, head before/after, per-path class and resolution, tier and attempts, test result,
   `changed_paths` for the next turn's prompt).
4. `flow/target_sync_record.py`: builds and appends the row (`action: target_sync`, stage, boundary, target SHA,
   conflicted paths, class per path, how resolved, resolver tier, attempt count, test result, `supersedes` = the id of
   the latest unresolved `sync_conflict` row for this branch when the sync resolved it). Append only; no earlier row is
   read for rewriting.
5. `flow/target_sync_resume.py`: `adopt_merge_in_progress(worktree, target_branch)` detects `MERGE_HEAD`; if
   `MERGE_HEAD` equals the current target SHA and every path is resolvable (mechanically now, or code via the resolver),
   finish it; otherwise `git merge --abort` and redo through `sync_with_target`. Called by the resume path before the
   dirty-tree guard.
6. Make `stage_conflicts.check_and_resolve_stage_conflicts` a thin wrapper that detects and resolves mechanical classes
   through `conflict_classes` (entrypoint callers inside containers keep their signature and still never spawn an agent)
   and move `_merge_tree_conflict_paths` to the new structured parser. `stage_conflict_resolution.py` delegates to
   `conflict_classes`. Register new symbols in `lazy_exports.py` and `flow/__init__.py` only where already the pattern.
7. Tests (new): `tests/flow/test_target_probe.py` (unchanged target makes no merge and no push; cache hit skips
   merge-tree; exact path list), `tests/flow/test_conflict_classes.py` (one test per mechanical class, each asserting no
   agent callable was invoked), `tests/flow/test_target_sync.py` (turn boundary with a non-conflicting target change
   does not move the head; stage boundary merges it; one ledger row per sync, earlier rows byte-identical; resume adopts
   an in-progress merge; no `rebase` or `push --force` in the recorded git calls; module budget file never written).
   Update `tests/test_stage_conflicts.py`, `tests/test_ledger_fast_conflict.py` for the wrapper.
8. Run
   `uv run pytest tests/flow/test_target_probe.py tests/flow/test_conflict_classes.py tests/flow/test_target_sync.py tests/test_stage_conflicts.py tests/test_ledger_fast_conflict.py`,
