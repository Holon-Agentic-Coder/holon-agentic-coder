## Plan Description & Strategy

Make the review approval survive target merges that only bring bookkeeping (clean merges, ledger appends, knowledge-base
appends), and make sure real code conflicts always narrow the next review to the resolved paths:

1. Fingerprint version `pf2`: hash the PR's own diff over reviewable pathspecs built from one shared bookkeeping
   definition.
2. `approval_covers` reports `bookkeeping_only` when approved head to current head touched only bookkeeping paths.

   helpers move out of `sync_points.py` so it and `conflict_gate.py` stay within their frozen 200-line budgets. The new
   public names are registered in the flow package exports.
4. Regression tests pin carry-over across each mechanical merge class.
5. Verify with the affected tests, the full suite once, lint, and a touch-set self-check.
