## Plan Description & Strategy

`refresh_intent_text(context, intent_path)` in `apps/sandbox-executor/src/sandbox_executor/intent_refresh.py` updates
`context.intent_data` in place from the intent file and then refuses a goal without the self-explaining-code sentence.
The checkpoint's second copy, `context.stage_results["intent"].payload["intent"]`, is left stale. The fix adds one
helper in the same module, called from `refresh_intent_text` right after the field loop and before the existing refusal
check, that copies each refreshed field the stored stage intent already holds from `context.intent_data` into that
stored dict. When the intent stage result, its `"intent"` payload, or its `"goal"` is absent, the helper returns without
change, so those checkpoints resume as before. The return value of `refresh_intent_text` (the list of changed
`intent_data` fields) and its log lines stay exactly as today, so current tests keep passing.

Tests go into `apps/sandbox-executor/tests/flow/test_intent_refresh_on_resume.py`: one saves a real checkpoint (with
`save_checkpoint`) whose `intent_data.goal` and stage payload goal both lack the sentence, loads it back through the
real resume path, runs `refresh_intent_text`, and asserts both goals equal the intent file's goal. The other covers a
checkpoint with no intent stage result.

1. In `intent_refresh.py` add a helper named for what it does, for example `stored_stage_intent(context)`, that returns

   where Stage 1 shared the dict) the copy is a no-op, which is fine.

   `goal_states_self_explaining_code` check. Leave the refusal, its message, the `changed` list and the log lines

5. In `test_intent_refresh_on_resume.py`:

     `list(REFRESHED_INTENT_FIELDS)` and `"intent" not in context.stage_results`. Parametrise it (or add one case) with
     an intent stage result whose payload has no `"intent"` goal, asserting that payload is left unchanged.
