## Plan Description & Strategy

Wire one repository-scoped `GitHubAdapter` from the review stage down through the review loop and into every GitHub call
the loop makes, give `ci_final_head.py` the same injection point, migrate the review-loop tests to inject `FakeGitHub`,
and pin the boundary with an AST test.

Design decisions:

1. **Proxy resolution moves before the adapter.** `run_review_loop` resolves the token-reduction proxy environment
   inline (the `context.token_reduce` / `sidecar.get_host_proxy_envs()` block). Move it verbatim into a new
   `flow/review/proxy_env.py` as `review_proxy_env(context) -> dict[str, str]` (same log lines, same swallow-and-warn
   behaviour). The stage calls it once and builds `GitHubAdapter(context.target_worktree, proxy_env)`. The loop uses
   `github.proxy_env` when an adapter is injected and calls `review_proxy_env(context)` itself otherwise (the container
   entrypoint `entrypoint/review_loop.py` calls `run_review_loop` without an adapter and must keep working unchanged).
2. **The loop asks the adapter, not `shutil`.** Both `shutil.which("gh")` checks become `github.available`;
   `import shutil` is removed from `loop.py`. Every orchestrator call passes `github=github`; `probe_ci` binds it in its
   `functools.partial`; posting passes `functools.partial(post_pr_review_consensus, github=github)` as the post function
   and `functools.partial(check_pr_mergeability, github=github)` as `mergeability_probe`, so `flow/review/posting.py`
   needs no change.
3. **`ci_final_head.py` takes the adapter through its existing seams object.** `FinalHeadSeams` gains
   `github: GitHubAdapter | None = None`; `_FinalHeadCheck` resolves it once (default
   `GitHubAdapter(repo_dir, dict(seams.proxy_env))`). The PR-head reader becomes
   `github.pr_head_sha(branch, STEP_LOOKUP_TIMEOUT_SECONDS)`, the rerun dispatcher becomes a new adapter method
   `rerun_failed(run_id, timeout) -> bool` (`gh run rerun <id> --failed`, returncode 0, False on spawn failure), and the
   default probe binds `github=`. Its git-only `subprocess.run` calls (`git rev-parse`, `git diff --name-only`) stay.
   `flow/stages/calibrate.py` keeps calling `check_final_head_ci` unchanged.
4. **Tests inject, never patch the loop's GitHub names.** Loop-level tests pass `github=FakeGitHub(...)` to
   `run_review_loop`; stage-level and pipeline tests patch the single constructor
   `sandbox_executor.flow.stages.review.GitHubAdapter` to return a `FakeGitHub` (one injection point, not five module
   globals). `FakeGitHub` gains: `proxy_env` (default empty dict), successive check payloads (`checks` may be a list of
   payloads consumed in order via a new `checks_sequence` field, the last one repeating), `rerun_failed`, and a
   `pr_head_sha` that honours its `timeout` argument. A small helper
   `ci_checks_payload(passed=, failed=, pending=, names=)` in `tests/flow/github/fake_github.py` builds `gh pr checks`
   JSON so migrated tests express the same CI states the old status dicts did.

Test discipline: affected tests first with `uv run pytest <paths>` after each step, then the full suite once with
`uv run task test`, then `uv run task lint`, all in the foreground. No repeated runs: this intent has no performance or
timing target.
