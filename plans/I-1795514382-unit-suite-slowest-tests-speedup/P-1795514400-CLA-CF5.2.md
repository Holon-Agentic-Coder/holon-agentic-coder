### Strategy Rationale

The intent is accepted as written. It is well scoped, it changes no production code, and the profile taken while
planning shows that most of the time in the 13 files is not spent on what the tests prove.

The plan orders the work by proven saving per unit of risk. It measures first (Step 1), applies the two shared flow
fixtures that help six files at once (Step 2), then the file-local fixes (Steps 3 to 6), then takes a checkpoint and
applies bounded second-tier levers only as far as needed (Step 7), and verifies once at the end (Step 8). Each lever
follows the intent's preference order: first "make it cheap", then "remove with a named covering test", and only last
"mark as stress with a reason".

How the overall numbers follow from the steps:

- **p_success_pred:** `0.50`. Success means that every acceptance criterion holds, including the 60 % threshold. The
  threshold is an aggregate of additive savings, so the product of the step probabilities is not the right model: a weak
  result in Step 4, 5 or 6 only lowers the total. The planner's own measurement predicts `1 - 85.0 / 181.9 = 0.533`
  after Steps 2 to 6 and about `0.57` to `0.61` after Step 7, with an uncertainty of about `0.03`. That gives roughly
  `0.55` for the threshold. Multiplied by `0.90` for a clean final verification (coverage, mutants, lint, serial run):
  `0.55 * 0.90 = 0.50`. The single-step bottleneck is Step 2 (`0.85`): without it the target cannot be reached.
- **entropy_pred:** the sum of the step entropies, `0.3 + 1.8 + 1.1 + 0.5 + 1.3 + 1.9 + 2.0 + 0.4 = 9.3`. A cross-check
  with the bootstrap formula of `docs/metrics.md`, using `SSA = 6`, `IRR = 2`, `CL = 5`, `SER = 3`, `NOV = 4`, gives
  `0.30 * 6 + 0.25 * 2 + 0.20 * 5 + 0.15 * 3 + 0.10 * 4 = 4.15`. The sum is kept because one shared fixture
  (`flow_repos`) serves many test files outside the scope.
- **impact_pred:** judged for the whole change, not summed. `80.0` reflects a unit suite whose slowest tenth runs in
  less than half the time on every developer machine and both CI runners, and tests that no longer read the checkout's
  real ledger or start the host's real `gh`.
- **cost_pred:** the sum of the step costs, `3.0 + 3.0 + 2.0 + 1.0 + 2.5 + 3.5 + 4.0 + 3.5 = 22.5`. Ten runs of the

### Measurement protocol (used by Steps 1, 7 and 8)

- All commands run from the repository root, in the foreground. Timing depends on the current directory, because of the
  ledger finding above.
- Results go to a directory outside the repository (called "the results directory" below), for example
  `"${TMPDIR:-/tmp}/I-1795514382-results"`.
- Timing command, identical before and after:
  `uv run pytest -n auto --dist worksteal -m "not integration_test and not stress" --durations=120 --junitxml=<results>/<name>.xml`.
- N is 3 before and 3 after. Reason: the summed time of one file varies by 10 to 15 % between runs under 18 workers with
  work stealing, and the acceptance threshold is a ratio. The median of three is the reported value. No further
  repetition is made.
- For each run the report states the passed and failed counts and pytest's own time. For each file it states the case
  count and the summed time of each run and the median.
- Per-file sums come from the junit files with a short scratch script kept in the results directory, not in the
  repository.
- A scope-only check after a step is one run of the affected files with `-n auto --dist worksteal`. Path arguments are
  grouped by directory (all `tests/*.py` first, then `tests/flow/*.py`, then `tests/flow/github/`, then
  `tests/flow/stages/`). The planner saw `fixture 'flow_repos' not found` when paths of different directories were
  interleaved.

### Mutant check (used by Steps 2 to 7)

- The executor makes two scratch clones in the results directory with `git clone --local --no-hardlinks`: one at the
  start commit of the execution and one at the current commit. Mutants are applied only there, one at a time, and are
  never committed or pushed.
- Tests in a scratch clone run with the worktree's interpreter and with the clone as current directory, so that the
  `pythonpath` setting of `pyproject.toml` puts the clone's `apps/sandbox-executor/src` first. A canary mutant (one
  function body replaced by a raise) must make a test fail; this proves that the mutated source is the one imported.
- For each mutant the executor runs only the in-scope file or files that test the module, with
  `-n auto --dist worksteal -x`. "Killed before" comes from the start-commit clone, "killed after" from the current
  clone. The rule: every mutant killed before is killed after. A mutant that was not killed before is reported as such
  and is not a failure of this plan.
- The list has four to six mutants per module: one per hashed or redacted input dropped, one per inverted condition on
  the path the changed tests exercise, and one constant return. The modules are named in each step.
