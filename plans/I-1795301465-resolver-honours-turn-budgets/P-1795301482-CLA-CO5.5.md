## Plan Description & Strategy

Make the Stage 4 resolver turn honour `HOLON_TURN_TIMEOUT_SECONDS` and `HOLON_TURN_STALL_SECONDS` in the same way the
executor, planner and review ensemble already do. The change has three parts:

1. **Production fix (one module).** In `entrypoint/review_loop.py`, import `load_budgets` from
   `sandbox_executor.budgets`. Inside `_run_resolver_agent`, call
   `run_turn(cmd, cwd=repo_dir, turn_budgets=load_budgets(os.environ).turn)`. The call reads the environment at turn
   time inside the role container. That matches `planner.py` and `executor/run.py`, and it keeps the private function's
   signature unchanged, so the call site at `review_loop.py:614` and every existing caller stay as they are. This is the
   smallest change: no new parameter and no plumbing through `_resolve_iteration`.
2. **Existing-test compatibility.** Four `assert_called_once_with(..., cwd=repo_dir)` assertions in
   `tests/test_review_loop.py` (lines 2310, 2327, 2345, 2367) must also accept the new `turn_budgets` keyword. Two
   `fake_run_turn(cmd, cwd=None)` stubs have to accept it too: one in `tests/test_review_loop.py:2299` and one in
   `tests/test_review_resolver_failure.py:537`.
3. **New hermetic tests.** Add a small focused class to `tests/test_review_loop.py`, next to
   `TestResolverAgentExecution`. It covers two cases. First, with `HOLON_TURN_STALL_SECONDS=900` and
   `HOLON_TURN_TIMEOUT_SECONDS=1800` set through `monkeypatch.setenv`, the captured `turn_budgets` has
   `stall_seconds == 900` and `turn_seconds == 1800`. Second, with both variables removed through
   `monkeypatch.delenv(..., raising=False)`, the captured value equals `TurnBudgets()`, that is `DEFAULT_TURN_SECONDS`
   and `DEFAULT_STALL_SECONDS`.

Module budgets: the line-budget gate only covers `packages: ["apps/sandbox-executor/src/sandbox_executor/flow"]` plus
explicit overrides. `entrypoint/review_loop.py` (920 lines) and the test files are not under that gate, and the change
adds about 2 lines to production code. No module split is needed, and `module_budgets.json` is not touched.

Test-run discipline: the intent does not measure timing, so there are no repeated runs. The affected tests run first,
then the full suite runs once with `uv run task test`, followed by `uv run task lint` and `uv run task lint-docs`.
