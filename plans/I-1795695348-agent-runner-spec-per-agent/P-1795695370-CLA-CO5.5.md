## Plan Description & Strategy

Introduce `sandbox_executor.runners`, a package of one small module per agent runner plus a shared `spec.py` that
defines the frozen `RunnerSpec` dataclass. Each agent module builds one `RunnerSpec` holding the facts that are today
spread over shared tables: the container image, the default model, the ticker (or `None`), the credential environment
variables accepted by validate, and a `check_credentials` behaviour that returns `None` when credentials are present or
the exact error text when not. `runners/__init__.py` collects the five specs into `RUNNER_SPECS` keyed by agent id (in
today's mapping order: antigravity, claude, pi, codex, opencode) and offers a `runner_spec_for(agent)` lookup that
normalises ids with `local_llm.normalize_agent_id`, so the package never imports `agent_defaults` or `agent_runner`.

`agent_defaults.py` replaces its three literal dictionaries with comprehensions over `RUNNER_SPECS`; they stay plain
`dict[str, str]` objects (so identity checks such as `cli.AGENT_IMAGE_MAPPING is AGENT_IMAGE_MAPPING`, `.get` and
monkeypatching keep working) and `AGENT_TICKERS` skips specs whose ticker is `None`. `StandardAgentRunner.validate`
becomes: resolve credentials, look up the spec, return when there is none, call `check_credentials`, and on an error
print it to stderr and `sys.exit(1)`. The `custom_validator` constructor parameter and attribute disappear, as does
`AgentRunner._missing_credentials_message` (its only caller was validate; its text moves into the specs). Runner
subclasses keep their argv behaviour unchanged.

Execution happens as one plan on the intent branch; every step is small and they share one test run.
