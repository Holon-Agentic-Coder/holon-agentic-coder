## Plan Description & Strategy

`target_only_paths(repo_dir, plan_rev, merge_base_sha, head_sha)` returns `on_target - own`:

- `on_target` comes from `git diff --name-only plan_rev...merge_base_sha`, meaning paths the target branch changed since
  the plan branch forked.
- `own` comes from `git log --no-merges --name-only merge_base_sha..head_sha`, meaning paths touched by the PR's
  non-merge commits.

When the execution branch merges `origin/main` and the merge commit itself edits a file main added, that edit is
invisible to `--no-merges`. The file therefore stays in `target_only_paths`. The counted paths
(`calibration_diff.execution_patch_numstat`, a three-dot `base...head` diff from the target merge base) do include it,
so `counted_target_only_file` fires.

The fix makes `own` the paths that differ between the merge base and the head, taken from the PR side:
`git diff --name-only merge_base_sha...head_sha --`. That is the same three-dot measurement the counted paths use, and
it covers edits made inside merge commits. Three outcomes follow:

- A file main added and the merge adapted differs from the merge-base tree, so it counts as the PR's own.
- A file only main changed, which the PR never touched by merge or otherwise, is identical in both trees, so it stays in
  `target_only_paths`. If it is ever counted, the condition still fires.
- A clean merge leaves main's files identical to the merge base, so they stay target-only but are not counted, and no
  violation follows.

Alternatives considered:

- **Per-merge-commit diff against the target-side parent:** more git calls, plus ordering and parent-selection logic,
  and for every case the intent describes it yields the same set as the three-dot diff. Rejected because it adds
  complexity and no discrimination.
- **Union of the old `log --no-merges` set and the new diff:** the only extra paths it adds are ones the PR touched and
  later reverted to a net-zero change. Those are never counted, so the union changes no outcome. Rejected as dead
  weight, since the intent asks to replace the log query.

The sequence is test-first:

- Step 1 adds the three hermetic regression tests and confirms that (a) fails on current code and (b) and (c) pass.
- Step 2 changes the one git query and the docstrings.
- Step 3 runs the targeted tests, then the full suite once, lint and lint-docs, all in the foreground.

The other four self-check conditions (`drag_without_failure`, `evaluated_ledger_only`, `evaluated_not_approved`,
`fallback_stub`) and the pure `self_check_report` function stay untouched.
