### Step 4: Implement `scripts/ci_merge_push_gate.py`

- Entry point `decide_merge_push(context, client, rules)`; `GateRules` bundles the gate's `diff_rule` and
  `is_bookkeeping_path` (the plan's allowed bundling), so the module never imports the gate and no cycle exists.
- Rules in order: hygiene (no request), parents (`None` on a read error or one parent; `merge-push-not-two-parents`,
  `merge-push-first-parent-not-previous-head`, `merge-push-incomplete-event` for an empty `base_ref`), chain on the
  previous head (plus `diff_rule(real_sha, before)` when the success is older), base push run (`MAX_BASE_RUNS = 5`,
  `merge-push-base-run-*`), merge base and four recursive trees (`merge-push-no-merge-base`,
  `merge-push-tree-truncated`, checked per tree so a truncated tree stops the reads), file-level three-way check,
  bookkeeping-filtered overlap by path and parent directory, bidirectional import/test scan in `apps` and `scripts`.
  Skip: `merge-push-clean-main-merge`. Every later exception is `merge-push-api-error` with class name and HTTP status.
- Choices beyond the plan text, all toward "run": a changed `conftest.py` is unanalysable (fixtures are used by name); a
  tree answer without `truncated` counts as truncated; `zip(strict=)` avoided (Python 3.10).
- First draft was 429 lines; docstring shortened and signatures compacted to 399 lines (budget 400). Ruff clean.
