### Implementation Details (No code blocks, only logic/steps)

1. Define standard-library imports plus targeted reuse from sibling modules (`is_bookkeeping_path` from
   `scripts.ci_bookkeeping_gate`; `job_key`, `runner_os`, `seconds_between` from `scripts.ci_durations_collect`), with
   fallback relative imports if invoked directly as a script. Ensure zero docstrings and zero comments except `# why:`
   where genuinely needed.
2. Define concise frozen dataclasses for structured records:
   - `HeadCommit`: `pr_number`, `head_sha`, `short_sha`, `head_kind` (`"code"` or `"bookkeeping"`), `subject`,
     `committed_at`, `changed_files`.
   - `HeadJobTiming`: `pr_number`, `head_sha`, `head_kind`, `workflow`, `job`, `job_key`, `runner_os`, `run_id`,
     `run_attempt`, `started_at`, `completed_at`, `duration_seconds`, `conclusion`.
   - `ReviewerWait`: `pr_number`, `iteration`, `head_sha`, `waited_seconds`, `state`.
   - `DurationStats`: `count`, `median_seconds`, `max_seconds`.
3. Define the injectable `GhRunner` type alias (`Callable[[Sequence[str]], Any]`) and default `run_gh_json(args)`
   implementation that invokes `subprocess.run(["gh", *args], check=True, capture_output=True, text=True)` and parses
   JSON (supporting `--paginate --slurp` outputs by flattening paged lists or dict-wrapped `workflow_runs`/`jobs`
   arrays). Never issue mutating `gh` commands; only read-only `gh api` (and
   `gh repo view --json nameWithOwner -q .nameWithOwner` when `--repo` is omitted).
4. Implement `--prs` range/list parser (`parse_pr_spec`): accept single numbers (`360`), inclusive ranges (`360-366`),
   and comma-separated combinations (`360-362,365`), validating positive integers and `start <= end`, deduplicating in
   sorted order, and defaulting `--prs` to `"360-366"`.
5. Implement GitHub collection per PR via `GhRunner`:
   - Fetch PR commits (`repos/{repo}/pulls/{pr}/commits`, paginated) in chronological order.
   - For each commit SHA, fetch commit file details (`repos/{repo}/commits/{sha}`) to collect `filename` and
     `previous_filename` (for renames).
   - Classify each head commit as `"bookkeeping"` vs `"code"`: a commit is `"bookkeeping"` if all changed file paths
     satisfy `is_bookkeeping_path(path)` (covers `plans/`, `executions/`, `holon-knowledge/` `.md`/`.json`/`.jsonl`), or
     if changed files are empty and the commit subject matches known bookkeeping commit prefixes (`ledger`,
     `calibration`, `review`, `plan`, `bookkeeping`, case-insensitive); otherwise `"code"`.
   - For each head SHA, query workflow runs (`repos/{repo}/actions/runs?head_sha={sha}&per_page=100`) and for each
     completed run query jobs (`repos/{repo}/actions/runs/{run_id}/jobs?filter=all&per_page=100`).
   - Filter out skipped or incomplete jobs (missing `started_at`, `completed_at`, or `conclusion`, or
     `conclusion == "skipped"`), computing `duration_seconds = seconds_between(started_at, completed_at)`.
6. Implement optional flow-log reviewer-wait correlation (`load_reviewer_waits`):
   - Accept `--flow-log` (repeatable or single file/directory path; optional, defaults to none).
   - Parse plain-text `[Review Loop]` flow logs matching `Starting review iteration {N}/...`,
     `CI wait (settled|stopped on a failure) after {S}s`, `CI wait budget of {B}s spent`, and
     `Resolver pushed new head '{sha}' at iteration {N}`, as well as JSONL execution records containing
     `review_iteration` and `ci_wait.waited_seconds`.
   - Associate parsed waits with PR number (from log context/filename or single-PR fallback) and iteration/head SHA so
     the summary displays reviewer wait per iteration where available, and omits or marks `n/a` when no flow log exists.
7. Implement statistics aggregation and summary table rendering:
   - Compute median (`statistics.median`) and longest (`max`) durations overall, per job (`job_key` / `runner_os`),
     split by head kind (`code` vs `bookkeeping`), and per PR head (`PR`, `head_sha[:8]`, `kind`, job count, median
     duration, longest duration, longest job name, and reviewer wait if correlated).
   - Print clean aligned Markdown/ASCII tables to stdout; keep `main(argv=None, runner=run_gh_json)` returning `0` on
     success and `2` on invalid CLI arguments.
8. Keep every function small and focused so `scripts/measure_ci_head_durations.py` stays under 350 lines and satisfies
   all Ruff limits (`C901 <= 10`, `PLR0912 <= 12`, `PLR0913 <= 5`, `PLR0915 <= 50`).
