### Step 2: Platform-sensitivity rule module

- New `scripts/macos_relevance_rules.py` (193 lines): `SENSITIVE_FILE_NAMES`, `SENSITIVE_SUFFIXES`,
  `SENSITIVE_NAME_PREFIXES` (`Dockerfile.`), `SENSITIVE_PREFIXES`, `SENSITIVE_NAME_FRAGMENTS`, `GATE_PATH_PATTERNS` and
  `CONTENT_PATTERNS` (`(reason, regex)` pairs of plan item 4), plus `path_reason`, `shebang_reason`, `strip_comment`,
  `content_reason`, `blob_reason` and `judge_change` returning a frozen `Verdict` (basis `path`/`content`, side, reason).
- Deviations, all towards "run": import patterns also match a later name of `import a, b` (the repository has
  `import os, signal, sys`); `from os import ...` / `from os.path import ...` is sensitive (the `os.` call patterns
  cannot see imported names; no such import exists today); `keychain` matches without word boundaries (so
  `claude_keychain` counts); `from .launcher` relative imports count. Extension-less files are read for a shell
  shebang only.
- Oversize, undecodable and unreadable content is `unreadable-content` (sensitive); the size cap is applied in the git
  module before reading the blob.
