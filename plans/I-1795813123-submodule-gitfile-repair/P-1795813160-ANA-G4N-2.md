## Plan Description & Strategy

We eliminate container-to-host submodule gitfile breakage in two defence-in-depth layers backed by one shared neutral
helper:

1. **Shared helper (`submodule_gitfile.py`):** Parse `.gitmodules` to locate configured submodules, inspect each
   `<submodule>/.git` gitfile and its referenced `core.worktree` config for absolute or unresolvable paths, and repair
   issues by running `git submodule absorbgitdirs` (when the gitdir is resolvable) and rewriting `gitdir:` and
   `core.worktree` to host-valid POSIX relative paths against `git rev-parse --git-path modules/<name>` (or common
   gitdir `modules/<name>`). Any gitfile that still cannot be resolved is returned as an explicit failure naming the
   offending file.
2. **Container-side prevention (`entrypoint/executor/repair.py`):** Extend `_probe_git_repo` to detect absolute or
   unresolvable submodule gitfiles (and invalid `core.worktree` entries) after the agent runs, and extend
   `_repair_git_repo` to repair them to host-valid relative paths before the container exits.
3. **Host-side pre-checkout guard (`flow/stages/calibrate.py` and `flow/stages/review.py`):** Run the submodule gitfile
   check and repair before `_checkout_execution_branch` in Stage 5 (`_prepare_execution_branch` in `calibrate.py`) and
   before `git checkout` in Stage 4 (`_checkout_execution_branch` in `review.py`). If repair succeeds, log the repair
   and proceed with checkout; if unrepairable, fail the stage cleanly before checkout, naming the offending gitfile.
4. **Hermetic verification:** Add unit tests in `test_executor_repair.py` and `test_calibrate.py` exercising real `git`
   worktrees/clones with container-path submodule gitfiles (both repairable and unrepairable cases), then run the
   targeted tests, full test suite, `uv run task lint`, and `uv run task lint-docs` in the foreground.

### Implementation Details (No code blocks, only logic/steps)

1. Create `apps/sandbox-executor/src/sandbox_executor/submodule_gitfile.py` using only standard-library modules
   (`configparser`, `dataclasses`, `os`, `posixpath`, `subprocess`, `collections.abc`) and
   `sandbox_executor.git.run_git` as the default runner (no imports from `flow/` or `entrypoint/`).
2. Define a frozen dataclass `SubmoduleGitfileIssue` with fields `name: str`, `path: str`, `gitfile_rel: str`,
   `gitdir_raw: str`, and `reason: str`.
3. Implement `parse_gitmodules(repo_dir: str) -> list[tuple[str, str]]`:
   - If `os.path.join(repo_dir, ".gitmodules")` is not a file, return `[]` immediately without running `git`.
   - Parse `[submodule "<name>"]` sections and collect `(name, path)` pairs for sections with a non-empty `path` value.
4. Implement `find_submodule_gitfile_issues(repo_dir: str) -> list[SubmoduleGitfileIssue]`:
   - For each `(name, rel_path)` from `parse_gitmodules(repo_dir)`, inspect
     `gitfile = os.path.join(repo_dir, rel_path, ".git")`.
   - If `gitfile` is not an existing regular file, skip it.
   - Read the `gitdir:` pointer line. If missing or empty, record an issue naming `f"{rel_path}/.git"`
     (`"missing gitdir pointer"`).
   - Resolve `target = raw if os.path.isabs(raw) else os.path.normpath(os.path.join(sub_dir, raw))`.
   - If `not os.path.isdir(target)`, record an issue naming `f"{rel_path}/.git"` (`f"unresolvable gitdir '{raw}'"`).
   - Else if `os.path.isabs(raw)`, record an issue naming `f"{rel_path}/.git"` (`f"absolute gitdir '{raw}'"`).
   - Else check `<target>/config` for `core.worktree` (parsing `[core]` in `<target>/config` with `configparser` so no
     subprocess is needed during read-only inspection): if `worktree` is set and either `os.path.isabs(worktree)` or
     `os.path.realpath(os.path.join(target, worktree)) != os.path.realpath(sub_dir)`, record an issue naming
     `f"{rel_path}/.git"` (`f"invalid core.worktree '{worktree}'"`).
5. Implement
   `repair_submodule_gitfiles(repo_dir: str, run: GitRunner | None = None) -> tuple[list[str], list[SubmoduleGitfileIssue]]`:
   - Inspect current issues with `find_submodule_gitfile_issues(repo_dir)`; if empty, return `([], [])`.
   - For issues where the current `gitdir:` exists on disk (e.g., absolute container path inside a live container), run
     `git submodule absorbgitdirs -- <rel_path>` via `run` (`check=False`).
   - Re-check issues. For each remaining issue `(name, rel_path)`:
     - Resolve candidate module gitdirs by querying `git rev-parse --git-path modules/<name>` and
       `<git_common_dir>/modules/<name>` (from `git rev-parse --git-common-dir`), picking the first existing directory
       that contains `HEAD` or `config`.
     - If a candidate module gitdir exists, compute POSIX-separated
       `rel_gitdir = os.path.relpath(candidate, start=sub_dir).replace(os.sep, "/")`, write `f"gitdir: {rel_gitdir}\n"`
       to `<sub_dir>/.git`, compute POSIX-separated
       `rel_worktree = os.path.relpath(sub_dir, start=candidate).replace(os.sep, "/")`, and update `core.worktree` in
       `<candidate>/config` via `git config --file <config> core.worktree <rel_worktree>`.
     - Record `f"{rel_path}/.git"` in `repaired`.
   - Re-run `find_submodule_gitfile_issues(repo_dir)` and return `(repaired, remaining)`.
6. Implement `format_submodule_gitfile_error(issues: list[SubmoduleGitfileIssue]) -> str` formatting a clear,
   single-line diagnostic listing each offending `gitfile_rel` and `reason`.
7. Keep every function within ruff complexity limits (`C901 <= 10`, `PLR0912 <= 12`, `PLR0913 <= 5`, `PLR0915 <= 50`),
   keep the file well under 350 lines, and write no docstrings and no comments except `# why:` comments where
   non-obvious constraints exist.
