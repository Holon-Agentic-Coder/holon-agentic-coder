## Plan Description & Strategy

The plan is a single execution. It does not decompose, because predicted entropy is 10.0, below the 15.0 budget.

Design decisions, shared by all steps:

1. **Sentinel.** A new module, `sandbox_executor/budget_limits.py`, is the single home of the sentinel. It is
   standard-library only and never imports `budgets`, so there is no import cycle. It holds:
   - the constant `UNLIMITED = "unlimited"`;
   - `is_unlimited(raw)`: true when `str(raw).strip().casefold() == "unlimited"`;
   - `format_budget_minutes(seconds_or_none)`: `"unlimited"` for `None`, otherwise the existing `format_minutes` rule;
   - `unbounded_supervision_warning(...)`, described in item 5.

   Only the exact token is accepted. Strings such as `"inf"`, `"nan"`, `"none"`, `"0"` and `"-1"` keep their current
   meaning (rejected with a warning; the default is kept).

2. **None means no ceiling.** No `float("inf")` value is ever used.
   - `StageBudgets` fields, `TurnBudgets.turn_seconds`, `Budgets.stage_seconds()` and `StageTimer.budget_seconds` become
     `float | None`.
   - `HOLON_STAGE_BUDGET_SECONDS` needs a third state ("unset", "a number", "unlimited"). `Budgets` therefore gains
     `stage_override_unlimited: bool = False`; it is never a second meaning of `None`.
   - `StageTimer` with a `None` budget: `breached()` is always False, `remaining()` returns `None`, and two new helpers
     are added. `has_time_left()` returns True when unlimited. `remaining_capped(cap)` returns the smaller of `cap` and
     the remaining time; it returns `cap` when unlimited.
   - `stage_budget_handdown_env` returns `{HOLON_STAGE_BUDGET_SECONDS: "unlimited"}` for an unlimited timer.
3. **Container side.** The role container already parses `HOLON_STAGE_BUDGET_SECONDS` through `load_budgets`. With the
   sentinel accepted there, the hand-down env round-trips and the container honours it: its own per-stage default must
   not fire under an unlimited host stage.
4. **StageResult (`flow/context.py`, 280/280, no headroom).** The edit is line-neutral. `summary_line` falls back to the
   bare form only when `elapsed_seconds is None`, and passes a `None` budget to `format_stage_summary`, which prints
   `unlimited`. `after_stage` already fills `budget_seconds` for every timed stage, so `None` with an elapsed time now
   only means "unlimited".
5. **Warnings.**
   - When a stage resolves to unlimited, the pipeline logs a WARNING when the stage starts.
   - `load_budgets` logs one WARNING per variable set to `unlimited`.
   - When the turn timeout is unlimited, stall detection is disabled (`0`) and at least one stage is unlimited,
     `unbounded_supervision_warning` returns an ERROR-level message. It is logged by `load_budgets` and printed by
     `holon doctor` ("nothing will stop a hung agent").
   - The plan chooses to **warn loudly, not refuse**, because refusal would break the existing operator escape hatch.
     The rationale is recorded in `docs/budgets.md`.
6. **Ledger.**
   - The execution summary row (`entrypoint/executor.py`) writes `budget_seconds: null` and `budget: "unlimited"` when
     the stage is unlimited.
   - The flow's StageResult payload gets `stage_budget: "unlimited"`, which is checkpointed with the stage.
   - `docs/ledger_schema.md` documents the field.

  `StageTimer`, without adding complexity to `run_turn`.
- **Git branch:** same execution branch
- **Sub‑intent:** NONE

### Implementation Details (No code blocks, only logic/steps)

1. Extract a pure helper `_silence_window(budgets, streaming)`:
   - A streaming runner uses `stall_seconds`.
   - A non-streaming runner uses `max(stall, turn)` when the turn timeout is finite.
   - When the turn timeout is unlimited, a non-streaming runner uses `max(stall, DEFAULT_TURN_SECONDS)`. Silence
     therefore stays bounded unless stall is also 0, and with stall at 0 the window is unused, as today.
   - Document this rule in the docstring and in `docs/budgets.md`.
2. Extract a pure helper `_turn_breach(budgets, turn_observable, now, last_progress, stage)`. It returns `None` when
   `turn_seconds is None`, and otherwise the existing turn `BudgetBreach` condition.
3. Replace the inline expressions at the current `silent_stall_seconds` line and the turn-check branch with the two
   helpers. This lowers the complexity of `run_turn`; the existing `noqa` stays untouched and no new one is added.
4. Replace `stage_timer.remaining() > 0` (two places in `supervise_authoring_turn`) with `stage_timer.has_time_left()`.
5. Keep the stall check unchanged. It still fires when `stall_seconds > 0`, whatever the turn and stage ceilings are.

### Implementation Details (No code blocks, only logic/steps)

1. In `budget_limits.py`, add `unlimited_stage_warning(stage)`. It returns a fixed sentence: "Stage '<stage>' runs with
   no wall-clock ceiling (budget 'unlimited'); only the turn and stall limits can stop it."
2. In `budget_limits.py`, add `unbounded_supervision_warning(turn_seconds, stall_seconds, unlimited_stages)`. It returns

   returns `None`. The function uses plain arguments, so it does not import `budgets`.
3. At the end of `load_budgets`, compute the list of unlimited stages (all five, or every stage when the override is

     uses one fixed log line.
   - Decision: warn, do not refuse. The intent allows either. Refusing would make `HOLON_TURN_STALL_SECONDS=0` plus
     unlimited unusable for legitimate long local-model runs. This rationale is documented in Step 5.
4. Wire `unlimited_stage_warning` into `PipelineEngine.timed_execute_stage` (Step 3, item 1). Doctor prints the
   unbounded-supervision message under the budgets line, prefixed with `WARNING:`.

### Strategy Rationale

The intent is accepted as is. It has clear operator value: an explicit `unlimited` replaces the misleading
`10080`-minute magic number. It is low-risk by default, because the sentinel is opt-in and unset values keep today's
defaults. It is also well specified.

The strategy isolates the sentinel and its messages in a new leaf module (`budget_limits.py`), for two reasons:
`budgets.py` stays under the ~400-line preference, and the flow modules that sit exactly at their frozen line budgets
only receive line-neutral edits. "No ceiling" is a typed `None`, with a separate boolean for the override variable's
third state. This satisfies the never-`inf` requirement, and mypy finds every consumer that would compare against
`None`.

The plan does not decompose. The seven steps are tightly coupled through the `None` contract. Splitting them would add
branch and merge cost and would leave intermediate states where `None` crashes a consumer. The summed entropy (10.0) is
within the 15.0 budget.

Aggregation:

- Plan entropy is the sum of the step entropies: `2.5 + 1.5 + 3.0 + 1.0 + 0.8 + 0.8 + 0.4 = 10.0`.
- `p_success` is driven by the bottleneck chain, Step 1 (0.90), Step 3 (0.83) and Step 7 (0.90). The steps are highly
  correlated, because they share the same author context and type checker, so the product (0.67) understates the chance
  of success. A qualitative 0.80 was chosen, a little below the weakest step.
- Impact is the plan-level value of the operator feature plus its safety signalling, set at 70. It is not the sum of the
  step impacts, which are partial contributions.
- Cost is the sum of the step costs, `3.0 + 2.0 + 4.0 + 1.0 + 1.5 + 1.5 + 1.0 = 14.0`.
- Learning value is 4.0, because it teaches how far a typed `None` contract can reach into budget-frozen modules.
- `EV = 0.80 * 70.0 + 0.5 * 4.0 - 0.3 * 10.0 - 14.0 = 56.0 + 2.0 - 3.0 - 14.0 = 41.0`.

The strongest assumption is that `after_stage` always sets `budget_seconds` for timed stages. The line-neutral
`summary_line` change relies on it, and Step 3 verifies it before the edit.
