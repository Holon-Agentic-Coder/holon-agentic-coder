### Strategy Rationale

The intent is sound and has already been implemented once. The only failure was administrative: the declared touch set
did not cover the edits a package split forces on tests that patch moved names. Re-planning from scratch would waste the
prior run's work and repeat its risk. Decomposing into sub-intents would add branch overhead to a change whose pieces
cannot be merged one at a time, because the package must replace the module atomically. So this plan:

- reuses the prior commits;
- widens the touch set with globs, so that all calibration test files and fixtures are covered;
- adds an explicit pre-commit touch-set self-check.

How the overall metrics were derived:

- **Entropy:** the sum of the step values, `4.0 + 3.0 + 2.0 + 2.0 = 11.0`. It is rounded up to 12.0 as a margin for
  hand-port drift. That is below the budget of 15.0.
- **p_success:** the product of the bottleneck chain, `0.90 * 0.88 * 0.85 * 0.88 = 0.59`. The steps are strongly
  correlated, because they verify the same already-passing code, so the estimate is lifted to 0.75.
- **Impact:** 70, for removing the highest-complexity function in the calibration path, removing six `noqa` suppressions
  and making calibration testable without a running flow.
- **Cost:** the sum of the step costs plus a margin, 14.
- **EV:** `EV = 0.75 * 70.0 + 0.5 * 4.0 - 0.3 * 12.0 - 14.0 = 52.5 + 2.0 - 3.6 - 14.0 = 36.9`, rounded to 37.0.

The strongest assumption is that the stale-override warning stays non-fatal. The docstring of
