The intent is accepted as is: it is well-scoped (12 named files, 80 findings), behaviour-preserving and has a precise,
machine-checkable acceptance test. One plan on one execution branch is cheaper and lower-entropy than sub-intents: each
slice is small, the slices share the same verification, and splitting would triple the Stage 4 review and CI overhead
for no reduction in risk. The work is still done in three file slices (Steps 3–5), each a separate commit with its own
before/after finding count, so the "small slices" rationale and the per-slice reporting criterion are both honoured
inside the single PR.

near-certain: `0.99 * 0.97 * 0.97 * 0.95 * 0.95 * 0.97 = 0.80`, adjusted to 0.88 because failures in Steps 3–5 are
locally repairable inside the same execution (a failing slice is fixed, not abandoned), so they are not independent

`0.5 + 2.0 + 1.5 + 3.0 + 3.5 + 1.5 = 12.0`. Impact is judged qualitatively (one more slice of the suite becomes true to
the self-explaining rule, plus a permanent regression guard for the 12 files): 50. Learning value is low (2.5): the only
new information is how often test-file prose carries a genuine reason. Bottleneck step: Step 5 (`test_review_report.py`
and `test_review_restart.py`, 34 findings, many trailing assertion comments that must be re-expressed without changing
