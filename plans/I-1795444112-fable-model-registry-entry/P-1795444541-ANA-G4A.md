## Plan Description & Strategy

This plan corrects the `claude-agent` model capability registry in
`apps/sandbox-executor/src/sandbox_executor/agent_defaults.py` so that `claude-fable-5-2` has its own dedicated

line and `holon doctor` display the canonical model ID and name the alias), adds a model-family alias invariant test in
`apps/sandbox-executor/tests/test_model_alias_families.py`, and updates existing tests and documentation in
`docs/agents.md`.

Key facts from codebase inspection:

- In `apps/sandbox-executor/src/sandbox_executor/agent_defaults.py`, `RUNNER_CAPABILITIES` currently lists
  `ModelCapability(runner="claude-agent", canonical_model="claude-opus-5-5", aliases=["opus", "claude-opus", "fable"], effort_levels=[], fallback_tier="Primary (Cloud/CLI)")`
  and has no entry for `claude-fable-5-2`.

  `model_name` without canonicalising aliases. When an operator passes `--model fable` or `HOLON_MODEL=fable`,

  `"--model (alias 'fable')"` or `"HOLON_MODEL (alias 'fable')"`), so `resolution.describe("Model")` produces
  `"Model resolved to claude-fable-5-2 (source: flag, --model (alias 'fable'))"` in both the stderr INFO log and
  `holon doctor` stdout, and `holon doctor --json` reports
  `{"value": "claude-fable-5-2", "source": "flag", "reason": "--model (alias 'fable')"}`. When the given value is
  already the canonical model ID (or an unrecognised pass-through string where `canonical == model_name`), `reason`
  remains `"--model"` or `"HOLON_MODEL"`, preserving existing log and doctor output expectations.
- `holon models` (`apps/sandbox-executor/src/sandbox_executor/cli/commands/models.py`) and `holon doctor`
  (`apps/sandbox-executor/src/sandbox_executor/cli/commands/doctor.py` and `run_doctor` in
  `apps/sandbox-executor/src/sandbox_executor/cli/__init__.py`) read directly from `RUNNER_CAPABILITIES`,

   and neither `holon doctor` nor the resolved-model log line surfaced what canonical model ID an alias resolved to.

the `15.0` entropy budget (`entropy_pred = 3.6`):

- **Overall `p_success_pred` (`0.94`):** Derived conservatively near the bottleneck steps (Step 1 at `0.96`, Step 2 at
  `0.95`, Step 3 at `0.98`; `0.94` accounts for minor cross-test assertion adjustments).

- **Overall `impact_pred` (`78.0`):** Sum of step impacts (`35.0 + 30.0 + 13.0 = 78.0`), reflecting the fix for silent
  wrong-family model execution, clear operator diagnostics in logs and `holon doctor`, and permanent regression
  protection via the alias family invariant test.
- **Overall `cost_pred` (`5.5`):** Sum of step costs (`2.0 + 2.0 + 1.5 = 5.5`).
- **Overall `learning_value_pred` (`4.0`):** Sum of step learning values (`1.5 + 2.0 + 0.5 = 4.0`).
