### Strategy Rationale

The repository already has a partial, untyped key table, `sandbox_executor/config_env_keys.py` (`DOCUMENTED_KEYS` with
name, default and purpose for operator-settable keys, plus `HOST_SET_KEYS`), consumed by `config_env.py`,
`config_env_report.py` and `tests/test_config_env.py` (which asserts every documented key appears in the package
README). It covers about 70 percent of the names and lacks type, unset or invalid handling, reading side, forwarding and
the internal or test-only marker. Rather than editing that module (out of scope and consumed by behaviour code), the new
`env_registry.py` is the typed superset; the drift test additionally asserts that every name in `DOCUMENTED_KEYS` and
`HOST_SET_KEYS` is in the registry and that the registry's `secret` flag agrees with `config_env.is_secret_key`. This
makes the three sources (code, registry, reference doc) agree without changing any runtime import graph: nothing in the
product imports `env_registry`.

Measured facts the plan relies on (gathered read-only while planning):

- A scan of string constants in `apps/sandbox-executor/src/**/*.py` and `scripts/*.py`, plus raw text of
  `apps/sandbox-executor/entrypoint/*`, `Dockerfile`, `docker-bake.hcl`, `build_all_images.sh`, `.github/**/*.yml`,
  `Makefile` and the `holon` launcher, with the pattern `(?<![A-Za-z0-9_])HOLON_[A-Z0-9_]*[A-Z0-9](?![A-Za-z0-9_*{])`,
  yields 69 names. Scanning Python string constants (via `ast`) instead of raw text drops Python identifiers such as
  `HOLON_OAUTH_TOKEN_ENV` (a constant whose value is `HOLON_AGENT_OAUTH_TOKEN`) and comment fragments such as
  `HOLON_TURN_*_SECONDS`; the look-behind drops `_HOLON_KEY_RE` and `ALLOWED_NON_HOLON_KEYS`.
- The single remaining false positive is `HOLON_CA_SOURCES`, a bash array local to `entrypoint/role_dispatcher.sh`. It
  goes in an explicit, commented `NOT_ENVIRONMENT_NAMES` exclusion in the test, so the exclusion is visible and
  reviewed.
- The only CI-read name is `HOLON_ALLOW_MODULE_BUDGET_CHANGE` (`.github/workflows/test-hygiene.yml`).
- Forwarding: since the `holon-env-all-via-env-file-v2` change, every forwarded `HOLON_*` value goes through the 0600
  `--env-file` (`launcher/env_files.is_env_file_item`); a value the env-file cannot carry (line break, non-UTF-8) is a
  passthrough `-e NAME` item. `HOLON_IN_CONTAINER=1` is set explicitly on the sidecar argv (`sidecar_plan.py`), and
  `HOLON_COHERENCE_WEB_PASSWORD` is a value-less `-e` flag.
