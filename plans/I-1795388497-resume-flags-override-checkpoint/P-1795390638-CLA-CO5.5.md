## Plan Description & Strategy

Current behaviour (read on `main` at `b22258dc`):

- `_update_flow_context` (`cli/commands/flow.py`) only ever sets `dry_run`, `skip_push`, `skip_review` and
  `skip_calibrate` to `True` from flags. It never clears them, so a stored `True` from an earlier run survives every
  later resume.
- `_check_skip_push` and `_check_dry_run_and_preflight` compute `effective_dry_run` and the skip-push check as
  `args.X or context.X`. A stored `dry_run` therefore also skips the pre-flight probe and allows a stored `skip_push`.
- `_resolve_checkpoint_and_intent` already prefers `--agent` / `--model` when given and keeps the checkpoint's runner
  and model otherwise. `_update_flow_context` writes `flow_agent` / `flow_model` onto `context.agent` / `context.model`,
  and Stage 4 (`flow/review/ensemble.py`, `flow/review/resolver.py`, `flow/review/loop.py`) and Stage 5 read
  `context.agent` / `context.model`. What is missing is proof that this holds end to end for every role, a log line
  naming the override, and a test that the saved checkpoint records the values used.
- `FlowContext.from_dict` (`flow/context.py`) already defaults missing skip fields to `False` and a missing agent or
  model to `LEGACY_DEFAULT_AGENT` / `LEGACY_DEFAULT_MODEL`, so older checkpoints load. That behaviour needs a regression
  test, not a code change.

Strategy:

1. Put the per-run switch policy in one small, focused helper in the existing resume module
   `cli/commands/_flow_resume.py` (37 lines today). It takes the switches only from the current flags and logs every
   stored skip it drops. `cli/commands/flow.py` (374 lines, outside the budgeted `flow` package) calls it and gets
   smaller rather than larger.
2. Make the two pre-run gates (`_check_skip_push`, `_check_dry_run_and_preflight`) read only the current flags.
3. Make the runner and model override explicit and logged, and keep the "no flag keeps the checkpoint's runner"
   behaviour unchanged.
4. Add the four hermetic acceptance tests to `tests/flow/test_resume_checkpoint.py` (which has the existing resume
   fixtures), then fix any older test that encoded inherited switches.

No sub-intents: the predicted entropy (5.6) is well inside the 15.0 budget and the change is about 60 to 120 lines of
production code plus tests.
