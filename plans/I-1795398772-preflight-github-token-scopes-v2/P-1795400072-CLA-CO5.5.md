- `flow/github/token_scopes.py` resolves the token (`GITHUB_TOKEN`, then `GH_TOKEN`, then `gh auth token`), reads its
  type from the prefix, and reads `X-OAuth-Scopes` from one `GET /user`. A fine-grained or app token, or a failed
  request, counts as unverifiable rather than missing.
- `flow/stages/token_scope_guard.py` and a new `check_token_scopes` step right after `preflight` in `execute.py` stop
  Stage 3 before admission and before the agent container starts. They fail only when the plan touch set or the intent's
  `scope` names a `.github/workflows/**` path and the token positively lacks `workflow`. The error names
  `gh auth refresh -h github.com -s workflow`.
- `flow/execution_recovery.py` handles a refused Stage 3 push. It pins each new execution branch tip on
  `refs/holon/recovery/<execution id>` and tries a fast-forward-only push to `holon-recovery/<execution id>`. The stage
  error names the ref, the short sha and the republish command, and the payload carries `recovery_refs` and
  `recovery_pushed`.
- `holon doctor` prints a value-free `github_token=<type> source=<source> scopes=<list>` line. It warns when `workflow`
  is missing or cannot be verified.
- Hermetic tests cover all of this, with a sentinel token that must never leak into any output.

The only problem was the touch set. Four files outside it were changed, each for a necessary reason:

- `flow/__init__.py`: the package export registry. `tests/flow/test_package_exports.py` requires every public name of a
  new `flow` module to be registered there.
- `tests/conftest.py`: the autouse `no_ambient_credentials` fixture stubs `token_scopes._run_gh` and
  `token_scopes._urllib_fetch`. Without that, any doctor or Stage 3 test could run the real `gh` or reach the GitHub
  API.
- `tests/flow/stages/test_execute.py` and `tests/flow/stages/test_execute_steps.py`: the assertion on the step order and
  the two existing push-error assertions now expect the new error text and the recovery payload.
