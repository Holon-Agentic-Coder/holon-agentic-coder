### Step 2: Restrict dual EV to Stage 3 execution rows and resolve recovered failures

- New `calibration_rows.py`: `row_stage` (explicit `stage` field wins, then the `REV-`/`CAL-`/`E-` id prefix; a row
  with no id or the plan's own execution id is an execution row), `is_execution_row`, and `is_infrastructure_failure`
  over `summary`, `error` and `failure_reason` with anchored harness patterns (container dispatch exited or failed,
  usage or session limit, harness or turn timeout, `budget of N s exceeded`).
- Deviation: `is_matching_record` is also used by `flow/stage5_verdict.py` (the hand-run verdict, which must still see
  the Stage 4 approval) and `calibration_predicted.py`, so it is unchanged. A new `is_matching_execution_record` in
  `calibration_ev.py` adds the execution-row filter for the dual EV; the "no match" fallback now only uses execution
  rows.
- `calibration_outcome.py`: a failing row (failed, non-zero exit or `sync_conflict`) followed by a later delivered
  (converged, zero-exit) execution row is resolved; a `sync_conflict` is also resolved by a later delivered row of any
  stage (the resumable conflict Stage 4 resolves, the pattern of five flows in the ledger); infrastructure failures
  never count; `latest_row_per_execution` lets a superseding revision of the same execution id replace its earlier row
  while separate attempts keep theirs.
- Clean EV now credits the run when any execution row delivered (`has_delivered`), not only the final row. Without
  this, drag is identically 0 once a later delivery resolves every earlier failure, and the plan's matrix (success then
  failure gives drag above 0) could not hold.
- `parse_actual_metrics` takes `exit_code` and `p_success` from the latest execution row only.
- Changed expectations: `test_intermediate_failure_with_converged_recovery` became
  `test_recovered_review_failure_adds_no_drag` (drag 0, was 50); the two `parse_actual_metrics` dual-EV tests with
  `REV-` failures now expect drag 0; `test_failed_row_superseded_by_converged_row_is_a_bug` became
  `test_review_approval_does_not_turn_a_failed_execution_into_a_delivery` (Clean EV 0, drag 0). New tests cover a
  failed attempt after a delivery (drag equals impact), a failure resolved by a later attempt, and a superseding
  revision.
- On the real ledger rows of PR #249, `evaluate_dual_ev_outcomes` now returns `bug_ev_drag = 0.0` and
  `ev_with_bugs == ev_clean`.
