## Plan Description & Strategy

Add a new module, `scripts/ci_main_push_superseded.py`, with one public function. It reads the tip of `main` with one
`git/ref/heads/main` read. When the tip equals the pushed sha it returns `None` with no further read. Otherwise it makes
one `compare/<pushed>...<tip>` read through the existing `scripts.ci_bookkeeping_api.compare` helper. When the status is
`ahead`, it returns `Decision(True, "main-push-superseded", "pushed <sha12> superseded by tip <sha12>")`. In every other
case, including any exception, it returns `None`.

`decide_main_push` calls it right after `_event_check` and before the pull-request rules. Only a strict ancestor of the
tip skips. The tip itself, a non-ancestor and any API doubt fall through to the unchanged rules, including
`main-push-tested-tree`. Re-runs are stopped earlier by `main-push-rerun-attempt`.

At most two API reads are added per gated job, and only one when the pushed commit is the tip. The fake gains a
served-ref table, and the existing gate tests set the tip to the pushed commit so that their decisions and URL
expectations stay the same. No workflow YAML, README, or module budget changes. The daily scheduled run is untouched
because `is_main_push` only covers `push` events.

### Implementation Details (No code blocks, only logic/steps)

1. Write a module docstring in the style of `ci_main_push_gate.py`. It explains:
   - Within a burst of merges, a pushed commit that is a strict ancestor of the current tip of `main` relies on the
     tip's push run, which tests a superset tree.
   - Every doubt returns no opinion.
   - The module uses the standard library only, Python 3.9 syntax, and `from __future__ import annotations`.
2. Define the constants:
   - `RULE_SUPERSEDED = "main-push-superseded"`

3. Add `main_tip(client: GateClient) -> str`. It calls `client.get_json(MAIN_TIP_REF)`, reads `object.sha`, and raises
   `ValueError` when that is missing or not a non-empty string. It may reuse `scripts.ci_bookkeeping_api._sha_of` only
   if that is public; otherwise it does a local check of a few lines.
4. Add `superseded_check(context: GateContext, client: GateClient) -> Decision | None`:
   1. Inside one `try`, read the tip.
   2. If `tip == context.sha`, return `None`. This is the only read when the pushed commit is the tip.
   3. Otherwise compare with `compare(client, context.sha, tip)`.
   4. If `comparison.status == "ahead"`, return
      `Decision(True, RULE_SUPERSEDED, f"pushed {context.sha[:12]} superseded by tip {tip[:12]}")`.
   5. Otherwise return `None`.
   6. Wrap the reads in `except Exception: return None`, with a comment that any doubt keeps the existing rules. The
      same broad catch is already used in `safe_decide`, so no `# noqa` is expected. If ruff's `BLE001` flags it, narrow
      the catch to `(OSError, ValueError, KeyError, TypeError, AssertionError)` instead of adding a suppression.
      `urllib.error.URLError` is an `OSError` subclass.
5. Import `GateClient`, `GateContext` and `compare` from `scripts.ci_bookkeeping_api`, and `Decision` from
   `scripts.ci_bookkeeping_chain`. Do not import from `scripts.ci_main_push_gate`, which would create a cycle.
