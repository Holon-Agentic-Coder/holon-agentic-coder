2. Run the full unit test suite once in the foreground: `uv run task test`.
3. Run the full lint and hygiene suite in the foreground: `uv run task lint` (which checks `uv.lock`, `ruff check`,
   `ruff format --check`, `scripts/check_self_explaining.py`, and `module_budgets.json` line caps).
4. Confirm via `git status --short` and `wc -l` that only files in the Touch Set were modified,
   `holon-config/hygiene/module_budgets.json` is untouched, and every touched source module is strictly at or below 350
   lines.

### Safety & Constraint Considerations

- **Relevant rules:** Foreground-only execution rule (never background commands),
  `holon-config/hygiene/module_budgets.json`, `.agents/AGENTS.md` root-only `uv` invocation.
- **Potential failure modes for this step:**
  - Formatting or ruff complexity failure requiring a quick clean-up pass.
  - Unintended regression in an unrelated review-loop test.
- **Guardrails and early‑abort checks:** Fix any reported lint/test error before re-running; do not re-run passing
  suites without edits.

### Success & Discard Criteria

- **Success:** Targeted pytest, `uv run task test`, and `uv run task lint` all exit 0 in the foreground with zero
  modified files outside the Touch Set.
- **Discard:** Stop and escalate if an unrelated pre-existing failure blocks `uv run task test` or if a module cannot
  fit within 350 lines without splitting outside the approved scope.
