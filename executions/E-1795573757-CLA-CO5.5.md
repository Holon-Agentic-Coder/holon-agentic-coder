### Step 3: Add the negative controls and the isolation proof (`test_stress_support.py`)

- Added `apps/sandbox-executor/tests/test_stress_support.py` (unit-selected, no `stress` marker). Each control writes
  one generated test file plus its own `pytest.ini` under `tmp_path`, and runs it with
  `uv run --no-sync --project <repo> pytest -c <ini> --rootdir <dir> --basetemp <context basetemp>` through
  `run_child()`, with `child_env()` of a fresh `child_context`. A guardrail asserts the child's `HOME` lies under the
  context root before every run.
- Hermetic canary negative controls (3): a child test overwrites `~/.holon-sandbox/workspace/canary.txt`, deletes the
  dummy `.git`, or creates `holon-knowledge/.index/x.db` under a throwaway index root in `tmp_path`. Each makes
  `canary_violations()` report the matching violation.
- Workspace survival negative controls (4), against a real one-commit repository at the context workspace: the child
  removes the workspace, removes `.git`, deletes `.git/HEAD`, or moves HEAD with an empty commit. Each makes
  `survival_violations()` report the matching violation.
- Positive controls (2): a hermetic child body gives empty violations for both checks.
- Isolation proof (3): two concurrent contexts have ten pairwise distinct paths, none inside the other's root, each
  `tmpdir` outside both HOMEs, and both roots removed on exit; `child_env()` pins `HOME` and `TMPDIR`/`TMP`/`TEMP` to
  the own context and keeps only `PYTEST_XDIST_AUTO_NUM_WORKERS` of the `PYTEST_XDIST_*` keys even when the test sets
  `PYTEST_XDIST_WORKER`, `PYTEST_XDIST_WORKER_COUNT` and `PYTEST_XDIST_TESTRUNUID`; `child_suite_command()` carries the
  context's own `--basetemp`.
- `uv run pytest apps/sandbox-executor/tests/test_stress_support.py -n auto --dist worksteal`: 12 passed in 3.87 s (each
