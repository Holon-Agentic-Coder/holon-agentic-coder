### Strategy Rationale

correction. They share one report pipeline (`parse_actual_metrics` → `generate_calibration` → `run_calibrate` → Stage
5), and the end-to-end regression test and the PR #249 regeneration need all three fixes together. Splitting them into
sub-intents would serialise three full flows, each of whose Stage 5 would itself run the broken calibrator. So the plan
runs as one execution with focused new modules, which keeps per-module blast radius small:

- `calibration_rows.py` classifies ledger rows (stage kind and infrastructure failure).
- `calibration_evaluated_sha.py` skips ledger-only commits.
- `calibration_self_check.py` holds the consistency guard.
