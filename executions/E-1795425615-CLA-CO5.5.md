### Step 5: Diagnose which text collides with the credential

- A temporary local print (removed; `git diff` shows only `seeded_secrets.py` changed) in the pre-fix variant showed
  the matched fragment and its context in the main argv:
  - seed 211: `frag='jvzq'` in `.holon/tmp/holon-pi-agent-w6tcjvzq:/home/holon/.holon-pi-agent:rw`;
  - seed 227: `frag='gvzj'` in `.holon/tmp/holon-pi-agent-64ulgvzj:...`.
- **Root cause:** for a forwarded invalid value (`HOLON_TURN_TIMEOUT_SECONDS` or `HOLON_STAGE_BUDGET_SECONDS`), the
  run goes on to create the pi-agent session dir with `tempfile.mkdtemp(prefix="holon-pi-agent-")`. Its 8 random
  `[a-z0-9_]` characters are mounted (`-v <dir>:/home/holon/.holon-pi-agent:rw`) and echoed (`Executing:`). When 4 of
  them equal a 4-character run of the case's credential, the check reports a false leak in both the captured output
  and the main argv. A second source of the same kind is the rest of the unmasked path, `tmp_path`, whose pytest
  run number `pytest-<N>` changes between runs (the #244 stress run reruns the suite, so N grows). Reproducing seed:
  `CREDENTIAL_TEST_SEED=211` (case `env:HOLON_TURN_TIMEOUT_SECONDS/socks5/user-password/digits6-colon/ipv4/path`),
  with the pi-agent mask removed and `--basetemp` pinned.
- Classification: hypothesis (a), a fixture-owned temp path. Not (b): with the mask in place, the dumped argv and echo
  of the forwarded-value and delimiter tests hold no random text but the masked `<env-file>`, and the probe tests pass
  the fixed container name `probe`, never `holon-preflight-<uuid>`. Not (c): no stage timer is active in these tests
  (`budgets.current_stage_timer()` is a context variable), and `sweep_stale_env_files` only removes day-old files.
  Product code does not leak: the value always reaches the env-file (`not-env-file` never failed).
